## 何をするものか

**メッセージを、相手に転送しません。**

父はAIと話し、母もAIと話します。書いた言葉そのものは、決して相手に届きません。
**合意に必要な事実だけが、伝聞のかたちで越えます。**

```
入力（父）
  月3万が限界。こっちだって仕事切られて必死なんだよ。そっちだって働いてるだろ、少しは考えろ

母に届くもの
  養育費について、月額3万円までを希望されているそうです。
  背景として、現在は職を失っているとのことです。
  ── お相手が書いた言葉そのものは含まれていません。
```

「必死なんだよ」「そっちだって働いてるだろ」「少しは考えろ」は届いていません。
**「仕事を切られた」という、合意に必要な事実だけが越えました。**

### なぜこれが要るのか

国の調査で、養育費の取り決めをしない理由の第1位は**「相手と関わりたくない」**です。
既存の共同養育アプリは**メッセージを転送します。**関わりたくない相手からの言葉が、そのまま届きます。

**関わらずに決められる**なら、取り決めができます。

## 中核となる3つの主張

| # | 主張 | 実装 |
| --- | --- | --- |
| **C1** | **メッセージを転送しない** | `buildRelayContext` が `partyId` を**引数に取らない**。相手の原文へ到達する経路が型に存在しない |
| **C2** | 入口を協議離婚に置く | 招待〜受諾〜対話が本番で通る。**相手を招待できない**という獲得上の障壁を構造的に解消 |
| **C3** | 合意がその後の判断基準になる | 「今回だけ？ 今後も？」を**AIが合意を参照して問う**。ONE_TIME は合意を書き換えない |

## 設計の要点

### 1. 「気をつける」ではなく「書けない」

```ts
// ★partyId を引数に取らない ＝ Message へ到達する経路が型レベルで存在しない
buildRelayContext(proposalId: string): RelayContext
```

同じ手を LLM にも使っています。`LlmRouter` を唯一の入口にし、
**Router の外から SDK・エンドポイント・APIキーを参照していないことを静的検査**しています。

### 2. 検査は、テストであると同時に実行時の門

LLM の出力は毎回変わります。**テストで確かめるだけでは足りません。**

```
生成 → 検査 → 通れば越える
            ↓ 落ちた
        1回だけ作り直す
            ↓ また落ちた
        ★事情を落として最小形で越える
```

**事情が伝わらないことより、原文が越えることのほうが重い**という判断です。

### 3. 数字と条項をLLMに作らせない

- 養育費の金額は、裁判所公表の**令和元年改定標準算定表**から決定的に引きます
- 条項は**ひな形の置換のみ**。未置換が残れば**文書を返しません**
- 空欄のある法的文書は、空欄のない誤りより危険です

算定表は帯グラフのPDFから機械的に抽出し、**3つの方法で検証**しました（9表中8表が通過。
通らなかった表は**含めていません**。誤った数字を出すより、出さないほうがよいためです）。

### 4. 観測できないことを断定しない

アプリは入金を観測できません。したがって**「未払い」とは書きません。**

| 状態 | 文言 |
| --- | --- |
| どちらの申告も無い | **まだ記録がありません** |
| 双方の申告が揃う | 確認できました |

### 5. AIは説教しない

危険な表現を検知しても、**その場では何も変わりません。**
「そのような表現は不適切です」と返した瞬間、**「何を書いてもいい」という約束が壊れます。**

受け止めたうえで、届けない。それだけです。
通告の判断は**人が行います**。自動化の入口を作っていません
（[国自身が、児相の一時保護判断AIを導入見送りにしています](docs/legal-child-risk-research.md)）。

## コスト

| | |
| --- | --- |
| 階層 | SMALL `gpt-4.1-nano` ／ MEDIUM `gpt-4.1-mini` ／ LARGE `gpt-5.1`（`reasoning_effort=medium`） |
| **CT-1** | メッセージ単価 **約0.42円**（事前試算 0.36円） |
| **CT-4** | ルーティングなしとの比較 **約50%削減**（[実測](https://aida-4n47tjpp2a-an.a.run.app/metrics)） |

> **数字は測る範囲で変わります。**`/metrics` は集計期間を画面に出します。
> 期間を示さない削減率は意味を持ちません。

### ★ 推論モデルの罠（実測）

| モデル | 出力トークン | 円/回 |
| --- | --- | --- |
| `gpt-5-nano`（既定） | **1,358** | **0.0822** |
| `gpt-4.1-nano`（非推論） | 29 | **0.0032** |

**単価表だけを見て `gpt-5-nano`（入力 $0.05）を選ぶと、`gpt-4.1-nano`（入力 $0.10）より高くつきます。**
思考トークンが出力に計上されるためです。**階層を変えたら実測する**という規約にしました。

## セキュリティ

| | |
| --- | --- |
| 分離 | `INV-1〜4a` を**実装より先に**テスト化。CI でブロッキング |
| インジェクション | 検知は**記録であって拒否ではない**。止めなくても、**コンテキストに無いものは出ません** |

## 技術

Next.js 16 / TypeScript / Tailwind CSS 4 / Firestore / Cloud Run（asia-northeast1）/ OrcaRouter

```bash
pnpm install && pnpm dev
```

`pnpm test`（**497件**）／ `pnpm typecheck` ／ `pnpm lint` ／ `pnpm build`

### 開発の進め方

**不変条件・状態遷移・安全に関わるものは、実装より先にテストを書いています**（`docs/development-guidelines.md` §5.0）。
コミット履歴で確認できます（`test(SN): …` が落ちる状態でコミットされ、次に `feat(SN): …` が通す）。

このやり方は実際に機能しました。**テストと実機の確認が、以下を検出しています。**

- 算定表の帯の誤記（デザイン納品物と設計書の両方）
- **C3 の区別が本番経路に接続されていなかった**（一時的な融通が合意を書き換えていた）
- 存在しなかった義務を「記録が確認できていません」と表示していた
- 調停案で「あなた」と「お相手」が入れ替わっていた
- 本番だけが Firestore を読めていなかった（デプロイは成功し続けていた）
