# Handoff 第3弾: Aida（あいだ）— オンボーディング・フロー・残りの全画面

第1弾（`../design_handoff_aida/README.md`）と第2弾（`../design_handoff_aida_v2/README.md`）の続きです。**デザイントークン・デザイン原則・文言規約・カピバラの扱いは第1弾のまま**で、再設計はしていません。第1弾 → 第2弾 → 本書の順に読んでください。

判断基準は変わりません。

> **深夜に泣きながら開いても、ふざけて見えないこと。**

これで**全40画面が揃いました。** 未着手の画面はありません。

## About the Design Files

このバンドルの HTML は**デザインリファレンス**です。意図した見た目と振る舞いを示すプロトタイプであり、そのまま本番コードとして流用するものではありません。対象コードベース（Next.js App Router ＋ TypeScript ＋ Tailwind CSS を想定）の既存パターンで再現してください。

`Aida 通しモック.dc.html` は**動きの確認用**です。遷移のフェード、発言の出現、カピバラの呼吸、年収の帯の変換、対話の応答待ちが実際に動きます。実装の挙動仕様として参照してください。

## Fidelity

**High-fidelity**。色・余白・角丸・文言はすべて確定値です。

**未決の論点は 3 点だけ**（いずれも第2弾から継続）:

1. **G（危険検知）の方針** — 案2＋案3の併用を推奨。検知の閾値が未決
2. 退会時のデータ削除範囲（弁護士確認中）
3. ナレッジ記事の監修体制

## 全画面リスト（40画面）

`Aida 画面フロー図.dc.html` が全体像です。7つの帯で構成しています。

| 帯 | 内容 |
| --- | --- |
| 1 | 入口（起動・ログイン・別端末から戻る） |
| 2 | オンボーディング／招待する側 |
| 3 | オンボーディング／受諾する側 |
| 4 | 5つのタブと、その配下 |
| 5 | お相手に伝える経路 |
| 6 | 画面を持たない横断のふるまい |
| 7 | 取り決めの状態遷移（7状態） |

### 必ず通る画面

**緑の枠が、避けて通れない画面です。**

- どちらの側も帯1の2枚（起動・ログイン）を通る
- そのあと**招待する側は4枚**（I-1・I-2・I-3・ホーム）→ 合計6枚
- **受諾する側は3枚**（A-3・H-1・ホーム）→ 合計5枚

**それ以外はすべて、本人が選んだときにだけ開きます。** 招待も、年収も、ナレッジも、準備モードも同じ扱いです。**何かを促すために画面を挟むことはしていません。**

## ★ 第3弾で変えた順序（2点）

### 1. 受諾した側に、その場で年収を聞かない

A-3で「参加しない選択もできます」と伝えた直後に年収を聞くと、**あの一文が入口の作法だったことになります。** まだ何も納得していない人に、最も抵抗の大きい質問を最初にぶつける順序でした。

**変更後**

```
A-3 受け取った側の最初の画面
  ↓
H-1 お子さんの確認 ← うかがうのはこの1枚だけ
  ↓                  年収も状況も同居も聞かない
ホーム
  ↓
（お金の話題に入り、目安が要る場面になってから）
H-2 対話の中で年収をうかがう ← 断れる
```

**目安が出ないことを不利益として書きません。** 「目安がないと話が進みません」と書いた時点で、実質的な強制になります。

### 2. 「まだ相手と話していない」を独立した問いにしない

聞いた時点で、**アプリが相手に伝える前提でいることが伝わります。** 「話していない」を選ばせれば、次に来るのは「では伝えましょう」だと予期されます。

代わりに**招待をオンボーディングから外しました。** 着地はホームで、招待はホームのカードから本人が選んだときだけ開きます（A-1には既に「あとにする」があります）。

### 進捗バーの判断

**出します。ただし数字とステップ数は出しません。** 細い3分割のバーだけです。終わりが見えないほうが負担が大きいと判断しました。**飛ばせる3枚（I-4・I-5・I-6）はバーの外**に置いてあるので、バーは3で埋まります。

## I. オンボーディング（招待する側）

### I-1. 状況の確認

**5つの選択肢は面積・枠線・文字サイズをすべて同一にしてください。**

1. これから離婚の話をする／条件は、まだほとんど決まっていない
2. 離婚の前で、条件は決まっている／書面にしておきたい
3. 離婚したが、決めていない／これから決めたい
4. 離婚して、取り決めがある／その内容で運用していきたい
5. まだ、よく分からない／話しながら整理したい

**★ 実装ルール**

- 「まだ、よく分からない」も同じ形で。**最後だが小さくしない**
- 2×2の表として聞くと詰問になります。**平たい5択に崩してください**
- **「離婚していますか」「取り決めはありますか」という直接の問いを画面に出しません**
- 選択後に「次へ」が fade+4px上昇 で現れる（選ばないと出ない）
- 末尾に「どれを選んでも、できることは変わりません。お出しする順番だけが変わります。」
- 4を選んだ場合のみ I-5 を出す

### I-2. 同居

3択（一緒に暮らしている／暮らしていない／お子さんによって違う）。

**破線の注記を1行だけ添えてください。** 「養育費をどちらが受け取る側になるか、この一点だけのためにうかがっています。」

監護の実態を問うものと読まれかねない問いなので、用途を限定して明示します。「あとで答える」を残します。

### I-3. お子さん

- **生まれた年と月だけ。日は聞きません**
- **名前は任意**（プレースホルダにも「（任意）」を入れる）
- 「＋ お子さんを追加」で最大3人
- **3人に達した時点で**、静かに注記が現れる（`surface-2`、fade+4px上昇）
  「4人目以降は、目安の表が公表されていないため、金額の目安をお出しできません。話し合いは、そのまま進められます。」

**★ エラーにも警告にもしません。** 算定表の対象外であることを、本人の責任のように見せないためです。

### I-4. 年収

第2弾 C の解をそのまま配置。変えたのは2点だけです。

- **進捗バーを外す**（飛ばせる画面なので、進捗の一部に数えない）
- ヘッダーに「目安を出すために」と用途を置く

変換の図は必須です（第2弾 C 参照）。

```
入力: 4,380,000円  →  お相手に見えるのは: 425〜450万円
```

「あとで入力する」を必ず残します。この画面は受諾側でも、対話の中から同じ形で開きます（H-2）。

### I-5. すでにある取り決め

I-1 で「離婚して、取り決めがある」を選んだ方のみ。

**★ 最上部に置くもの**（`bubble-ai`、破線枠、カピバラ28px）

- 「お相手の確認は要りません。」
- 「ここに書いていただくのは、記録です。お相手にお尋ねすることはありません。お相手も同じ内容を記録されたときに、はじめて『合意済』になります。それまでは、ご自身の記録として残ります。」

**記録が相手に通知されるのではという不安を、先に消します。**

**★ ステータスを1種追加します**

| 状態 | 枠線 | 地 | 文字色 |
| --- | --- | --- | --- |
| **ご自身の記録** | 破線 `#C4B8A7` | なし | `text-sub` |

既存6種のどれでもない状態です（相手が同じ内容を記録すると「合意済」に変わる）。**合計7状態**になります。

- 「覚えている範囲でかまいません。あとから直せます。」
- 「いまは書かない」で飛ばせること

### I-6. 次に使うとき（メールの登録）

**★ 「アカウント作成」「会員登録」という語を使いません。** 目的だけを書きます。

3行の約束（`surface` のカード）:

1. お送りするのは、お戻りいただくための確認コードだけです。
2. 件名にも本文にも、離婚・養育費といった語は入りません。
3. お知らせのメールをお送りすることはありません。

破線の注記「ご家族と共有されているアドレスは、避けていただくほうが安全です。」

「この端末だけで使う」を残しますが、**失うものも書きます**（「端末を変えると書いたものは戻せません」）。

### I-7. 別の端末から戻る

**パスワードではなく確認コード**（6桁）。長く開かない人が多い前提なので、覚えておく必要があるものを増やしません。

**差出人と件名を先に伝えます。** 「差出人は『Aida』、件名は『確認コード』です。」受信箱を探すときに、用途が推測される検索をしなくて済みます。

## H. 受諾した側

### H-1. 受諾直後（うかがうのはこの1枚だけ）

招待した側が登録した内容を見て、違えば直すだけ。

- 「お子さんのことが、すでに登録されています」
- 「違っているところがあれば、直してください。合っていれば、そのまま進めます。」
- 各行に「直す」
- 破線の注記「直された場合、お相手には『変更がありました』とだけ伝わります。**どちらが正しいかを、こちらで決めることはしません。**」

**★ 画面の下に必ず置くもの**（`bubble-ai`、破線枠）

- 「うかがうのは、ここまでです。」
- 「ご事情や、お住まいのことは、おうかがいしません。お話しになりたいことから始めていただけます。」

**質問がまだ続くのではという警戒を、その場で終わらせます。**

### H-2. 年収は、必要になった時点で

**独立した画面ではなく、対話の中のカード**として開きます。②の吹き出しと同じ左インデント（**37px**）に揃えて、AIの発言の続きとして読めるようにします。

```
AI: 目安の表があります。
    お出しするには、おふたりの年収が必要です。うかがってもよろしいですか。

［カード］ご自身の年収  ─────
         入力した金額 → お相手に見えるのは「帯だけ」
         金額そのものは、お相手には見えません。
         ［入れる］
         ［入れずに話す］

入れなくても、話し合いは続けられます。
```

**★ 「入れずに話す」と「入れなくても、話し合いは続けられます。」が両方揃っていないと、実質的な強制になります。**

**入力欄は、このカードが出ているあいだも開いたままです。**

## K. ナビゲーションの補完（第4弾）

**タブを5つ設計したのに、着地する画面を描いていたのは3つだけでした。** その穴を埋めます。

### K-1. 相談の一覧 ← タブの着地（新設）

**相談タブは対話に直行しません。一覧に着地します。** 「養育費」「面会の日程」「塾の費用」が同時に進みます。

構成:

1. **届いているご相談**（封書ヘッダ付きカード）
2. 進行中の相談（項目名＋日付＋一行の状態）
3. 「お話しが済んだもの」（`surface-2` に沈める。**消さない**）
4. 「別のことを話す」（破線枠＋カピバラ34px → 1-a へ）

**★ 実装ルール**

- 見出しの下に「どれから話しても、順番はありません。」← **上から片づけるものに見せない**
- 日付は右端に小さく置くだけ。**未読の印も件数バッジも持たない**
- 並び順は更新の新しい順

### K-2. 対話（タブバーを補った版）

**第1弾の対話画面にタブバーがありませんでした。** 補います。

- 下部にタブバー（相談がアクティブ）
- ヘッダの `⌄` は **K-1 と同じ一覧をシートで開く**（別の相談へ移るために、いちいちタブへ戻らせない）
- **選択肢のチップは1行に収まる2つまで**

> チップが3つ並ぶと、下から積み上がる要素が4段（窓口・チップ・入力・タブ）になり、会話が見える高さが400pxを割ります。

### K-3. 設定 ＞ 登録した内容（新設）

オンボーディングで4種類お預かりしているのに、あとから見る画面がありませんでした。

| 項目 | 操作 |
| --- | --- |
| いまの状況 | 直す |
| 同居 | 直す |
| お子さん | 直す → K-4 |
| ご自身の年収 | 直す → I-4 と同じ画面 |
| **お相手の年収** | **表示のみ（幅だけ）** |

**★ 相手の年収も同じ画面に置いてください。** 自分の値だけが見えていると「相手には自分の額が見えているのでは」という疑いが残ります。幅だけが並んでいることで、対称性がその場で分かります。

- 自分の欄には「お相手に見えるのは 425〜450万円」を併記
- 相手の欄には「お相手が入力された幅です。こちらから直すことはできません。」
- 末尾に「**お子さんのこと以外は、直してもお相手にお知らせしません。**」

### K-4. お子さんを直す（新設）

**お子さんの情報だけは相手と共有されます。** 直す前にそれを書きます。

`bubble-ai` の破線カード:

- 「直すと、お相手には『変更がありました』とだけ伝わります。」
- 「お子さんのことは、おふたりで共有している情報だからです。**何をどう直したかは伝わりません。**」
- 「お名前は共有されません。この端末でだけ表示されます。」

`surface-2` の注記:

- 「生まれ年を直すと、養育費の目安が変わることがあります。**すでに合意済みの金額は、そのまま残ります。**」

**ここを曖昧にすると、直すことをためらいます。**

### K-5. 取り決めの項目詳細（新設）

第1弾に「項目をタップすると詳細へ」と書いて、画面がありませんでした。

- 定義リスト（金額／支払日／終わり／合意日）
- **「これまでの経過」** — 時系列。左の細いバーだけで合意点を示す（合意は `agree`、それ以外は `border-dashed`）
- 2つのボタン（**同じ重さ**）:「この項目について相談する」「変更を申し出る」
- 「変更には、お相手の同意が必要です。」

**★ 経過に相手の言葉を残しません。** 「お相手から 45,000円の案がありました」のように、金額は残しますが言葉は残しません。

**★ 「変更を申し出る」を目立たせません。** 一度決まったものを動かす操作を、勧める形にしないためです。

### K-6. 変更申請を受ける側（新設・欠落していた）

**「変更申請中」を「合意済」に戻すには相手の同意操作が要るのに、その画面がありませんでした。**

ボトムシート。背後の会話は `opacity: .35`。

```
AI: 面会交流の取り決めを、変えたいというご相談です。
    背景として、土曜に就業されることになったとのことです。

［surface-2 のカード］
  いまの取り決め   月1回・第2土曜
  変わったあと     月1回・第3日曜   ← agree-text

回数は変わりません。曜日と週が変わります。

［この内容でよい］
［別の案を出したい］
［いまの取り決めのままにしたい］

いま決めなくてかまいません。
お返事があるまで、いまの取り決めが続きます。
```

**★ 3つの選択肢をすべて同じ見た目にしてください。** 法的合意の変更なので、「よい」を強調した時点でダークパターンになります。

**★ 「回数は変わりません。曜日と週が変わります」のように、何が変わって何が変わらないかを言葉で足します。** 条文の差分を目で追わせません。

**★ 返事をしないあいだは現状が続くことを明示します。** 放置が不利にならないと分かって、はじめて落ち着いて選べます。

## L. 空の状態（第5弾）

### 3つに共通して守ること

**空を「まだ何もしていない状態」として書きません。** 「まだ」「〜がありません」で始めると、遅れているように読めます。

代わりに、**そこに何が入る場所なのかを書きます。** 急かす言葉、達成率、次にすべきことの提示は置きません。**イラストで空白を埋めることもしません**（カピバラを大きく置くと、慰められている感じが出ます）。

### L-1. 相談が空

**「まだ相談はありません」と書きません。** 入力欄をそのまま置いて、書ける場所であることだけを示します。

- `bubble-ai` の破線カード：カピバラ40px ＋「思っていることから、書いていただけます。」＋入力欄の見た目
- **「ここに書いたことは、お相手には届きません。整えなくても、まとまっていなくてもかまいません。」**
- 下に4分類のリスト＋「選ばなくてかまいません。」

**★ 「お相手には届きません」を、書く前に見える位置に置いてください。** 1件目を書くときがいちばん怖い瞬間なので、約束は書いたあとではなく書く前に必要です。

### L-2. 取り決めが空 ← いちばん重要

**★ 進捗バーを出しません。** 0/8のバーは、開くたびに何も進んでいないことを突きつけます。**1件でも決まった時点から出します。**

- 見出しの下に「決まったことが、ここに上がってきます。」
- `bubble-ai` の破線カード：**「全部を決める必要は、ありません。」**＋「ご事情によって、当てはまらない項目があります。ひとつ決まれば、それだけで書面にできます。」
- 8項目は **`surface-2` に沈め、ステータスチップを付けない**
- 見出しは「決めること」ではなく **「話し合うことがある項目」**

> 「未着手」を8個並べると宿題の一覧になります。
> 「全部を決める必要は、ありません」を最上部に置いたのは、8という数を見た直後に効かせるためです。

### L-3. これからが空

**この画面はカレンダーに見えますが、ユーザーが予定を入れる場所ではありません。**

- 「支払いの日や、お会いになる日が並びます。」
- 「取り決めが決まると、その日付がここに入ります。**ご自身で入力していただく必要はありません。**」
- 破線カードに「入るものの例」を3つ
- 末尾に「予定を思い出させる通知は、設定で切れます。」← 支払日が並ぶ画面は督促のように働きうるため

## M-1. ご利用をやめるとき（第2弾で導線だけ作っていた画面）

**冒頭の1文が最重要です。**

> 取り決めをやめることではありません。このアプリのご利用をやめる手続きです。何がどうなるかを、先にお伝えします。

**ここを誤解すると、養育費が消えると思われます。4行を読む前に必要です。**

| 項目 | 結果 | 説明 |
| --- | --- | --- |
| 取り決めた内容 | 残ります | 公正証書の原案になっている場合があるためです |
| お書きになったもの | **消えます** | 対話の内容、下書き、年収。戻せません |
| お相手の画面 | 続きます | 「ご利用を終えられました」とだけ伝わります。理由は伝わりません |
| これからの予定 | **通知されません** | お知らせは止まります。取り決めそのものは、法的には続きます |

- 「消えます」「通知されません」のみ `attention-text`。**赤字も警告アイコンも使いません**
- `surface-2` のカード「控えを先にお出しします／取り決めた内容と、これまでの経過をPDFでお渡しします。」
- 2つのボタン（**同じ重さ**）:「控えを受け取って、手続きに進む」「まだ決めない」

**★ 引き止めません。** 「よろしければ続けませんか」の一言も入れていません。やめたい人にそれを見せるのは、ダークパターンの一種です。

## N. 合意の成立 ／ 調停へ ／ 通知

### N-1. 合意が成立した瞬間

**★ 祝いません。紙吹雪も、バッジも、「おめでとうございます」もありません。**

対話の中に、**上下に線が1本ずつ引かれて、その中に内容が置かれるだけ**です。

```
AI: おふたりのお考えが、同じところに来ました。

───────────────────  ← border-top: 1px solid agree（480msで左から引かれる）
  取り決めになりました        ← 11.5px agree-text
  養育費　月 50,000円
  毎月末日                    ← 19px
  2026年8月12日 ／ おふたりの記録に残ります
───────────────────  ← border-bottom: 1px solid agree

AI: お支払いの日を「これから」に入れました。
    変えたくなったときは、いつでもおっしゃってください。
    ［この項目を見る ▸］
```

**★ これは離婚の条件が決まった瞬間です。祝われると、失ったものを思い出させます。**

**★ 「同じところに来ました」という言い方にしてください。** どちらかが譲ったという構図を作らないためです。

### N-2. 調停へ移ったとき

**彩度をゼロにし、無効色で扱います。ただし失敗として書きません。**

- 「**話し合いの場が、外に移りました。**」（`muted-bg` のカード）
- 「この項目について、こちらでお話しを進めることはしません。家庭裁判所での手続きに沿って進みます。」
- 3行のリスト:
  - これまでの経過 → **残ります。PDFで書き出せます**
  - ほかの項目 → これまでどおりお話しになれます
  - **戻ってきたとき** → 調停で決まった内容を記録すると、また「これから」に入ります
- 破線の注記「**こちらでお力になれなかった、ということではありません。** 制度で決めたほうがよいことがあります。」

**★ 「AIでは解決できませんでした」と書きません。** 使った人の落胆になります。

**★ PDFの書き出しは必須です。** 調停には資料が要ります。アプリを離れる場面で、いちばん役に立つ機能です。

**★ 「戻ってきたとき」を書いてください。** この状態が終点ではないと示すためです。

### N-3. 通知の見え方（ロック画面）

| 状態 | 表示 |
| --- | --- |
| **既定（本文なし）** | 「お知らせがあります」のみ。**件数も、相手の存在も、内容も出さない** |
| 本文を出す設定 | 「日程についてのご相談を、お預かりしています」 |
| 時間帯の外 | **出さない。** 翌朝9時にまとめる |

**★ ONにしても、主語はAIのままです。** 「お相手から」とは書きません。相手の名前も、金額も、「養育費」という語も出しません。

**★ 深夜に通知を出しません。** 眠れない夜に相手の存在を知らせないことが、時間帯設定の目的です。

アイコンはカピバラ（伏せ）34px、角丸9px。

## O. 用語集 ／ 例外

### O-1. 用語集

**五十音順にしません。手続きで出てくる順です。** 調べるためではなく、対話の途中で分からない語に当たった人が読む画面だからです。

順序: 監護者 → 基準日 → 債務名義 → 先取特権 → …

- 文体は記事と同じで、すべて「〜とされています」
- **1語あたり3行以内**
- 末尾に「一般的な説明です。個別のご事情への助言ではありません。」

### O-2. 招待が使えないとき

**「無効」「エラー」と書きません。取り消した側を責める書き方もしません。**

- 「このご案内は、いまは使えません」
- 「お渡しになった方が、取り消されたようです。もう一度お渡しいただくことは、できます。」
- 破線の注記「こちらから、お渡しになった方にご連絡することはありません。」

### O-3. すでに参加されている

**行き止まりにしません。** 同じリンクを2度開く人は珍しくありません。

「このご案内は、すでにお使いになっています」→ メールアドレス入力 → 確認コードを送る（I-7 へ合流）

### O-4. 通信できないとき

**技術的な内容を出しません。** 文言は第1弾で確定したものです。

- 上部に帯（`muted-bg`）:「**うまくいきませんでした。もう一度お試しください。**」
- 送信できていない発言の下に 10.5px `attention-text`「まだ送れていません」
- 破線の注記「**お書きになったものは、この端末に残っています。消えません。** つながったときに、そのままお送りします。」
- 送信ボタンは `#DCC7A6`（無効状態）

**★ 「消えません」の一行が最重要です。** 注意色は送信状態にだけ使い、本文はそのまま残します。**書くこと自体は、つながっていなくても続けられます。**

## 取り決めの状態遷移（7状態）

第1弾の6状態に、**「ご自身の記録」**（I-5 で新設）が加わります。

```
未着手 ──▸ 係争中 ──▸ 合意済 ──▸ N-1 が対話に出る
              └──▸ 調停へ ──▸ N-2。ほかの項目は続く

合意済 ──▸ 変更申請中 ──▸ 相手側に K-6。返事まで現状が続く
合意済 ──▸ 逸脱 ──▸ 4-a。責める通知は送らない

ご自身の記録 ──▸ 合意済
  I-5 で記録 → 相手も同じ内容を記録した時点で
```

**「ご自身の記録」から「合意済」への遷移だけは、相手の操作を待つのではなく、両者が独立に記録した結果として起きます。**

### 状態が決めるもの

| 状態 | 出る画面 |
| --- | --- |
| 合意済になった瞬間 | N-1（対話の中） |
| 調停へ | N-2 |
| 変更申請中 | 相手側に K-6 |
| 逸脱 | 4-a |
| 全項目が未着手 | L-2（進捗バーを出さない） |
