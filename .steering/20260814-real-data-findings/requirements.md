## 1. ★★ 最優先：構造化抽出が、事実でない値を作っている

### 1.1 実測（同じ入力を3回）

原文に **「6万円」** とある費用相談を通した。

```
#1  amountYen: 5000     ← 誤り
#2  amountYen: 50000    ← 誤り
#3  amountYen: 50000    ← 誤り
```

**一度も正しく出ない。**

さらに、**金額も分担も出てこない事務連絡**（三者面談・制服の採寸）を通すと：

```
subject:   "入学金"                ← 原文に無い
shareText: "半分ずつ / 6倍4"       ← 原文に無い
date:      "2023-10-10"            ← 実在しない。原文は「来週火曜」
```

`subject` と `shareText` は、**スキーマの `description` に書いた例文**
（「例: 入学金 / 塾の費用」「例: 半分ずつ / 6対4」）**をそのまま複製している。**

### 1.2 なぜ気づかなかったか

**伝聞文（画面に出る文）は正しかった。**

> ご相談について、娘のメガネが壊れて**6万円**かかったので折半を希望されているそうです

★**言い換えは正確で、構造化抽出だけが壊れている。**
目に入るのは伝聞文なので、**目視では見つからない。**

### 1.3 何が起きるか

`payload` は Adjustment として保存され、**「決まったこと」に並ぶ。**

> 今回だけ　金額 50,000円／何について 入学金
> 取り決めそのものは変わっていません。

**存在しない合意事項が、間違った金額で、控えとして残る。**

### 1.4 ★ これは今回の方針の抜け穴だった

今回、**取り決め（公正証書）からは LLM を完全に外した**（P3）。
だが **Adjustment には LLM 抽出の数字が残っていた。**

> **P3 に、まだ例外があった。**

## 2. C1 は、実データの敵対的文言に効いていた

実データの対立は、**丁寧語のまま進む**のが特徴だった。

- 「〜した方が良いと思います」
- 「〜にあたると思われる」
- 「〜のでしょうか？」（質問の体裁で相手を疑う）

これらを通したところ、**法的な威嚇・詰問・子を人質にした威嚇は、すべて取り次がれなかった。**

> ★**強い結果である。**説明資料に書ける（実測であることも含めて）。

「原因帰属（〜のせいだ）」と「過去の蒸し返し」も落ちていた。
1メッセージ単位で「その論点の事実」を抽出する設計の、副次的な効果である。

## 4. 取り決めにできるのに、していないもの

> 特別費用の折半ルール（メガネ・キャンプ・医療費・学用品など**1万円超は折半**）

**画面に出しておらず、条項にも無い。**

## 5. シナリオに無い領域

実データの10大項目のうち、**3つがまるごと無い。**

| | |
| --- | --- |
| **学校トラブル・問題行動への対応** | 校則違反、対人トラブル、呼び出しへの対応分担 |
| **しつけ・生活ルールのすり合わせ** | お小遣いの方針、ゲーム・スマホの時間制限 |
| **★ 緊急対応・安全確認** | 家出、体調急変、安否確認 |

### 5.1 ★ 緊急は、扱えないと言うべき

実データには、**警察に捜索願を出す直前**まで発展した家出がある。

いまのアプリは、真逆を明記している。

> **お急ぎいただくご連絡はしません。期限もありません。**

**平時の設計としては正しい。**急かさないことを機能にした。
だが**緊急時には有害**である。

そして**いまのアプリには「これは扱えません」と言う場所が無い。**

> ★**扱えないものを入口に出さない**という規律は守っている。
> だが**扱えないことを、必要な場面で言う**仕組みが無い。
