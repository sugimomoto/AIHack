# Aida（あいだ）— 説明資料

> **離婚しても、子どもが健やかに育つための基盤になる。**

- AI HACK 2026 提出作品
- 本番：https://aida-4n47tjpp2a-an.a.run.app

## 1. 何を解こうとしているか

日本の離婚の約9割は**協議離婚**です。当事者だけで決めます。
そこで、決定的な差が出ています。

| | 養育費の取り決め率 | 面会交流の取り決め率 |
| --- | --- | --- |
| **協議離婚**（母子世帯 758,312） | **43.6%** | 27.9% |
| その他の離婚（同 192,146） | 81.2% | 56.5% |

そして、**養育費を現在も受けている母子世帯は 28.1%** です。

裁判所を経れば 81.2%。**制度が足りないのではなく、そこに至れていない。**

### なぜ至れないのか

3つが重なっています。

| | |
| --- | --- |
| **費用** | 公正証書の原案を専門家に頼むと 5万〜10万円 |
| **知識** | 何を決めればよいのか、当事者は知らない |
| **★ 会話** | **相手と話すこと自体が、いちばんの障壁** |

3つ目が本丸です。費用と知識は情報で解けますが、
**「その人と話したくない」は情報では解けません。**

## 2. 中心の主張

> ## メッセージを、転送しない。

父は AI と話し、母も AI と話します。
**書いた言葉そのものは、決して相手に届きません。**

```
A が書いたもの
  「また勝手に土曜に決めやがって。こっちだって必死なんだよ」
        ↓  ★ここを越えるのは、事実だけ
B に届くもの
  「面会交流の日程について、ご相談があるそうです。
    土曜日のご都合が難しいとのことです。」
```

### これは「フィルタ」ではありません

チャットに検閲を挟んだのではありません。**転送する経路が実装に存在しません。**

- 相手の発言は、**AI に渡す材料にも入りません**
- `/context` で、AI に渡している材料そのものを表示します
- **「安全です」と書く代わりに、渡していないことを画面で見せます**

不変条件としてテストで固定しています（**798 件**）。落ちたらリリースしません。

## 3. 価値仮説（3つ）

### ① 目的抽出 — 「要約」ではなく「基準に基づく取捨選択」

養育費なら、合意すべき項目は決まっています（月額・支払日・終期）。
**その基準を先に定義しておき、AI は基準に沿って情報を選びます。**

要約させると、論点が逸れます。**何を取るかを、先に決めておく。**

### ② 感情フィルタリング — 攻撃を削ぎ、事情を残す

削るのは**攻撃・批判・感情**です。**背景は残します。**

```
削る    「勝手に」「必死なんだよ」「少しは考えろ」
残す    「土曜が難しい」「職を失っている」
```

事情が消えると、相手は**理由の分からない要求**を受け取ることになります。
それでは合意できません。**残すものと削るものを、分けて設計しています。**

### ③ 仲介 — うまくいかなかったときに、いちばん効く

**予定どおりに進んでいるあいだ、当事者はこのアプリを必要としません。**

困るのは、予定どおりにならなかったときです。
そこは**直接連絡したくない相手と話さなければならない場面**であり、
**仲介の価値がいちばん高い。**

そして「会えなかった」は、責める言葉が最も出やすい場面でもあります。

## 3b. ★ 実データで測りました（2026-08-14）

実際の共同養育のやり取り **約1,080件（9.5か月）** の提供を受けました。
**推測で語らず、その文言を本物の実装に通しました。**

### C1 は、実データの敵対的な文言に効いていました

実データの対立は、**丁寧語のまま進む**のが特徴でした。

> **文面は載せません。**提供いただいた私信であり、
> **原文を渡さないという製品の主張とも矛盾する**ためです。性質だけを書きます。

| 入力の性質（実データ） | 結果 |
| --- | --- |
| 法的な語彙を用いた威嚇（丁寧語のまま、過去の金銭の件に遡及する） | **取り次がれない** |
| 連絡がなかったことへの非難（隠していた、という断定を含む） | **取り次がれない** |
| 通報を示唆する申し立て（面会の拒否を理由に、公的機関へ相談すると告げる） | **取り次がれない** |

想定していた攻撃語（「殺す」「死ね」）とは形が違います。
**それでも落ちていました。**原因帰属（「〜のせいだ」）と過去の蒸し返しも同様です。

### ★ そして、欠陥が3つ見つかりました

**測ったから見つかりました。**テストは全部通っていました。

| 実測 | |
| --- | --- |
| 原文「**6万円**」 | → `5000` / `50000` / `50000`。**3回とも誤り** |
| 金額も分担も無い連絡 | → `subject:"入学金"`（スキーマの**例文**）、`date:"2023-10-10"`（**実在しない**） |
| 運動会の写真の共有 | → 「決まったこと」に**控えが残っていた** |

**伝聞文（画面に出る文）は正しかった**ので、目視では見つかりません。

### 直し方 — 既存の検査を、逆向きに使いました

| 対象 | 求めるもの |
| --- | --- |
| 取次ぎ本文 | **逐語であってはならない**（原文の流出） |
| 事実の断片 | **逐語でなければならない**（でなければ捏造） |

> ## 言葉は渡さない。事実は、原文のまま。

金額は原文のまま取り、**コードで解釈**します。単位の換算は算術であって、LLM の仕事ではありません。

**修正後**：`60000`（正しい）。捏造は消え、お知らせでは控えが立たなくなりました。

### シナリオも作り直しました

実データの**8割以上が事務連絡**でしたが、シナリオは交渉中心（14 対 3）で**実態と逆**でした。

- カテゴリ **4 → 5**（★**学校のこと**を新設。学校の話が2つに割れていた）
- シナリオ **19 → 27**（実データの10大項目すべてに入口）
- ★**「決める」と題しながら決まらないシナリオを 0 件に**

## 4. AI が触る場所と、触らない場所

**今回の設計の核心です。**

| | 誰が作るか | AI | 公正証書 |
| --- | --- | --- | --- |
| **取り決め** | **本人が入力する** | **触らない** | **載る** |
| 相談（対話） | AI が仲介する | 受け止めと取次ぎ | 載らない |

### なぜ分けたか — 実測で3つ壊れたから

当初は「対話しているうちに取り決めができあがる」体験でした。そこから：

| 起きたこと | |
| --- | --- |
| **進学費用の相談が、合意済みの養育費の月額を書き換えうる状態だった** | 別の話をしているのに、既にある取り決めが動く |
| **「スマホ代」が「コピー代」に化けた** | 抽出時の言い換えが、品目名まで変えていた |
| **はっきり書いた人ほど、伝わる中身が減っていた** | 原文と一致する部分を落とす検査が働き、要約が空になった |

歯止めは入れられます。しかし**歯止めが要ること自体が構造の問題**でした。

> **取り決めを入力に限れば、これらは構造的に起こりません。**

### 数字と条項を、LLM に作らせない

| | |
| --- | --- |
| **金額** | 算定表を**引くだけ**。生成しない。AI が金額に触れる経路が無い |
| **条項** | ひな形の置換だけ。**弁護士法72条**（法律事務の取扱い）の問題がある |
| **置換に失敗したら** | **文書を出さない。**空欄のある法的文書は、空欄のない誤りより危険 |

## 5. 合意の作られ方 — 仮案を作って、了承してもらう

```
本人が入力 → 下書き（相手に見えない）→ お渡しする → 相手が了承 → 合意済
                  ↑                        ↓
                  └──── 取り下げる ────────┘
```

### 下書きは、相手に見えません

**画面で隠しているのではありません。サーバが返しません。**
API を直接見ても読めません。C1 と同じ強さで守っています。

> **下書きは、考えるための場所です。**
> 見られていると思うと、書けません。

### 「見ていない状態」には戻せません

取り下げはできます。ですが**「見なかったこと」にはできません。**

だから、**渡す前の確認シートの中**にこう書いています。

> お渡ししたあとで取り下げることもできますが、**一度ご覧になったことは取り消せません。**

ボタンの下に小さく書いても、押す前には読まれないからです。

### そして、この形が欠陥を1つ消しました

以前、実機でこう壊れました。

```
A の提案 3万円 ／ B の提案 4万円 で双方が承諾
  → 誰も合意していない 3万円が確定した
```

仮案→了承にすると、了承する側は**同じ仮案に**承諾します（payload はサーバが複製）。
**歯止めを足したのではなく、発生条件そのものが消えました。**

## 6. 対立を作らない設計

このアプリは、当事者の「あいだ」に立ちます。**どちらの側にも立ちません。**

| 場面 | どうしたか |
| --- | --- |
| **了承しないとき** | ★**対案をフォームで返させない。**「了承する」か「**このことを相談する**」の2つ |
| **差額** | **計算しない。**「2万円の開き」と書けば、それが争点として立つ |
| **既読** | **持たない。**「読んだのに返事が無い」を作らない |
| **通知・催促** | **出さない。**期限も設けない |
| **進捗の数字** | **出さない。**「4つのうち2つ」は、開くたびに残りを突きつける |
| **合意** | **片方だけでは成立しない。**取り決めも、おふたりで決めたルールも |

### ★ いちばん危うい画面を、作らずに済ませました

双方の案が違うとき、二つの金額を左右に並べる画面を設計していました。
デザイン依頼で「**いちばん難しいところ**」と書いた画面です。

**やめました。**

> 了承しないときは、**必ず仲介を通す。**
> それがこのアプリの主張そのものであり、
> **並べた時点で交渉の卓になる**画面に、そもそも到達しなくなります。

**そして、その機能は壊れていました。**別の案を保存しても画面に出ず、渡す手段もない。
**設計した画面に、一度も到達していませんでした。**

直さずに、経路ごと外しました。**危ういものが減る方向です。**

★ 代わりに「**先に渡した人が、その論点の筆を持つ**」を API で保証しています
（画面だけで止めません）。ただし**初回の仮案は、どちらからでも出せます。**
片方だけが起案できると、**もう片方は論点を卓に載せられなくなる**ためです。

## 7. やめたこと（正直に）

### 履行の記録と、逸脱の検知をやめました

毎月「支払いました」「入金を確認しました」を押す前提でした。

```
手間 → 押されない → 記録が無い → 逸脱として検知される
                                    ↓
              実際には払っているのに「確認できていません」と出る
                                    ↓
                    ★ 摩擦を作る。このアプリが減らすはずのもの
```

> **記録率が低い台帳は、正しい信号より誤った信号を多く出します。**

失うものも書いておきます。**逸脱の検知は、受給率に効く仕掛けとして唯一の実装でした。**
代わりに、**取り決めが作られること**と**公正証書になること**で効かせます。

### スケジュール管理もスコープ外にしました

予定を並べ、思い出させ、実施を追うのは、このアプリの役目ではありません。
**決まったことを残します。**日付は、決定事項の属性にすぎません。

## 8. 受給率に、どこで効くか

`28.1%` に対して、経路を素直に並べます。

| 経路 | 効き方 |
| --- | --- |
| **取り決めが作られること** | **最も大きい。**取り決めの有無が受給の前提（協議離婚の取り決め率 43.6%） |
| **公正証書になること**（債務名義） | 支払いが滞ったときの手段が残る |
| 継続的な連絡が成立すること | 関係が切れないこと自体が履行を支える |
| ~~毎月の記録~~ | **押されないので効かない** |

**今回の入力ウィザードは、いちばん効く経路に真正面から効きます。**

## 10. まだ無いもの

正直に書きます。

- **領収書などの画像**を扱えない（実費の精算に要る）→ Issue #6
- **公正証書そのもの（PDF）を預かれない**（置き場所だけ用意）→ Issue #6
- **証跡と精算**（振込までを見届ける）→ Issue #7
- ~~年金分割の按分割合は一次資料の確認が未了~~ → **確認済み**（`docs/verification-pension-split.md`）
- 面会交流の実施記録 → Issue #5

**扱えないものを、入口に出していません。**
慰謝料・親権者・婚姻費用も、画面にありません。

### ★ 確認して、記述を1つ取り下げました

年金分割について「按分割合には上限があるとされています」と書いていました。
**一次資料（日本年金機構）を確認したところ、そう書かれていませんでした。**

正しくは「定められる**範囲**は、年金事務所が出す**情報通知書**で分かる」です。
画面の注記を書き直しました。**書かれていないことを、アプリが断定しない。**

なお確認の過程で、**公正証書の謄本が合意分割の添付書類として認められる**ことも分かりました。
合意書だけだと**双方そろって年金事務所に行く**必要があります。
**このアプリが公正証書の原案を作る意義に、直接つながります。**
