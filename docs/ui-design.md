## 1. 変わらない前提：ユーザーの心理状態

**これを外すと実装全体が失敗する。**

このアプリを開く人は、人生でもっとも消耗している時期にいる。相手への強い怒り、あるいは恐怖を抱えており、**相手の名前が画面に出るだけで動揺する**。

国の調査では、養育費や面会交流の取り決めをしない理由の**第1位が「相手と関わりたくない」**だった。

> **「相手の存在を感じさせないこと」が、このプロダクトの機能そのものである。**

| | |
| --- | --- |
| ✅ 目指すもの | 静けさ・安全・守られている感じ |
| ❌ 避けるもの | 明るさ・元気・励まし・対立の可視化・急かし |

**判断基準**：*深夜に泣きながら開いても、ふざけて見えないこと。*

## 2. デザイン原則（確定）

| # | 原則 | 実装への現れ |
| --- | --- | --- |
| **U-1** | **相手の存在を最小化する** | 相手のアイコン・実名を出さない。呼称は「**お相手**」 |
| **U-2** | **二人を色で対立させない** | **当事者を指す色が存在しない。**彩度を持つのは AI と合意の2色だけ |
| **U-3** | **AIキャラクターは「愚痴を投げられる相手」** | **カピバラ**。表情差分・リアクションを作らない（→ §4） |
| **U-4** | **「合意」が主役** | 進捗バーと「8つのうち2つが決まりました」。祝わない |
| **U-5** | **急かさない** | 未読バッジ・赤ドット・既読・入力中表示を実装しない |

### 2.1 確定した色の方針

| # | ルール |
| --- | --- |
| 1 | **赤を使わない。**注意を促す場面でも、責める色ではなくくすんだクレイで静かに示す<br>（★逸脱・入金の未確認は、そもそも表示しなくなった） |
| 2 | **純黒・純白を使わない。**最も濃い文字色は `#3A342E`、最も明るい面は `#FFFCF5` |
| 3 | **図版用と文字用の値を分ける。**`#C08F3C` 等を `color:` に使うとコントラスト比を割る。テキストは `-text` 側を使う |

配色・タイポグラフィ・余白・角丸・モーションの**確定値は [design/README-v1.md](../design/README-v1.md) の Design Tokens を参照**。第2弾もこれを踏襲している。

## 3. ★ 3つの設計課題と、その解

デザイン依頼時に提示した3つの課題は、いずれも解けている。

### 課題1｜対話画面の3種別の描き分け

**「相手の生の言葉が届いていない」ことを、説明文なしで理解させる。**

| # | 種類 | 解 |
| --- | --- | --- |
| ① | 自分の発言 | 右寄せの吹き出し（78%幅）。直下に **「ここに書いたことは、お相手には届きません」** |
| ② | AI自身の発言 | カピバラマーク ＋ 左の吹き出し（82%幅） |
| ③ | **AIによる取次ぎ** | **吹き出しではない。画面幅いっぱいの「封書カード」** |

**③が①と別種に見える理由**——5つの属性が同時に反転する。

| | ① 自分の発言 | ③ 取次ぎ |
| --- | --- | --- |
| 寄せ | 右 | 幅いっぱい |
| 形 | 吹き出し | **見出し付きカード** |
| 幅 | 78% | 100% |
| 面 | 塗りのみ | **枠線＋破線の仕切り** |
| 署名 | なし | **「AIが要約しました」** |

> **文字を読む前に別種と分かる。このうち1つでも崩すと課題が解けなくなる。**

封書カードは3つの層を持つ。

```
┌─────────────────────────────────────┐
│ ✉ お相手からのご相談   AIが要約しました │ ← ヘッダ帯
├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤ ← 破線
│ 土曜の日程について、別案のご相談が    │
│ 来ています。                        │
│ 背景として、お相手は現在求職中との    │ ← 伝聞形式
│ ことです。                          │
├─────────────────────────────────────┤
│ お相手が書いた言葉そのものは          │ ← フッタ
│ 含まれていません。                    │
└─────────────────────────────────────┘
```

**①直下の「ここに書いたことは、お相手には届きません」と、③フッタの「お相手が書いた言葉そのものは含まれていません。」は、プロダクトの約束を担う。削らず、コントラストを落とさない。**

### 課題2｜合意ステータス6種を色に頼らず描き分ける

**アイコン ＋ 枠線のスタイル ＋ 色**の3信号で区別する。

| 状態 | アイコン | 枠線 | 色 |
| --- | --- | --- | --- |
| 合意済 | ✓ | 実線 | 合意（緑） |
| 係争中 | △ | 実線 | 注意（クレイ） |
| 未着手 | 点線の円 | **破線** | 無効 |

色を落としても、アイコンと枠線で判別できる。

### 課題3｜「今回だけ？ 今後も？」の重さの違い

**2つの選択肢を、視覚的な重さで差別化している。**

| | 今回だけ変更する | 今後も変更する |
| --- | --- | --- |
| 見た目 | 沈んだ面のみ。軽い | **枠線つきカード ＋ アイコン ＋ 合意色** |
| 補足 | 「9月13日の1回だけ。取り決めは変わりません。」 | 「**取り決めそのものを書き換えます。**お相手の同意が必要です」 |
| 追加情報 | なし | **変更前／変更後の差分を表示** |
| 確認 | 即時 | **確定前に条文をもう一度提示** |

さらに「**あとで決めることもできます**」という逃げ道を用意している。**急かさない**（U-5）の徹底。

## 4. AIキャラクター：カピバラ

### 採用理由

> 争わない。他の動物に背中を貸す。そして**表情筋が動かない**。
> **「無表情である」ことに説明が要らない**のが、この題材で選ぶ最大の利点。

### 実装ルール（重要）

| # | ルール | 理由 |
| --- | --- | --- |
| 1 | **表情差分もポーズ差分も作らない** | ユーザーの感情に反応して表情が変わると「**見抜かれた**」という監視感が生まれる。相手の相談を取り次ぐ場面で中立に見えなくなる |
| 2 | ポーズは2種のみ（伏せ／座り） | 伏せ＝通常の対話、座り＝相談の開始と空の状態 |
| 3 | **動きは3.2秒周期の呼吸だけ。**リアクションを実装しない | — |
| 4 | **温泉・ゆず・「まったり」を使わない** | 癒やしキャラとして消費されると、当事者の切実さと釣り合わない |

素材は `public/character/capybara.png`（伏せ）と `capybara-sit.png`（座り）。

> **1が最も重要。**「AIが感情を読み取って反応する」のは一般には良い体験だが、このプロダクトでは**監視されている感覚**に転ぶ。

**ボトムタブ5つ。**

| タブ | 役割 |
| --- | --- |
| **ホーム** | 今日の状態。取次ぎの有無、取り決めの進捗、いつでも書ける入口 |

各画面のレイアウト・文言・寸法は [design/README-v1.md](../design/README-v1.md)（基本5画面）と [design/README-v2.md](../design/README-v2.md)（追加画面）を参照。

| # | 画面 | 対応機能 | 状態 |

| A-1〜A-4 | **招待**（作成・メール文面プレビュー・受け取り側・待機中） | F15 | 確定 |

| E | ログイン | F14 | 確定 |
| **G** | **危険検知時の窓口提示** | F19 | ✅ **案2＋案3 で確定**（2026-08-11 → §5.2） |
| **H** | **オンボーディングの分岐** | C2 | ✅ **第3弾で納品**（2026-08-12 → §5.3） |

### 特筆すべき解

**① 年収の変換を「図」で見せる**

> 年収の入力は心理的な抵抗が大きい項目です。**文だけでは信じにくい種類の約束**なので、実際の値の変換を並べて示します。

```
入力した金額        →     お相手に見えるのは
4,380,000円               425〜450万円
```

第1弾の「ここに書いたことは、お相手には届きません」と**同じ役割の表示**として設計されている。

> ⚠️ **納品物の例には帯の誤りがある。**`design/README-v2.md` は 4,380,000円 → 「400〜425万円」としているが、
> 438万円は25万円刻みでは **425〜450万円** の帯に入る。**実装は正しい帯を用いる**（テストで検出済み）。
> 画面に出す例示値も実装側で整合させること。

**② 退会は「退会」と呼ばない**

見出しは**「ご利用をやめたいとき」**。ボタンは「やめたいと伝える」。

> 即時削除のボタンではない。**赤字にも、警告アイコンにも、破壊的操作の色にもしない。**設定の最下部に置くが、隠してもいない。

合意が法的文書の基礎である以上、単純な削除ボタンにはできないという制約を、**UIの語彙で表現**している。

**③ ナレッジはタブを増やさない**

5タブが埋まっているという制約に対し、**タブを増やさない**解を出している。詳細は README-v2 を参照。

### 5.2 ✅ 危険検知時の窓口提示は「案2＋案3の併用」（2026-08-11 決定）

3案が提示され、**併用を採用する。**

| 採用 | 内容 |
| --- | --- |
| **案2** | 入力欄の脇に**常設**。盾アイコン ＋「相談できる公的な窓口」。**検知に一切反応しない** |
| **案3** | 検知したときのみ、**次に開いたときのホーム**に1枚。他のカードと同じ形。**本人に向けたものだと明示しない** |
| ~~案1~~ | 会話の末尾にカードを置く。**採用しない** |

**判断の理由**

| # | 理由 |
| --- | --- |
| 1 | **案1は「読まれている」感覚が最も強く出る。**誤検知したとき、監視されているという体験が残る |
| 2 | **案3は時間差があるため、誤検知の印象が最も小さい。**書いた直後の羞恥や反発も避けられる |
| 3 | 案2で**常に手が届く場所**を確保しておけば、案3が届かなくても経路が残る |
| 4 | **会話の流れに一切触れない**——これが決定的。C1の「何を書いてもいい」を守れる |

**どちらの案でも守る原則（デザイナー提示）**

| # | 原則 |
| --- | --- |
| 1 | **AIは何も判定しない。**「あなたは危険な状態です」と言わない |
| 2 | **説教しない。**「そのような表現は不適切です」は禁止 |
| 3 | **検知したことを本人に告げない。**「〜という記述がありましたので」と書かない |
| 4 | 大きな警告を出さない（モーダル・警告色・感嘆符・振動を使わない） |
| 5 | **無視しても、次に同じものが出てこない。**一度閉じたら繰り返さない |
| 6 | 窓口は公的なものに限る（DV相談ナビ、法テラス、児童相談所など） |

> **3が最も重要。**検知を本人に告げた時点で、それは監視の通告になる。
> 気づいていることを、気づかせずに支える——それがこの画面の要件である。

**残る未決**：**検知の閾値**。誤検知したときの影響は案3で最小化されるが、閾値そのものは S17 で決める。

### ★ 第3弾で覆された順序（2点）

デザイン側から**実装済みの流れに対する指摘**として上がったもので、いずれも受け入れた。

**① 受諾した側に、その場で年収を聞かない**

> 「参加しない選択もできます」と伝えた直後に年収を聞くと、**あの一文が入口の作法だったことになる。**

実装は「受諾 → お子さん → 年収 → ホーム」だった。**年収をオンボーディングから外し**、
お金の話題で目安が要る場面になってから対話の中でうかがう形に変えた（H-2 は未実装）。

**② 「まだ相手と話していない」を独立した問いにしない**

> 聞いた時点で、**アプリが相手に伝える前提でいることが伝わる。**

実装は状況の5つ目に「まだ相手とは話していない」を置き、それ以外を招待へ通していた。
**招待をオンボーディングから外し**、ホームのカードからのみ開くようにした。
5つ目の選択肢は「まだ、よく分からない」に置き換えた。

### その他の受け入れた指摘

| 指摘 | 対応 |
| --- | --- |
| 2×2の表として聞くと詰問になる | **平たい5択に崩した。**「離婚していますか」と直接問う文言を持たない（テストで検査） |
| 同居は監護の実態を問うと読まれかねない | **用途を1行で限定。**「養育費をどちらが受け取る側になるか、この一点だけのために」 |
| 4人目以降を、本人の責任のように見せない | 「**話し合いは、そのまま進められます**」まで書く。エラーにも警告にもしない |
| 年収を飛ばせないと実質的な強制になる | 「あとで入力する」＋「**入れなくても、話し合いは続けられます**」を両方置いた |
| 進捗バーに飛ばせる画面を数えない | バーは3分割・**数字を出さない**。年収と取り決めはバーの外 |

| **L-2** | 取り決めが空 | 最初に開いたとき必ず見る画面 |
| **K-1** | 相談の一覧 | いま対話に直行しており、複数の相談を並べられない |

### K-6・N-1 で見つかった不具合（実装して初めて分かったもの）

| # | 見つかったこと | 影響 |
| --- | --- | --- |
| ★1 | **`REVISION_REQUESTED` から「断る」遷移が無かった** | 変更を断ると `IN_NEGOTIATION` に落ち、**断った人が現在の取り決めを失う**。`DECLINE_REVISION` を追加 |
| ★2 | **変更申請中が `isDocumentable` から漏れていた** | 相手が変更を申し出た瞬間、**合意済みの内容が公正証書の原案から消える**。「お返事があるまで、いまの取り決めが続きます」は書面についての約束でもある |
| ★3 | **申し出の理由（自由記述）が必ず消えていた** | 取次ぎの検査は「原文と10文字以上一致しないこと」を求める。本人が書いた文をかければ当然すべて落ちる。**書いた本人だけが「伝えた」と思い込む。**ホワイトリストからの選択に変更 |
| ★4 | **3つのパネルの高さ上限の合計が枠を超えていた** | 42%＋36%＋38%＝116%。**対話の高さが 0 になっていた。**まとめる側で 52% を持つ形に変更 |

> **★ 年収の経路が一度なくなっていた。**
> 順序の変更を受け入れた時点で、**受諾した側は年収を入れる画面を一つも持たなくなった。**
> 算定表は双方の年収で引くため、これは中核機能が動かない状態である。
> 通り道には戻さず、**ホームのカード**（`IncomeCard`）として塞いだ。
> 「あとにする」に相当する逃げ道と「入れなくても、話し合いは続けられます」は残してある。

## 6. 当初仕様との差分と判断

| # | 項目 | 当初 | 納品 | 判断 |
| --- | --- | --- | --- | --- |
| 1 | ダークモード | 必須 | **スコープ外**（単一テーマ） | ✅ **対象外と決定**（→ §6.1） |
| 2 | ボトムタブ | 4つ（対話／合意／予定／設定） | **5つ**（ホーム追加） | ✅ **採用**（→ §6.2）<br>★4つ目は「これから」→**「決まったこと」**に改名（→ §5.4） |
| 3 | キャラクター | 方向性のみ指定 | **カピバラに確定** | ✅ 採用 |
| 4 | 3端末デモ | 依頼に含めた | 個別画面のみ | 実装側で組む（S12） |
| 5 | 4画面の精度 | — | 「これから」「逸脱の詳細」「設定」「公正証書の原案」は**ラフ** | ★「逸脱の詳細」は**画面ごと無くなった**（→ §5.4） |

### 6.1 ✅ ダークモードは対象外（2026-08-11 決定）

当初は「夜間の利用が想定される」「眩しくないこと」を根拠に**必須**としていたが、**対象外とする。**

**判断の理由**

| # | 理由 |
| --- | --- |
| 1 | **当初の懸念には単一テーマで応えられている。**背景 `#FDF8EF` は純白より十分に低輝度であり、夜間に眩しくない |
| 2 | **単純な反転では作れない。**「彩度を持つのは AI と合意の2色だけ」「赤を使わない」「当事者を色分けしない」という色の役割分担を、ダーク側で作り直す必要がある |
| 3 | 得られる価値に対してコストが見合わない |

**反映済み**：product-requirements.md NFR-05 ／ architecture.md §2.2.1 ／ development-guidelines.md §4.1

> **将来対応する場合は、納品パレットからの派生ではなく、役割つきパレットを再設計する。**明度の反転だけでは §2.1 のルールを維持できない。

### 6.2 ホームタブの追加について

当初は4タブ（対話／合意／予定／設定）を想定していたが、**ホームが追加されて5タブになった。**

★ 4つ目は「これから」→**「決まったこと」**に改名し、**アイコンもカレンダーからチェックに変えた。**
カレンダーのままだと**予定表に見える**（→ §5.4）。

> ★ 実装時に、**取り決め（書面に✓）と決まったこと（✓）が同じ形に見える**問題が出た。
> 取り決めのアイコンから内側のチェックを外し、**書面**にした。
> 取り決めは公正証書に入れる内容なので、意味としても書面のほうが正しい。

これは妥当だと判断する。理由：

- **アプリを開いた直後に「今日は何があるか」だけを見て閉じられる。**毎回チャット画面に着地すると、心理的負担が高い
- 「お返事は、急ぎません。」という文言が置かれており、**U-5（急かさない）を最初の画面で体現している**
- 取次ぎの件数を表示するが、**バッジではなくカードとして静かに提示**している

> ホーム画面の存在自体が「開いても何もしなくていい」という許可になっている。

## 5.4 ★ 第4弾で作り直した画面（2026-08-13 納品）

実体験者へのヒアリングを受けて、**取り決めの作り方そのものを変えた。**

### 取り決め（A-1 / A-2）

| | |
| --- | --- |
| 一覧 | 4論点＋状態を**1行の文**で。**数字を出さない**（1/4・○% を作らない） |
| 論点ごと | **6状態**（未入力／下書き／お相手のご返事待ち／お相手から案／別の案／合意済／取り下げ） |

**★ 下書きは、地の色ごと閉じる**

```
画面の地   bg (#FDF8EF) → surface-2 (#F7EFE1)
上部の帯   鍵アイコン ＋「まだお相手には見えていません」
```

トグルや小さなアイコン1つでは示さない。**渡した瞬間に、地と帯の2点が同時に変わる。**
一覧でも同じ手法で、**その行だけ沈み、鍵が付く。**

**★「お相手に見ていただく」は一方向のボタン。トグルにしない**

> ON/OFF のスイッチにすると、**取り消せるように見える。**
> 取り下げは、渡したあとの画面にある**別の操作**である。往復する一つのスイッチに見せない。

**★「取り消せません」は確認シートの中に置く**

ボタンの下に小さく書いても、**押す前には読まれない。**
取り下げたあとの画面でも、**同じ言葉で書く。**ここで黙ると、あの警告が形式だったことになる。

### 🚫 お相手から別の案（S-4）— **やめた**

**二つの金額を左右に並べない。並べた時点で交渉の卓になる。**

★ 設計としてこの帯を用意したが、**経路ごと外した。**

> 受け取った側にできるのは「**了承する**」か「**このことを相談する**」の2つ。
> 対立は、フォーム上の対案の応酬ではなく、**必ず仲介を通す。**
> それがこのアプリの主張そのものである。

★ 実装も壊れていた。別の案を保存しても画面が `INCOMING` に戻り、
下書きが見えず、渡す手段も無かった（実機で検出）。**S-4 には一度も到達していなかった。**

★ `Divergence.tsx` / `RangeBar.tsx` は残してある。呼ばないだけ。
（算定表の帯そのものは、お相手の案を見るときに使っている）

以下は、そのときの設計である。

算定表の帯に、両方の案を目盛として重ねる。

- 色も太さも同じ。どちらかを強調しない
- **差額を計算しない。**「2万円の開き」と書けば、それが争点として立つ
- ラベルは「あなた／お相手」ではなく **「はじめの案／お相手の案」**
  → 仮案モデルでは案に時間の順序がある。**人ではなく案を主語にすると、対立の構図が薄くなる**

数量でない論点（面会交流など）は帯が引けないので、**合っている項目を先に、多く見せる。**

### フォームを詰問にしない4つ

| | |
| --- | --- |
| 飛ばせることを、先に見せる | 見出しの右に「あとでも」を**常時**置く。入力してから分かるのでは遅い |
| 必須の印を持たない | アスタリスクも「必須」ラベルも使わない |
| 進捗を出さない | 1/4 も ○% も出さない |
| 空欄を欠落として描かない | 破線の下線と「—」。**赤も感嘆符も使わない** |

### 決まったこと（旧「これから」）

**引き算だけ。**外したもの：予定・履行の記録・逸脱・先取特権・リマインド。

「お約束として控えています」は、**済んだかどうかを問わない書き方**である。
押されないボタンを置かない代わりに、**状態を持たない文**にしてある。

### オンボーディング3枚

説明 → メール登録（飛ばせる）→ 招待するか。**状況の5択は廃止。**

★ 招待を戻すにあたっての歯止め3つ：
関係の状態を一切聞かない／2択を**同じ寸法**で／
**「お渡しになるまで、お相手には何も届きません」を選択肢より先に置く。**

## 5.5 ★ 実機で見つけて直したもの（2026-08-14）

デザインの納品後、**実際に2人で触って**出てきたものである。
どれも机上では見えなかった。

### ★ 届いた封書が、2px に潰れていた（最重要）

お相手からの取次ぎ（③ 封書カード）が、**DOM にはあるのに高さ 2px だった。**
枠線1px × 2 だけが残り、**画面では細い横線にしか見えなかった。**

原因は CSS の一点である。

> ★ flex の子は、`overflow` が `visible` でないと**自動の最小高さが 0** になる。

封書だけが `overflow-hidden` を持っている（角丸で中を切るため）。
吹き出し（① 自分の発言／② 取次ぎの控え）は持たない。

★ **だから、自分の発言だけが残り、お相手から届いたものだけが消えた。**
**C1 の主題そのものが、画面から消えていた。**

→ `shrink-0` を付けた。

### ★ 新しいものが、画面の外にあった

いちばん下へ送る処理が、**送信のあとにしか走っていなかった。**
送った人は自分の分が見えるが、**開いただけの人は上に留まる。**

> ★ **受け取る人ほど、下を見ない。送った人だけが、下にいた。**

さらに測ると、`scrollIntoView`（高さ0の目印）も
`behavior: "smooth"` も**効いていなかった。**
→ 入れ物の `scrollTop` を直接動かす。**常に即時。**

★ 画面が滑ると「何かが起きた」ように見えるが、
起きたのは**届いていたものが見えるようになっただけ**である。

### ★ 相手が届いても、画面が取り直さなかった

取得が初回だけだった。**開いたまま置いたタブに、あとから届いたものが出ない。**
→ 別のウィンドウから戻ったとき（`focus` / `visibilitychange`）と、
見えているあいだ20秒ごとに取り直す。

★ **通知はしない。**音もバッジも赤い点も出さない。**急かさない**（AC-06）は変えない。
変えたのは「**見ているのに古いまま**」を無くすことだけである。

### 引き算したもの

| | |
| --- | --- |
| 相談画面の上の「このご相談では、いまの取り決めは変わりません」 | ★**削除。**`FORMAL` が 0 になり、**すべての相談で出る**ようになった。<br>どれにも出る注意書きは区別をしない。**区別しないものは、注意にならない**<br>しかも書く前に、画面のいちばん上に出ていた |
| 中身が空の「お話し合いの内容」 | ★**出さない。**読める項目が0行でも見出しと注意書きだけが残っていた |

### 入口（TOP）を作り直した

5枚のカードが、**3種類の別々の読み手を1列に混ぜていた。**

★ 足したのは「**どう進むか**」の3行である。

```
① おひとりで、AIに話す        書いた言葉は、お相手に届きません
② 決めたいことを、書いて渡す   金額と条項は、ご自身で。AIは作りません
③ 記録が同じになったら、合意   片方だけでは成立しません
```

**「転送しません」は、しないことしか言っていない。**
話したあと何が起きるのかが無いと、何をするアプリか分からない。

★ **入口を2つに分けない。**「お戻りになる」を別リンクにせず、
同じ欄で受ける（すでに登録があれば「おかえりなさい」と出る）。
**選ばせずに、こちらが見分ける。**

★ 審査用（AIに渡しているもの／原価／体験モック）は**隠さず、宛先を書いて分けた。**
「CT-1〜CT-4」は当事者には何のことか分からない。
