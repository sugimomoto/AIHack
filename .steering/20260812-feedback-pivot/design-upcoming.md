# 整理：「これから」は何のためにあるのか

- 対応する要求：`requirements.md`（AC-3 の見直し）
- 作成日：2026-08-12（履行の記録についての判断を受けて改訂）

---

## 1. きっかけ

> 取り決めが「これから」に並ぶ（AC-3）は要らない。取り決めは独立している形で構わない。
> **履行の記録は、単純に手間だと思う。**
> どちらかといえば、**相談での決定事項を記録する場所**のほうが良い。
>
> 面会交流の会う日も並べなくてよい。
> **おそらくスケジュール管理はこのアプリのスコープ外。**
> どちらかといえば、**会えなかった場合にその相談を AI を介してできる**ことのほうが、
> このアプリのメリットが強い。

---

## 2. ★ 履行の記録をやめる

### 2.1 手間だから記録されない。そして、それが害になる

毎月、双方が「支払いました」「入金を確認しました」を押す前提だった。

```
手間 → 押されない → 記録が無い → 逸脱として検知される
                                   ↓
              実際には払っているのに「記録が確認できていません」と出る
                                   ↓
                        ★ 摩擦を作る。このアプリが減らすはずのもの
```

文言は「未払い」ではなく「確認できていません」に抑えてある。
だが**抑えても、事実でない疑いが相手に見える形で立つ**ことは変わらない。

> **記録率が低い台帳は、正しい信号より誤った信号を多く出す。**
> 出さないほうがよい。

### 2.2 受給率への効き方を、置き直す

`docs/product-requirements.md` §4.1 の指標「養育費の受給率 28.1% → 向上」に、
このアプリが効く経路はどこか。

| 経路 | 効き方 |
| --- | --- |
| **取り決めが作られること** | **最も大きい。**取り決めの有無が受給の前提になる（取り決め率 43.6%） |
| **公正証書になること**（債務名義） | 支払いが滞ったときの手段が残る |
| 継続的な連絡が成立すること | 関係が切れないこと自体が履行を支える |
| ~~毎月の記録~~ | **押されないので効かない。**むしろ誤った信号を出す |

**★ 今回のウィザードは、いちばん効く経路（取り決めを作れること）に真正面から効く。**
毎月の記録は、そこに乗らない。

### 2.3 やめると消えるもの

| | 扱い |
| --- | --- |
| 履行の申告（支払いました／入金を確認しました） | **画面から外す** |
| 逸脱の検知 | **画面から外す** |
| 先取特権の説明 | 逸脱が出なくなるので出番が消える。**ナレッジ記事には残る**（制度の説明としては有用） |
| リマインド（支払日が近い） | **外す。**督促になる |

> ★ コードは消さない（`design.md` §7）。呼び出しを外すだけ。
> Issue #7（証跡と精算）で作り直すときの土台になる。

## 2.4 スケジュール管理をスコープ外にする

会う日も並べない。**予定を管理する機能を持たない。**

| | スケジュール管理 | このアプリがすること |
| --- | --- | --- |
| 何をする | 予定を並べ、思い出させ、実施を追う | **決まったことを残す** |
| 日付の扱い | 主役 | **決定事項の属性にすぎない** |

外すもの：毎月の支払日（2章）／**会う日**／リマインド

> 会う日の生成（`visitationDatesOf`）は**今日この場で実装したもの**である。
> Issue #5（面会交流と養育費の非対称）に効かせるために入れた。
> **今回スコープ外になる。**コードは残すが呼ばない。
>
> なお、この判断で**非対称そのものは解消する。**
> 「お金には日付と追跡がつき、それ以外は消える」構造が、
> **どちらにも置かない**ことで消える。

## 2.5 価値の置き直し：うまくいかなかったときに相談できること

> 会えなかった場合に、その相談を AI を介してできる。

これは**予定を管理するより強い。**理由：

- 予定どおりに進んでいるあいだ、当事者はアプリを必要としない
- **困るのは、予定どおりにならなかったとき。**そこは直接連絡したくない相手と
  話さなければならない場面であり、**仲介の価値がいちばん高い**
- 「会えなかった」は責める言葉が出やすい場面でもある。
  **受け止めと取次ぎの検査が、まさに効く**

### 足すもの：相談のシナリオ

いまのシナリオには「日程を変更したい」はあるが、**うまくいかなかったあと**が無い。

| 題 | kind | 分類 |
| --- | --- | --- |
| **会えなかったことを相談する** | ADJUSTMENT | 子どもと会うこと |
| **お支払いのことで相談する** | ADJUSTMENT | お金のこと |

- 書き出しの案内（`opening` / `examples`）も用意する
- **責める言い方を例に置かない**
  例：「先月お会いできなかったので、振替をご相談したいです」

## 3. 「これから」の再定義

> **「これから」＝ お話し合いで決まったことの記録。**

相談から決まったことだけを置く。取り決め（公正証書の内容）は独立させる。

```
これから
  8月22日 ／ 送迎                お約束として控えています
  9月3日  ／ 14時 小学校 父母会   お約束として控えています
  ──────────────────────────
  今回だけ 曜日 日曜日 に変更（面会交流）
  取り決めそのものは変わっていません。
```

### 3.1 載るもの

| # | 中身 | 出どころ |
| --- | --- | --- |
| 1 | 了承された個別の約束（日付つき） | 相談（L2） |
| 2 | 今回だけの変更 | 相談（C3） |
| 3 | 揃った調整（臨時費用の分担など） | 相談（Adjustment） |

### 3.2 載せないもの

- 取り決めそのもの（→ 取り決め画面）
- 毎月の支払日・会う日（→ 出さない。§2）
- 履行の記録・逸脱（→ 出さない。§2）

### 3.3 名前を見直す

第1弾は「『予定』だと督促感が出る／過去の記録も並ぶため」として「これから」を選んだ。
**督促感を避ける理由は、いまも有効。**

だが中身が**「これから起きること」から「決まったことの記録」に変わった。**
「これから」のままだと、**予定表だと思われる**（スコープ外にしたはずのもの）。

| 案 | 評価 |
| --- | --- |
| これから（現状） | 予定表に見える。スケジュール管理を期待させる |
| **決まったこと** | 中身と一致する。督促感も無い |
| 記録 | 事務的すぎる |

> **「決まったこと」を推す。**変更は文言だけで、実装の影響は小さい。

### 3.4 空のとき（L-3 の書き換え）

| | |
| --- | --- |
| いま | 「取り決めが決まると、その日付がここに入ります。ご自身で入力していただく必要はありません。」 |
| **これから** | 「**お話し合いで決まった予定が、ここに並びます。**ご自身で入力していただく必要はありません。」 |

「入るものの例」も書き換える。

```
・お会いになる日を変えたとき
・費用の分担が決まったとき
・送り迎えなど、その回だけのお約束
```

末尾の「予定を思い出させる通知は、設定で切れます。」は **外す。**
リマインドを外すので、この通知は出ない。**できないことを書かない。**

## 6. ★ この判断で失うものを、正直に

- **逸脱の検知は、受給率に効く仕掛けとして唯一の実装だった。**
  それを外す。代わりに、**取り決めを作れること**（ウィザード）と
  **公正証書になること**（債務名義）で効かせる、という置き換えである
- 「払われていない」ことにアプリが気づく道は、いったん無くなる
- Issue #7（証跡と精算）で作り直すときは、
  **手で押させない形**（証跡・期日・状態の自動化）を考える必要がある
- **今日実装した面会交流の日程生成が、スコープ外になる。**
  Issue #5 に効かせるために入れたが、**非対称は「どちらにも置かない」ことで解消する。**
  Issue #5 はこの判断を反映して書き直す必要がある
