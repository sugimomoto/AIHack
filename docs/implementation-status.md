> **「作っていないもの」を書き残すことは、「作ったもの」を書くことと同じくらい重要である。**

## 6. ★ 実データで測ったこと（2026-08-14）

実際のやり取り約1,080件の提供を受け、**推測せず実装に通した。**

### 6.1 C1 は、実データの敵対的文言に効いていた

実データの対立は**丁寧語のまま進む**（「〜と思われる」「〜でしょうか？」）。
想定していた攻撃語とは形が違う。それでも：

| 入力（実データ・仮名化済み） | 結果 |
| --- | --- |
| 「名誉毀損にあたると思われる／不正アクセスの疑いも含めて厳正に対処する」 | **取り次がれない** |
| 「なぜこちらに連絡がなかったのか／隠していた。隠匿」 | **取り次がれない** |
| 「娘を父親に会わせる事を拒否していると言う事で、警察と児童相談所に相談します」 | **取り次がれない** |

「〜のせいだ」（原因帰属）と過去の蒸し返しも落ちていた。

### 6.2 ★ 構造化抽出が、事実でない値を作っていた（修正済み）

| 実測 | 内容 |
| --- | --- |
| **金額** | 原文「6万円」→ `5000` / `50000` / `50000`。**3回とも誤り** |
| **例文の複製** | `subject:"入学金"`（description の例）、`shareText:"例: 半分ずつ / 6対4"`（description そのもの） |
| **title の複製** | `subject:"何について"` |
| **架空の日付** | 原文「来週火曜」→ `"2023-10-10"` |

**伝聞文（画面に出る文）は正しかった。**目視では見つからない種類の欠陥だった。

**直し方**

> **言葉は渡さない。事実は、原文のまま。**

| 対象 | 求めるもの |
| --- | --- |
| 取次ぎ本文（`content`） | **逐語であってはならない**（原文の流出・INV-4a） |
| 事実の断片（`payload`） | **逐語でなければならない**（でなければ捏造） |

金額は原文のまま取り、**コードで解釈する**（`parseYen`）。解釈できなければ持たない。

**修正後の実測**：`amountYen: 60000`（正しい）／捏造は消え、お知らせでは控えが立たない。

| # | 内容 |

| **端末をまたぐ復帰** | セッションは端末に紐づく。メール登録が無いと戻れない（C-04） |

| **`kind` の意味の縮小** | 対話から取り決めを作らなくなったため、`FORMAL` はほぼ意味を失った。<br>いま効くのは **ADJUSTMENT／NOTIFICATION の区別**である |
