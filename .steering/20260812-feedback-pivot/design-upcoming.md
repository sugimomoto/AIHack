# 整理：「これから」は何のためにあるのか

- 対応する要求：`requirements.md`（AC-3 の見直し）
- 作成日：2026-08-12（履行の記録についての判断を受けて改訂）

---

## 1. きっかけ

> 取り決めが「これから」に並ぶ（AC-3）は要らない。取り決めは独立している形で構わない。
> **履行の記録は、単純に手間だと思う。**
> どちらかといえば、**相談での決定事項を記録する場所**のほうが良い。

---

## 2. ★ 履行の記録をやめる

### 2.1 手間だから記録されない。そして、それが害になる

毎月、双方が「支払いました」「入金を確認しました」を押す前提だった。

```
手間 → 押されない → 記録が無い → 逸脱として検知される
                                   ↓
              実際には払っているのに「記録が確認できていません」と出る
                                   ↓
                        ★ 摩擦を作る。このアプリが減らすはずのもの
```

文言は「未払い」ではなく「確認できていません」に抑えてある。
だが**抑えても、事実でない疑いが相手に見える形で立つ**ことは変わらない。

> **記録率が低い台帳は、正しい信号より誤った信号を多く出す。**
> 出さないほうがよい。

### 2.2 受給率への効き方を、置き直す

`docs/product-requirements.md` §4.1 の指標「養育費の受給率 28.1% → 向上」に、
このアプリが効く経路はどこか。

| 経路 | 効き方 |
| --- | --- |
| **取り決めが作られること** | **最も大きい。**取り決めの有無が受給の前提になる（取り決め率 43.6%） |
| **公正証書になること**（債務名義） | 支払いが滞ったときの手段が残る |
| 継続的な連絡が成立すること | 関係が切れないこと自体が履行を支える |
| ~~毎月の記録~~ | **押されないので効かない。**むしろ誤った信号を出す |

**★ 今回のウィザードは、いちばん効く経路（取り決めを作れること）に真正面から効く。**
毎月の記録は、そこに乗らない。

### 2.3 やめると消えるもの

| | 扱い |
| --- | --- |
| 履行の申告（支払いました／入金を確認しました） | **画面から外す** |
| 逸脱の検知 | **画面から外す** |
| 先取特権の説明 | 逸脱が出なくなるので出番が消える。**ナレッジ記事には残る**（制度の説明としては有用） |
| リマインド（支払日が近い） | **外す。**督促になる |

> ★ コードは消さない（`design.md` §7）。呼び出しを外すだけ。
> Issue #7（証跡と精算）で作り直すときの土台になる。

## 3. 「これから」の再定義

> **「これから」＝ お話し合いで決まったことの記録。**

相談から決まったことだけを置く。取り決め（公正証書の内容）は独立させる。

```
これから
  8月22日 ／ 送迎                お約束として控えています
  9月3日  ／ 14時 小学校 父母会   お約束として控えています
  ──────────────────────────
  今回だけ 曜日 日曜日 に変更（面会交流）
  取り決めそのものは変わっていません。
```

### 3.1 載るもの

| # | 中身 | 出どころ |
| --- | --- | --- |
| 1 | 了承された個別の約束（日付つき） | 相談（L2） |
| 2 | 今回だけの変更 | 相談（C3） |
| 3 | 揃った調整（臨時費用の分担など） | 相談（Adjustment） |

### 3.2 載せないもの

- 取り決めそのもの（→ 取り決め画面）
- 毎月の支払日・会う日（→ 出さない。§2）
- 履行の記録・逸脱（→ 出さない。§2）

### 3.3 名前

「これから」は**未来だけを指す語に見える**が、済んだ約束も並ぶ。
第1弾の設計は「『予定』だと支払期日の督促感が出る。過去の記録も同じ画面に並ぶため」として
この名を選んでいる。**督促感を避ける理由は、いまも有効。**名前は変えない。

### 3.4 空のとき（L-3 の書き換え）

| | |
| --- | --- |
| いま | 「取り決めが決まると、その日付がここに入ります。ご自身で入力していただく必要はありません。」 |
| **これから** | 「**お話し合いで決まった予定が、ここに並びます。**ご自身で入力していただく必要はありません。」 |

「入るものの例」も書き換える。

```
・お会いになる日を変えたとき
・費用の分担が決まったとき
・送り迎えなど、その回だけのお約束
```

末尾の「予定を思い出させる通知は、設定で切れます。」は**残す**
（リマインドを外すので、実際には通知が出ないが、設定の存在は伝えてよい）。

→ ★ リマインドを外すなら、この一文も外す。**できないことを書かない。**

## 5. 実装への影響

| | |
| --- | --- |
| `SchedulePanel` | 予定・履行・逸脱・先取特権・リマインドの表示を外す。約束と例外だけにする |

| `generateObligations` ほか | **残す。**呼ばない |
| L-3 の空の状態 | 文言を書き直す |
| E2E | 履行・逸脱の検査を外す。約束が並ぶことを検査する |

---

## 6. ★ この判断で失うものを、正直に

- **逸脱の検知は、受給率に効く仕掛けとして唯一の実装だった。**
  それを外す。代わりに、**取り決めを作れること**（ウィザード）と
  **公正証書になること**（債務名義）で効かせる、という置き換えである
- 「払われていない」ことにアプリが気づく道は、いったん無くなる
- Issue #7（証跡と精算）で作り直すときは、
  **手で押させない形**（証跡・期日・状態の自動化）を考える必要がある
