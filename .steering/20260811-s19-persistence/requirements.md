## 1. 目的

> **S4・S5 の成果を DB に繋ぎ、両当事者の画面で一連の流れが動く状態にする。**

### 1.1 現状の断絶

```
S4  受け止め      … 動く。しかし保存されない
S5  取次ぎの生成  … 動く。しかし相手に届かない（保存経路がない）
                                  ↑
                        ★ここが繋がっていない
```

**生成できることと、届くことは違う。**
C1 は「相手のセッションに何が現れるか」で決まるため、
保存と読み出しを通して初めて検証が完結する。

### 1.2 ★ 認証をどう扱うか

本番では Firebase Authentication による当事者の解決が必要である。
しかし、**両当事者の画面を並べて確認する**ためには切替が要る。

```
❌ 開発用の切替を、本番でも通る形で入れる
     → 誰でも他人の当事者になれる。C1 が無意味になる

✅ 本番では絶対に通らない形で入れる
     → 検査を先に書き、通らないことをテストで固定する
```

**これは利便性の問題ではなく、安全性の問題である。**

## 3. ★ テストを先に書く対象

| 対象 | 理由 |
| --- | --- |
| **開発用の切替が本番で通らないこと** | **通ると C1 が無意味になる** |
| **保存後も相手の原文が読めないこと** | S2 の担保が、実データで成立するか |
