## 4. 設計上の要点

### 4.1 論点は enum、payload スキーマは DB

**コードで固定するのは「論点そのもの」であって、「payload の形」ではない**（→ functional-design.md §4.9）。

| 何を | どこで |
| --- | --- |
| 論点の enum（8つ） | **コード** — 法律に由来し、実務知見では増減しない |
| payload スキーマ | **DB**（`PayloadSchema`・版管理） |
| 条項ひな形 | **DB**（スキーマ版に紐づく） |

### 4.2 マスタは seed ファイルで版管理する

編集は運営が DB を直接操作する方針だが、**seed ファイルを Git で管理し、そこから投入する**。法的文書の定義を含むため、変更履歴が追えない状態を作らない。

### 4.3 状態遷移は1箇所に集約する

`domain/agreement/stateMachine.ts` を経由しない状態変更を作らない（→ development-guidelines.md §2.2）。
