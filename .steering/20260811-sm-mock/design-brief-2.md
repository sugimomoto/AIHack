## ★ A. 招待とケースの成立

### この画面が背負っていること

このアプリは**二人が揃わないと本来の価値が出ません**。しかしユーザーは「相手と関わりたくない」層です。

> **招待という行為そのものが、相手を刺激しうる。**

### A-1. 招待の作成（招待する側）

**渡し方を2つから選べるようにしてください。**

| 方式 | 内容 |
| --- | --- |
| **リンクをコピーして自分で渡す** | アプリは相手に接触しない。弁護士経由・親族経由・既存の連絡手段など、渡し方を本人が決める |
| **メールで送る** | アプリが送信する |

**設計上お願いしたいこと**

- **どちらが安全か、押しつけずに伝えたい。**「リンクを自分で渡す」ほうが相手を驚かせにくい、という情報は出したいが、選択を誘導しすぎない
- メールを選んだ場合、**文面は編集できません**（プロダクト側で固定）。その旨を、制限として不快に感じさせずに伝えたい
- **送信前に、相手に届く文面をそのまま見せてください。**何が送られるか分からないまま送らせない

### A-2. 送信される招待メールの文面（これもデザイン対象です）

**件名・本文から内容が推測されないこと。**相手の職場や家庭で見られる可能性があります。

| 制約 | |
|---|---|
| 件名に「離婚」「養育費」「調停」を**出さない** | |
| 送信者の実名を出すかどうか | **選べるようにしたい** |
| 自由文の欄は**作らない** | この経路で罵倒や脅迫を送れないようにするため |

> **結果として、通常のメールより安全な経路になります。**それが伝わる文面にしたい。

### A-3. 招待を受け取った側の最初の画面

**相手にとっては「元配偶者から何か来た」という状態です。**構えている人が最初に見る画面になります。

伝えたいこと：

- これは何のアプリか
- **参加しても、相手と直接やりとりすることにはならない**
- 断ってもよい
- 個人情報が相手に見えるわけではない

### A-4. 相手が参加していない状態の表示

招待したが、まだ応じていない期間があります。**この期間を「待たされている」と感じさせたくない。**

- 催促のボタンは作りません（U-5）
- 再送も基本的にしません
- **「相手が参加するまで一人でできること」への導線**（→ B）

## ★ B. 準備モード（相手の参加前）

### 何のための画面か

**相手が参加しなくても、一人で使えるようにします。**

```
参加を待つ間に：
  ├ AIと対話して、自分の考えを整理する
  ├ 取り決めたい内容を下書きとして構造化しておく
  └ 相手が参加した瞬間、それを提案として出せる状態にしておく
```

### 設計上お願いしたいこと

- **「準備中である」ことが分かるが、劣った状態に見えないこと。**一人でも意味がある画面にしたい
- 通常の相談画面と**どう違って見せるか**。同じに見えると「相手に届いた」と誤解される危険があります
- 下書きが溜まっていく感じ。ただし**急かさない**
- 相手が参加した瞬間の遷移

> **ここは「相手が来るまでの待合室」ではなく、「一人で準備する場所」として設計してください。**

## C. 前提情報の登録（オンボーディング）

算定表を引くために必要な情報を登録します。

| 項目 | 備考 |
| --- | --- |
| 子の生年月日 | 複数人 |
| 基準日（別居日） | |
| **自分の年収** | ★下記 |

### ★ 年収の扱い（重要）

**入力した精密な年収は、相手には見えません。**相手に伝わるのは算定表の「帯」だけです。

```
入力: 4,380,000円             ← 相手には見えない
   ↓
相手に見える: 「400〜425万円」  ← 算定表のセルが特定できる粒度
```

**これを入力画面で伝えてください。**年収の入力は心理的な抵抗が大きい項目です。「何がどこまで相手に見えるのか」が分からないと、正確に入力してもらえません。

第1弾の「ここに書いたことは、お相手には届きません」と同じ役割の一文が要ります。

## ★ D. ナレッジ（制度・手続きの解説）

### なぜ必要か

AIは**個別の法的助言をしません**（法規制上の制約）。しかしユーザーは制度を理解する必要があります。

**この矛盾を、画面を分けることで解きます。**

```
【個別の助言】AIが「あなたはこうすべき」と言う   → できない
【一般的な情報】ナレッジで制度を説明する        → できる
【対話】AIは「一般的な説明はこちら」と誘導する   → できる
```

### 構成

| 分類 | 項目の例 |
| --- | --- |
| 手続き | 協議離婚とは／公正証書とは／公証役場の使い方／調停とは |
| お金 | 養育費の決め方／算定表の読み方／特別費用とは |
| 制度 | 2026年4月の改正で何が変わったか／法定養育費／先取特権／共同親権 |
| 用語 | 債務名義・監護者・基準日 ほか |

### 設計上お願いしたいこと

- **一覧と記事本文**の2画面
- **AIとの対話から記事へ飛べる導線**。逆に、記事から相談を始められる導線
- **「これは一般的な説明であり、個別の助言ではありません」**という位置づけが伝わること
- 監修者の表示（弁護士監修を明示できる場合に備えて枠を用意）
- **法律の話が、怖く見えないこと。**このプロダクトのユーザーは法律に不慣れで、かつ消耗しています

> タブをどこに置くかも提案してください。現在5タブが埋まっています。「これから」に統合する、設定内に置く、対話から辿るのみにする——選択肢があると思います。

## F. 設定（退会を含む）

第1弾ではラフでした。今回は退会を含めて詰めたいです。

| 項目 |
| --- |
| 相手の表示名の変更 |
| 通知設定（**通知に本文を出すかどうか**を含む） |
| ナレッジへの導線（Dの配置による） |
| **退会・データ削除** |

### 退会について

**単純な「退会する」ボタンにはできません。**

- 合意した内容は**法的文書の基礎**であり、一方の意思だけで消えてよいものではない可能性があります
- 相手が残っている場合の扱いがあります
- **削除範囲は現在検討中**（弁護士に確認中）

そのため、**「退会したい」と伝える導線**として設計してください。即時削除のボタンではなく、**何が起きるかを説明したうえで手続きに進む**形を想定しています。

## ★ G. 危険を検知したときの窓口提示 ⚠️ 要相談

### 状況

対話の中で、**書いた人が被害を訴えている**ことをAIが検知する場合があります（暴力・恐怖の記述など）。

現状、**何も起きません。**これは欠落だと判断しました。

### やりたいこと

**公的な相談窓口を、静かに提示する。**（DV相談ナビ、法テラス、児童相談所など）

### ★ 最も難しい設計課題

| ❌ やってはいけない | 理由 |
| --- | --- |
| AIが説教する（「そのような表現は不適切です」） | **「何を書いてもいい」という約束が壊れる** |
| 大きな警告を出す | 驚かせる。監視されている感覚になる |
| 「あなたは危険な状態です」と決めつける | AIが判定してよいことではない |

| ✅ 目指すもの |
| --- |
| **静かで、押しつけがましくなく、しかし見落とされない** |
| 本人が必要と思ったときにだけ手を伸ばせる |
| **無視しても、責められた感じがしない** |

> **これは今回いちばん難しい設計です。**
> 「気づいているけれど、踏み込まない」という態度を、UIで表現する必要があります。
> カピバラの無表情さが活きる場面かもしれません。

**まず方向性の案を2〜3出していただき、議論させてください。**いきなり作り込まなくて構いません。
