## 1. 目的

> **招待の受諾から、本番で一連の流れが動く状態にする。**

### 1.1 なぜパスワードを持たないか

```
❌ メール/パスワード
     このアプリは、住所・年収・子の情報を持つ。
     パスワードを保持すると、漏洩時の被害がそこに及ぶ。

✅ 招待トークン → セッション
     パスワードを一切保持しない。
     漏れて困るものを、そもそも預からない。
```

**docs の C-04「招待コードのみで進める」と一致する。**

### 1.2 ★ ここを誤ると、C1 が意味を失う

セッションが偽造できれば、**誰でも他人の当事者になれる。**
S19 で開発用切替を厳しくしたのと同じ理由である。

## 2. スコープ

### 2.1 実装する

| # | 項目 |
| --- | --- |
| 1 | **署名付きセッション**（HMAC-SHA256） |
| 2 | **HttpOnly / Secure / SameSite の Cookie** |
| 3 | 招待の受諾 → セッション発行 |
| 4 | `resolveParty` にセッション経路を追加 |
| 5 | ログアウト |

### 2.2 実装しない

| 除外 | 理由 |
| --- | --- |
| パスワード | **意図的に持たない** |
| 端末をまたぐ復帰 | 再招待で対応（C-04） |
| 多要素認証 | 範囲外 |

---

## 3. ★ テストを先に書く対象

| 対象 | 理由 |
| --- | --- |
| **改竄したセッションを受け付けないこと** | **偽造できれば C1 が意味を失う** |
| **署名鍵が違えば通らないこと** | 鍵の取り違えに気づけるように |
| **期限切れを受け付けないこと** | 端末を離れたあとに使われない |
| **Cookie 属性**（HttpOnly / Secure / SameSite） | JS から読めない・平文で飛ばない |

---

## 4. 受け入れ条件

- [ ] **AC-01｜1文字でも改竄されたセッションを拒否する**
- [ ] **AC-02｜別の鍵で署名されたセッションを拒否する**
- [ ] **AC-03｜期限切れを拒否する**
- [ ] **AC-04｜Cookie が HttpOnly かつ SameSite=Lax 以上**
- [ ] AC-05｜招待の受諾でセッションが発行される
- [ ] AC-06｜**本番で開発用切替より認証が優先される**

---

## 5. 設計上の要点

### 5.1 鍵が無ければ起動しない

`SESSION_SECRET` が未設定なら、**セッションを発行も検証もしない。**
既定値を持たせない。既定値は、いつか本番で使われる。

### 5.2 セッションに入れるもの

`partyId` と `caseId` と期限のみ。**名前や連絡先を入れない。**
Cookie は端末に残る。
