## ★ 実データで C1 が完結した

**両当事者の画面を並べ、双方向で確認した。**

```
Aが書いた: 月3万が限界。こっちだって仕事切られて必死なんだよ。
           そっちだって働いてるだろ、少しは考えろ

Bに現れた: 養育費について、月額3万円を上限にしたいとのことです。
           背景として、現在は職を失い経済的に困難な状況にあるとのことです。
           ── お相手が書いた言葉そのものは含まれていません。


Bが書いた: 3万なんてふざけないで。こっちは子どもの塾代も出してるのに。
           せめて4万にしてほしい。

Aに現れた: 養育費について、最低でも月4万円にしてほしいとのことです。
           背景として、子どもに塾の費用がかかっているそうです。
```

**「必死なんだよ」「少しは考えろ」「ふざけないで」は、どちらにも届いていない。**
**「失職」「塾代」という合意に必要な事実だけが越えた。**

### 保存を通した検証

```
Aの原文が、Aの画面にはある        ✓
★Aの原文が、Bの画面には無い       ✓
★非難『必死』がBに届いていない     ✓
★非難『少しは考えろ』が届いていない ✓
★Aの受け止め応答がBに無い         ✓
★今回の取次ぎがBに現れる          ✓
★今回の取次ぎがAには現れない       ✓
```

## 設計上の記録

### 相談は当事者ごとに分かれている

```
cons_party_dev_a   … Aのセッション
cons_party_dev_b   … Bのセッション
```

**セッションが跨がらないことが、パスの設計そのものになっている。**
`scopedMessages` はここを拠り所にしている。

### 保存の順序に意味がある

```
1. 自分の発言を保存       … 相手からは読めない
2. 受け止めを保存         … 同上
3. 取次ぎを検査して保存   … ★ここで初めて相手側に現れる
```

3 が失敗しても 1・2 は残る。**受け止めは取次ぎに依存しない。**

### 開発用の切替は安全性の問題である

本番で通ると、**誰でも他人の当事者になれる。C1 が無意味になる。**
利便性の話ではないため、通らないことをテストで固定してから実装した。
