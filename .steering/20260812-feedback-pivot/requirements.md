# 要求：入口を「定型入力」に切り分ける（ユーザーフィードバック反映）

- 作成日：2026-08-12
- 起点：実体験者へのヒアリング
- 議事の原本：`.meetings/`（**Git 対象外・実名を含む**）。本書は匿名化済み

---

## 1. 背景

### 1.1 フィードバックの中心

> **入口機能**は「公正証書・基本取り決めの**定型入力（ウィザード形式）**」。
> **コア機能**は「離婚後の**日常的コミュニケーションの仲介**」。
> ドラフト作成は **AI 相談に全面依存せず**、年収・財産の有無・面会ルールなどを
> ウィザードで入力・生成する。

専門家にドラフトを頼むと5万〜10万円かかる。そこを定型入力で効率化しつつ、
**その後に都度発生する連絡こそが本体**、という整理である。

### 1.2 ★ いまの実装は、その逆になっている

**取り決めを作る道が、AI 対話しかない。**

| | 定型入力 | 対話 |
| --- | --- | --- |
| 養育費 | △「離婚済み・取り決めあり」を選んだ人だけ | ○ |
| **面会交流** | **✗** | ○ |
| 財産分与・年金分割 | ✗（そもそも対象外） | ✗ |

「これから決める」層——**国の調査で最も多い層**——には、対話しか道がない。
フィードバックが「全面依存しない」と名指ししたところに、依存が残っている。

### 1.3 すでに満たしているもの（今回の対象外）

| フィードバック | 実装 |
| --- | --- |
| 合意と共有で挙動を分ける | `kind`（FORMAL/ADJUSTMENT/NOTIFICATION）で帰結を分岐 |
| 共有に合意前提を混ぜない | 取り決めを動かせるのは FORMAL だけ。書き込み直前でも検査 |
| 要約ではなく取捨選択 | 抽出は「言い回しだけ言い換え、事実は変えない」 |
| 攻撃的表現の緩衝／DV 配慮 | 受け止めは感情を否定せず、取次ぎだけが検査を通る。窓口は常設 |

## 2. 今回の要求

### 2.1 スコープに入れるもの

**対話を経ずに、基本の取り決めへ到達できる道を作る。**

1. **面会のルールの定型入力**（回数・曜日・週・時間・受け渡し場所）
2. **養育費の定型入力を、すべての状況の人が使えるようにする**
   （いまは「離婚済み・取り決めあり」を選んだ人にしか出ない）
3. 入力したものが、**対話で合意した場合とまったく同じ扱い**になること
   （予定に並ぶ／公正証書の原案に載る／変更の申し出ができる）

### 2.2 スコープに入れないもの

| | 理由 |
| --- | --- |
| 財産分与・年金分割・慰謝料 | 扱える設計になっていない。**扱えないものを入口に出さない** |
| 臨時費用を独立した単位にする | → Issue #7 |
| 領収書などの画像 | → Issue #6 |
| 面会の実施記録 | → Issue #5 |
| 口座連携による入金確認 | **「アプリは入金を観測できない」という不変条件を捨てることになる** |

## 3. ユーザーストーリー

### US-1（これから決める人）

> 離婚に向けて条件を話し合っている。**何を決めればよいのかが分からない。**
> 対話で一つずつ引き出されるより、**決めるべき項目が最初から並んでいて、
> 埋められるところから埋めたい。**

### US-2（すでに決めてある人）

> 公正証書は作ってある。その内容を入れておけば、
> **予定や履行の記録に使える**と聞いた。養育費だけでなく**面会のルールも入れたい。**

### US-3（対話から入りたい人）

> 何から書けばよいか分からない。**フォームを見せられると身構える。**
> これまでどおり、思っていることから書き始めたい。

> ★ US-3 を壊さないこと。**定型入力は道を増やすのであって、置き換えではない。**

---

## 4. 受け入れ条件

- [ ] **AC-1**：対話を一度も使わずに、面会のルールを取り決めにできる
- [ ] **AC-2**：AC-1 の取り決めが「これから」に会う日として並ぶ
- [ ] **AC-3**：AC-1 の取り決めが公正証書の原案に載る
- [ ] **AC-4**：AC-1 の取り決めに対して「変更を申し出る」ができる
- [ ] **AC-5**：定型入力は**どの状況を選んだ人にも**開ける
- [ ] **AC-6**：定型入力を**飛ばせる**。飛ばしても行き止まりにならない
- [ ] **AC-7**：片方が入力しただけでは**合意にならない**
      （記録として残り、相手が同じ内容を記録したときに合意になる）
- [ ] **AC-8**：入力に書かれていない項目を、こちらで埋めない

## 5. 制約

### 5.1 壊してはいけない不変条件

| # | 内容 |
| --- | --- |
| **P3** | **数字と条項を LLM に作らせない。**定型入力はこの規律に沿う（むしろ強化する） |
| **合意の成立** | 双方が承諾し、**かつ内容が一致**したときだけ確定（`canFinalizeAgreement`） |
| **G-3 / G-3b** | 条項に出せるのは、表記の定義がある値だけ。意味の定まらない値を出さない |
| **C1** | 定型入力の内容も、**そのままは相手に渡らない**。合意した事項だけが共有される |

### 5.2 設計上の規律

- **扱えないものを選択肢に出さない**（財産分与などを並べない）
- **詰問にしない。**「必ず入力してください」と書かない
- 飛ばせること。**埋まっていないことを、遅れとして書かない**

### 5.3 時間

締切 2026-08-15 15:00。**提出物は「完全版」ではなく、
コンセプトと体験価値が伝わるデモと説明資料**（フィードバックで合意済み）。
