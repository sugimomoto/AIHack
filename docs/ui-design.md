## 1. 依頼内容

離婚・共同養育の当事者が使う**スマートフォンアプリ**のUIを設計してください。

| 項目 | 内容 |
| --- | --- |
| **フォームファクタ** | **スマートフォン専用**。基準ビューポート **390 × 844**（iPhone 15 相当） |
| 最終形 | iOS / Android ネイティブアプリ |
| 現在の実装 | Webアプリ（Next.js ＋ Tailwind CSS）。**レイアウトとデザインはスマートフォン前提** |
| ナビゲーション | **ボトムタブ**（4つ） |
| ダークモード | **必須** |

> PC版は作りません。PC幅で開いた場合は中央に固定幅で表示するだけです。

**成果物は §11 を参照してください。**

## 2. プロダクトの説明

**Aida（あいだ）** は、離婚する／した父母のあいだにAIが立ち、**二人を直接やりとりさせずに合意をつくり、それを守り続けるアプリ**です。

決定的な特徴が1つあります。

> **メッセージを転送しません。**
> 父はAIと話す。母もAIと話す。AIが両者のあいだで着地点を探り、**合意した内容だけ**が共有されます。
> 相手が書いた言葉そのものは、一度も相手に届きません。

父が「また勝手に土曜に決めやがって」と打っても、母の画面に出るのは
**「土曜の日程について、別案の相談が来ています」** というAIからの静かな相談だけです。

### 2.1 このアプリがやること

```
【1】離婚時の取り決めを決める        … 養育費・面会交流
        ↓ この合意が基準になる
【2】決めたあとの調整を続ける        … 日程変更・塾の費用・進路
        ↓
【3】約束が守られているか見守る      … 支払い・面会の記録、逸脱の検知
```

**【2】が利用時間の大半を占めます。**【1】は一度きり、【2】【3】は10年以上続きます。

### 2.2 目的

> **離婚しても、子どもが健やかに育つための基盤になる。**

親同士の連絡を楽にすることは目的ではなく、手段です。

## 3. ★ 最重要の前提：ユーザーの心理状態

**これを外すとデザイン全体が失敗します。**

このアプリを開く人は、人生でもっとも消耗している時期にいます。

- 相手への強い怒り、あるいは恐怖を抱えている
- **相手の名前が画面に出るだけで動揺する**（実際にそういう要望があります）
- アプリを開くこと自体が心理的な負担
- 子どものために我慢して使っている

国の調査では、養育費や面会交流の取り決めをしない理由の**第1位が「相手と関わりたくない」**でした。

> **「相手の存在を感じさせないこと」が、このプロダクトの機能そのものです。**

### 3.1 スマートフォンであることの意味

手のなかで、ひとりで開かれます。**深夜、ベッドのなかで、泣きながら開かれることもあります。**

| 状況 | デザインへの要求 |
| --- | --- |
| 夜間に使われる | **ダークモード必須**。眩しくないこと |
| 片手で使われる | 主要な操作は**親指の届く下半分**に |
| 感情が高ぶった状態で使われる | 誤タップで取り返しがつかないことが起きない。確定操作は一段深く |
| **人に見られたくない** | アプリ名・通知・スクリーンショットから内容が推測されにくいこと |

最後の項目は特に重要です。DV・つきまといの文脈が現実にあります。**ロック画面に「元夫から連絡が来ています」と出るような設計は危険です。**

### 3.2 デザインが果たすべき役割

| | |
| --- | --- |
| ✅ 目指すもの | **静けさ・安全・守られている感じ・ここでは怒らなくていい** |
| ❌ 避けるもの | 明るさ・元気・励まし・対立の可視化・急かし |

**判断基準**：*深夜に泣きながら開いても、ふざけて見えないこと。*

## 4. デザイン原則

### U-1｜相手の存在を最小化する

- 相手のアイコン・実名・顔写真は**出さない**
- 相手は「**お相手**」など中立な呼称。**ユーザーが表示名を自由に変更できる**（機能として必須）
- 相手の発言を想起させる引用・吹き出しを使わない

### U-2｜二人を色で対立させない

**左右を赤と青に分けるような配色は避けてください。**対立構造を視覚的に強化してしまいます。

色で最も目立つべきなのは当事者ではなく、**AIと「合意」**です。

### U-3｜AIキャラクターは「愚痴を投げられる相手」

**このプロダクトにはAIキャラクターが必要です。**これは共同養育の当事者本人から出た要件です。

> メッセージを一旦、**AIのキャラクターに投げる**。「これを相手に伝えて」と頼むと、AIが要約して相手に伝えてくれる。

**なぜキャラクターが要るのか**

無機質なシステムに向かって「あいつが勝手に決めやがって」とは書けません。
このアプリの中核は「感情をぶつけても相手に届かない」ことですが、**ぶつける先が必要**です。
空白のテキストボックスでは、人は本音を書きません。

**「かわいい」の方向性**

| ✅ 目指す方向 | ❌ 避ける方向 |
| --- | --- |
| **穏やか・控えめ・寄り添う** | ポップ・元気・にぎやか |
| 静かにそこにいる | 感情表現が豊か、リアクションが大きい |
| 色数を絞る | カラフル、装飾的 |
| 抽象的〜半具象（動物的すぎない） | 記号的にかわいいマスコット |
| 大人が持っていて恥ずかしくない | 子ども向けアプリに見える |

**振る舞い**

- 感情を受け止めるときは、静かにそこにいる
- 相手の相談を取り次ぐときは、一歩引いた中立な立場に見える
- **喜怒哀楽を大きく表現しない**（ユーザーの感情に反応しすぎない）
- アニメーションは最小限

> 表情差分や複数ポーズの要否も含めて提案してください。**「表情を持たせない」という選択肢もありえます。**

### U-4｜「合意」が主役

このアプリの成果物は合意です。合意した項目が増えていくことが、唯一のポジティブな進捗表現になります。
ただし**祝いすぎない**。紙吹雪やバッジは不適切です。静かに確定する感じ。

### U-5｜急かさない

未読バッジ、赤い通知ドット、「入力中…」、既読表示は**使いません**。
そもそもリアルタイム性を持たない設計です。相手を待たせている感覚を与えないこと。

## 5. トーン & マナー

### 5.1 使ってほしい方向

- 低彩度・落ち着いた配色。**ライト／ダークの両方**
- 余白を広く。情報密度は低め
- 角は柔らかく。ただし丸すぎない（子ども向けアプリにしない）
- 日本語主体。可読性重視の落ち着いたサンセリフ
- アニメーションは最小限。ゆっくり、控えめに

### 5.2 明確に避けてほしいもの

| NG | 理由 |
| --- | --- |
| 笑顔の家族写真・イラスト | 当事者にとって残酷な表現になる |
| 明るいビタミンカラー、装飾的なグラデーション | 場違いな軽さ |
| 赤／青の対立的な色分け | 対立を視覚化してしまう |
| ポップで元気なマスコット | 題材の重さと合わない（キャラクター自体は必要／→ U-3） |
| 「かんたん！」「安心！」的なコピー | 当事者は簡単だと思っていない |
| ゲーミフィケーション（バッジ・レベル・連続日数） | 不適切 |
| 未読バッジ・赤ドット・既読・入力中表示 | 相手の存在を意識させる |
| ダークパターン（同意を促す強調ボタン等） | **法的合意を扱うため厳禁** |
| LINE 風の左右振り分け吹き出し | 相手と直接話している印象を与える |

## 6. 文言規約

**画面に出る言葉は、デザインの一部です。**

### 6.1 使ってはいけない語

| 使わない | 代わりに使う | 理由 |
| --- | --- | --- |
| 違反 | **逸脱** | 責める語彙を避ける |
| 未払い・滞納 | **入金が確認できていません** | 断定を避ける（反映遅れがありうる） |
| 元夫 / 元妻 | **お相手** | 関係性を想起させない |
| 相手のメッセージ | **お相手からのご相談** | 相手の言葉ではないため |
| チャット | **対話** / **相談** | 相手と直接話す印象を避ける |
| テンプレート / 定型文 | **選択肢** | 定型文は採用していない |
| ユーザー登録 | **招待** | 双方の参加が前提 |

### 6.2 表現の規約

| 項目 | 規約 |
| --- | --- |
| 法的な事柄 | 断定しない。「〜とされています」「〜の可能性があります」 |
| **相手の申告** | **伝聞形式。「〜とのことです」** |
| 逸脱の表現 | 責めない。事実として静かに示す |
| エラー | 技術的な内容を出さない。**「うまくいきませんでした。もう一度お試しください」** |

### ★ 画面1｜対話（最優先）

**このアプリの中心画面です。**

**必ず「AIと1対1で話している」画面に見えること。**相手とチャットしている印象を与えたら失敗です。

#### 1-a｜相談の開始（トピック選択）

対話は**シナリオを選んで開始**します。ただし**選択を必須にしてはいけません。**

```
┌──────────────────────────┐
│  何について相談しますか？    │
├──────────────────────────┤
│  ╭────────────────────╮  │
│  │  お金のこと          │  │
│  ╰────────────────────╯  │
│  ╭────────────────────╮  │
│  │  子どもと会うこと     │  │
│  ╰────────────────────╯  │
│  ╭────────────────────╮  │
│  │  子どもの進路・生活   │  │
│  ╰────────────────────╯  │
│  ╭────────────────────╮  │
│  │  日常の連絡          │  │
│  ╰────────────────────╯  │
│                          │
│  ────────────────────    │
│  選ばずに書く         ▸   │ ← ★塞いではならない
├──────────────────────────┤
│ ┌──────────────────┐ ▶  │
│ │ メッセージを入力    │    │ ← 入力欄は常に開いている
│ └──────────────────┘    │
└──────────────────────────┘
```

> **⚠️ トピック選択を強制してはいけません。**
> 「まず愚痴りたい」人に選択を強いると、このアプリの核心である**感情の受け止めが選択画面の後ろに隠れます。**
> 入力欄は常に開いておき、自由入力から始まった場合はAIが後からシナリオへ紐付けます。

分類を選ぶと、その配下のシナリオ一覧（各5〜8個）が出ます。**各分類の末尾に必ず「その他（自由に書く）」を置きます。**

参考：シナリオの例

| 分類 | シナリオ |
| --- | --- |
| お金のこと | 養育費を決める／塾・習い事の費用／進学費用の分担／今月の支払いを待ってほしい |
| 子どもと会うこと | 面会のルールを決める／今回の日程を変更したい／学校行事に参加したい／長期休暇の過ごし方 |
| 子どもの進路・生活 | 進学について／医療について／転居・転校について |
| 日常の連絡 | 送迎をお願いしたい／子どもの体調を伝える／写真・成長を共有する |

#### 1-b｜対話（★最重要の設計課題）

登場する要素は**3種類だけ**です。**この3つの描き分けが、このアプリで最も重要なデザイン課題です。**

```
┌──────────────────────────┐
│  今回の日程を変更したい ⌄   │ ← 現在のシナリオ（切替可・控えめ）
├──────────────────────────┤
│                          │
│  ╭────────────────────╮  │
│  │ ③ お相手からのご相談 │  │
│  │ 土曜の日程について、 │  │
│  │ 別案の相談が来ています│  │
│  │ 背景として、お相手は │  │
│  │ 現在求職中とのことです│  │
│  ╰────────────────────╯  │
│                          │
│      ╭──────────────────╮│
│      │① また勝手に土曜に ││
│      │  決めやがって     ││
│      ╰──────────────────╯│
│                          │
│  ╭────────────────────╮  │
│  │ ② そのお気持ち、    │  │
│  │   受け止めました     │  │
│  ╰────────────────────╯  │
│                          │
├──────────────────────────┤
│ [日曜がいい] [今は決めない]│ ← AIが提示する選択肢
│ ┌──────────────────┐ ▶  │
│ │ メッセージを入力    │    │
│ └──────────────────┘    │
└──────────────────────────┘
```

| # | 種類 | 例 | 求められる印象 |
| --- | --- | --- | --- |
| ① | **自分の発言** | 「また勝手に土曜に決めやがって」 | **ここには何を書いてもいい。誰にも届かない** |
| ② | **AI自身の発言** | 「そのお気持ち、受け止めました」 | 落ち着いた第三者 |
| ③ | **AIが相手の相談を取り次いだもの** | 「土曜の日程について、別案の相談が来ています」 | **相手の言葉ではなく、AIの言葉**であることが伝わる |

> **③の表現が最重要です。**
> 相手の存在は伝わる。しかし相手の言葉ではない。この微妙な位置づけを視覚的に表現してください。
> ①と③が**明らかに別種のものに見える**なら、この課題は解けています。

**選択肢について**：入力欄の上に、AIが提示する選択肢を出す領域があります。これは**定型文ではありません。**選んだものは相手に送られるのではなく、AIへの入力になります。

#### 1-c｜★「今回だけ？ 今後も？」の確認

**このアプリで最も特徴的なインタラクションです。**

日程変更などの申し出があったとき、AIは**合意（取り決め）を参照して**こう聞きます。

```
┌──────────────────────────┐
│  ╭────────────────────╮  │
│  │ 取り決めでは        │  │
│  │ 「月1回・第2土曜」  │  │
│  │ となっています。     │  │
│  │                    │  │
│  │ 今回だけの変更ですか？│  │
│  │ それとも今後もですか？│  │
│  ╰────────────────────╯  │
│                          │
│  ╭────────────────────╮  │
│  │  今回だけ変更する    │  │
│  │  取り決めは変わりません│  │
│  ╰────────────────────╯  │
│  ╭────────────────────╮  │
│  │  今後も変更する      │  │
│  │  取り決めを変更します │  │
│  ╰────────────────────╯  │
└──────────────────────────┘
```

**2つの選択が持つ意味の違いが、見た目で伝わってほしい。**

| | 今回だけ | 今後も |
| --- | --- | --- |
| 意味 | その回だけの例外 | **法的な取り決めそのものを変える** |
| 重さ | 軽い | **重い** |

「今後も」は取り決めの改訂にあたるため、**一段深い確認**（確定前にもう一度確認する等）があってよいと思います。ただし**脅かさないこと**。

### 画面2｜合意

離婚時に決めるべき項目は**8つ**あります。その一覧と状態を表示します。

```
┌──────────────────────────┐
│  合意の状況                │
│  2 / 8 項目が決まりました   │
├──────────────────────────┤
│  養育費              合意済 │
│  月50,000円 / 毎月末日     │
│                          │
│  面会交流            係争中 │
│  調整中                   │
│                          │
│  親権者              未着手 │
│  財産分与          今後対応 │
│  慰謝料            今後対応 │
│  年金分割          今後対応 │
│  婚姻費用          今後対応 │
│  離婚への同意      今後対応 │
├──────────────────────────┤
│  [ 公正証書の原案を見る ]   │ ← 合意が揃うと出現
├──────────────────────────┤
│  対話   合意   予定   設定 │
└──────────────────────────┘
```

#### ★ 状態は6種類。色だけに頼らず描き分けてください

| 状態 | 意味 |
| --- | --- |
| **未着手** | まだ話し合っていない |
| **係争中** | 意見が分かれている |
| **合意済** | 決まった |
| **変更申請中** | 事情が変わって再交渉中 |
| **逸脱** | 約束が守られていない |
| **調停へ** | AIでは解決できず、専門家・裁判所へ |

**設計課題：6状態を、色だけに頼らずに描き分けてください。**（色覚特性への配慮も兼ねて。形・記号・文字を併用）

とくに **「逸脱」を責める表現にしないでください。**強い赤は避け、事実として静かに示します。

項目をタップすると詳細（合意内容・合意日時・**変更履歴**）へ遷移します。

### 画面3｜公正証書の原案

- 合意した内容が、公証役場に持っていける文書の形で表示される
- **スマートフォンで長い法的文書を読ませる**という難所。条項ごとに畳めるなどの工夫が欲しい
- **「これは原案です。公正証書は公証人が作成します」という注意書きを常時表示**（法的に必須。目立つが威圧的でない置き方を）

#### 4-a｜逸脱の詳細と法的状態

入金が確認できない場合、その状態を客観的に説明する画面が要ります。

```
┌──────────────────────────┐
```

## 8. デモ用レイアウト

デモ動画では、**スマートフォン3台を横に並べて**撮影します。

```
      父の端末              合意状態（中央）           母の端末
  ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
  │  対話         │  ✕   │  合意         │  ○   │  対話         │
  │              │ ───▶ │              │ ───▶ │              │
  │ 「また勝手に  │届かない│  養育費 係争中 │ 届く │ お相手からの   │
  │  決めやがって」│      │  面会交流 係争中│      │ ご相談        │
  │              │      │    ↓ 更新     │      │              │
  │  AI:「その    │      │  養育費 合意済 │      │ 「日曜なら    │
  │  お気持ちは」  │      │  面会交流 合意済│      │  大丈夫です」  │
  │  対話 合意 予定│      │              │      │  対話 合意 予定│
  └──────────────┘      └──────────────┘      └──────────────┘
```

**専用画面は作りません。**通常のアプリ画面を端末フレームに入れて3つ並べるだけです。

ただし、この並べ方をしたときに次が成立してほしい：

> **「左の人の生の言葉が、右には届いていない」**
> これを、説明文なしで視覚的に理解させたい。

そのために、**画面1-b の3種別の描き分け**が効いてきます。
左端末の「自分の発言」と、右端末の「AIによる取次ぎ」が**明らかに別種のものに見える**なら、この課題は解けています。

**3台を並べる際の枠デザイン（端末フレーム、背景）も提案してください。**

## 9. デザインシステム要件

| 項目 | 要件 |
| --- | --- |
| 配色 | **役割つきパレット**（背景・面・境界・本文・補助テキスト・AI・合意・注意・無効）。**ライト／ダーク両方** |

| アイコン | 最小限。装飾的に使わない |
| モーション | 種類と duration を定義。**控えめ・ゆっくり** |
