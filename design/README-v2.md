## A. 招待とケースの成立

### 設計の前提

**招待という行為そのものが、相手を刺激しうる。** この一連の画面では、アプリが勝手に何かをしないことを繰り返し示します。渡し方は本人が決める。文面は事前に全文を見せる。相手が応じなくても催促しない。

### A-1. 招待の作成

**Layout**: 戻る＋タイトル「お相手を招待する」→ AI の一言 → 渡し方 2 枚 → 破線の注記 → 「あとにする」

**Components**:

1. **AI の一言**（カピバラ 28px ＋ `bubble-ai` の吹き出し）
   「お渡しの方法を、選んでください。」／`text-sub` で「どちらでも、あとから変えられます。」

2. **リンクをコピーして、自分で渡す**（`surface`、`border` 1px、角丸 20px、`padding: 18px`）
   - 説明「アプリはお相手に連絡しません。いつ、どの手段で渡すかを、ご自身で決められます。」
   - リンク欄：`surface-2`、角丸 16px、`padding: 12px 14px`、右に「コピー」`agree-text`

3. **メールで送る**（同じ寸法・同じ枠線）
   - 説明「アプリが送信します。文面は決まっていて、書き換えられません。送る前に、そのままお見せします。」
   - メールアドレス入力欄（`surface-2`、最小高 44px）
   - 「送られる文面を見る ▸」`agree-text`

4. **破線の注記**（`border-dashed` の 1px、角丸 20px、12.5px `text-sub-2`）
   「リンクをご自身で渡すほうが、お相手が急に連絡を受け取ることにはなりません。ただ、どちらが良いかは事情によります。」

**★ 実装ルール**

- **2 つのカードは面積・枠線・角丸をそろえ、どちらも強調ボタンにしません。** primary / secondary の関係を作らないでください
- 安全性の情報は**選択肢の外側**に置きます。カードの中に入れると推奨になります
- 末尾の「ただ、どちらが良いかは事情によります。」で判断を本人に戻します。**この一文を削らないでください**
- 「あとにする」を必ず残します

### A-2. 送信前のプレビュー

**Layout**: 戻る＋「送られる文面」→ 注記 → メールカード（件名／本文）→ 注記 → 固定領域（実名トグル → CTA → 戻る）

**メールカード**（`surface`、`border` 1px、角丸 20px、`overflow: hidden`）

```
├ 「件名」ラベル: envelope-head の地 / 下辺 破線 / 11.5px text-sub
├ 件名: 15px 「お手続きのご案内（Aida）」
├ 「本文」ラベル: envelope-head の地 / 上下 破線 / 11.5px text-sub
└ 本文: 13.5px / 行間 1.95
```

**送信される本文（確定文言）**

```
Aida は、お子さまに関する取り決めを、おふたりが直接やりとりせずに
進めるためのサービスです。

このご案内は、○○さまからのご依頼でお送りしています。ご参加の場合も、
直接メッセージをやりとりすることはありません。

お返事の期限はありません。
▸ 内容を確認する
```

**実名トグル**（固定領域・CTA の上、`surface` のカード）
「お名前を出す」／既定 **ON** ／ 説明「出さない場合は「ご関係の方からのご依頼で」となります。」
OFF のとき、本文 2 段落目の「○○さまからのご依頼で」が「ご関係の方からのご依頼で」に置き換わります。

**★ 実装ルール**

- **件名・本文に「離婚」「養育費」「調停」を出しません。** 相手の職場や家庭で見られる可能性があります
- **自由文の欄を作りません。** この経路で罵倒や脅迫を送れないようにするためです。画面上でも「自由に書き足せる欄もありません」と明示します
- **送信前に全文を必ず見せます。** 何が送られるか分からないまま送らせない
- 文面はプロダクト側で固定。編集不可であることを、制限ではなく保証として書きます

### A-3. 招待を受け取った側の最初の画面

相手にとっては「元配偶者から何か来た」という状態です。**勧誘の言葉を置きません。**

**Layout**: カピバラ（座り）76px 角丸タイル ＋ 見出し「Aida は、おふたりのあいだに立つためのサービスです。」20px 中央寄せ → 4 行のリスト → 注記 → 2 つの選択肢

**4 行のリスト**（`surface` のカード、各行 `padding: 15px 0`、14.5px、行間に `border-subtle`）

1. おふたりが直接やりとりすることには、なりません。
2. 書いた言葉は、お相手には届きません。合意できた事項だけが共有されます。
3. 連絡先も、入力した内容も、お相手には見えません。
4. 参加しない選択もできます。期限はありません。

**★ すべて「〜しません／〜見えません」の形にしています。** 機能の説明ではなく、安全の説明です。

**選択肢**: 「内容を見てみる」（`agree` の枠・`agree-bg`）／「いまは決めない」（`border-strong` の枠）／下に 12.5px `text-sub`
「お断りになった場合、その旨はお相手に伝わりません。」← **この一文は必須です**

### A-4. お相手が参加していない状態

**★ この期間を「待たされている」と感じさせません。**

- ヘッダーは「いまは、ひとりで進めています」。**「招待中」「未承諾」などの進行状態の語を使いません。** 相手の不作為ではなく、自分の現在地として書きます
- 「お相手が見たかどうかは、こちらでは分かりません。催促のご連絡はしません。期限もありません。」
- **催促ボタン・再送ボタン・経過日数・開封状況を出しません**（U-5）
- 準備モードへの導線（`bubble-ai` の地、破線の枠、カピバラ 40px）
  「待っているあいだに、できることがあります。」→「ひとりで準備する」
- ナレッジへの導線（準備期間中のみホームに置く例外。→ D 参照）

## B. 準備モード

**相手が参加しなくても、一人で使えるようにします。** 待合室ではなく、一人で準備する場所として設計しています。

### 通常の相談画面との差は 3 点だけ

| | 通常の相談 | 準備モード |
| --- | --- | --- |
| 地の色 | `bg` `#FDF8EF` | **`surface-2` `#F7EFE1`**（一段沈む） |
| 上部の帯 | なし | **鍵つきの帯が常設** |
| ③ 封書カード | 出る | **一度も出ない** |

**同じに見えると「相手に届いた」と誤解される危険があります。** この 3 点を必ず実装してください。逆に、これ以上の差（機能制限の表示、ロックアイコンの多用、警告色）は付けないでください。劣った状態に見せないためです。

### B-1. 準備モードの対話

**常設の帯**（`surface`、`#DCC7A6` の 1px、角丸 16px、`margin: 0 16px 12px`、`padding: 11px 14px`）

- 鍵アイコン 13px（線 `ai-text`）＋ 12px `text-sub-2`
- 「ここに書いたことは、まだ誰にも共有されていません」

**セパレータ**: 「準備 ／ 養育費のこと」11px `text-sub`、中央寄せ

**下書きの一覧カード**（会話の下に常設）

- 「下書きにしたこと」14px ／ 右に件数 12.5px `text-sub`
- 各行：6px の円（`ai`）＋ 13.5px `text-sub-2`

AI の応答例：「下書きにしておきますね。／お相手が参加されたとき、そのままお出しできます。」

### B-2. 下書きの一覧と、参加後の遷移

- 見出し「準備していること」22px ／ 「まだ誰にも共有されていません」13px `text-sub-2`
- 項目カードは取り決め画面と同じ形。ステータスチップは 2 種のみ
  - **下書き**: `#DCC7A6` の実線枠、`bubble-ai` の地、`ai-text` の文字
  - **書きかけ**: 破線枠、地なし、`text-sub` の文字
- 破線の注記「そろえる必要はありません。ひとつだけでも、お相手が参加されたときに出せます。」← **急かさないための一文**

**参加後の遷移**

- **通知もバッジも出しません。** 次に開いたときに、画面下部にカードが 1 枚増えているだけです
- カード（`surface`、`agree` の 1px 枠）：カピバラ（座り）34px ＋「お相手が参加されました。」
- 「準備された3件を、いつでもお出しできます。どれから始めるかは、ご自身で決められます。」
- **下書きは自動送信しません。** ユーザーが明示的に選んだものだけが提案になります

## ★ G. 危険を検知したときの窓口提示 — 未確定（3 案）

### 3 案に共通して守ること（どの案を採用しても必須）

1. **AI は何も判定しません。** 「あなたは危険な状態です」とは言いません
2. **説教しません。** 「そのような表現は不適切です」は禁止。**「何を書いてもいい」という約束が壊れます**
3. **検知したことを本人に告げません。** 「〜という記述がありましたので」とは書きません
4. **大きな警告を出しません。** モーダル・警告色・感嘆符・振動は使いません
5. **無視しても、次に同じものが出てきません。** 一度閉じたら繰り返しません
6. 窓口は公的なもの（DV 相談ナビ、法テラス、児童相談所など）

### 案 1 ／ 会話の末尾に、小さく置く

AI の発言の直後に、**吹き出しではないカード**を 1 枚だけ置きます（`surface`、`border` 1px、角丸 16px、左に 37px のインデント＝マークの幅ぶん）。

- 「お話しできる公的な窓口の一覧が、いつでもご覧いただけます。」13px `text-sub-2`
- 「窓口を見る ▸」13px `agree-text`

吹き出しにしないので「AI が言った」ことにはなりません。見落とされにくい一方、**検知に反応していることが伝わるため監視感がわずかに残ります。**

### 案 2 ／ 入力欄の脇に、常設する

**検知に一切反応しません。** 入力欄の上に、最初から最後まで同じ 1 行が置かれているだけです。

- 盾アイコン 13px（線 `text-sub`）＋「相談できる公的な窓口」12.5px `text-sub-2`

監視感はゼロ。ただし**常にあるものは見えなくなるため、いちばん必要なときに気づかれない危険があります。**

### 案 3 ／ 次に開いたとき、ホームに 1 枚

その場では何も起きません。**次に開いたときのホーム**に、他のカードと同じ形で 1 枚だけ増えます。

- 「お住まいの地域の相談窓口」15px
- 「どなたでもご利用いただけます。ご相談の内容が、こちらに伝わることはありません。」12.5px `text-sub-2`
- **本人に向けたものだと明示しません。**

時間差があるぶん、書いた直後の羞恥や反発を避けられます。

### 現時点の推奨

**案 2 ＋ 案 3 の併用。** 案 2 で常に手が届く場所を確保し、検知したときだけ案 3 で時間差の 1 枚を足す。会話の流れには一切触れません。

案 1 はその場で気づいてもらえる強さがある一方、「読まれている」感覚が最も強く出ます。緊急性の高い記述に限って使う、という切り分けはありえます。

> **未決の論点**: 検知の閾値をどこに置くか。誤検知したときにユーザーが受ける印象は、案 1 が最も大きく、案 3 が最も小さくなります。**実装前に決定してください。**

## D. ナレッジ

### 配置：タブは増やしません

6 つ目のタブを置くと、常時見えるところに「勉強するもの」が並びます。消耗している人にとって、開くたびに宿題が見えている状態は負担です。

入口は 3 か所に分散させます。

| # | 入口 | 備考 |
| --- | --- | --- |
| ① | **対話の中で AI が記事へ渡す** | **主経路。** 個別の助言ができない場面を、一般的な説明で引き取る |
| ② | 取り決めの各項目から、関係する記事へ | 養育費の項目 → 算定表の読み方、など |
| ③ | 設定の中に一覧の入口 | 「制度のこと」 |

準備モード（B）では例外的にホームにも置きます。相手を待つあいだは、読むことが数少ないできることだからです。

### AI と記事の役割分担

```
【個別の助言】AIが「あなたはこうすべき」と言う   → できない（法規制）
【一般的な情報】ナレッジで制度を説明する        → できる
【対話】AIは「一般的な説明はこちら」と誘導する   → できる
```

### D-1. 一覧

- 見出し「制度のこと」22px ／ 「一般的な説明です。個別のご事情への助言ではありません。」12.5px `text-sub-2`
- 分類見出し 11.5px `text-sub` `letter-spacing: .08em`
- 項目リスト（`surface` のカード、各行 `padding: 13px 0`、14.5px、行間に `border-subtle`）

| 分類 | 項目 |
| --- | --- |
| 手続き | 協議離婚とは／公正証書とは／公証役場の使い方／調停とは |
| お金 | 養育費の決め方／算定表の読み方／特別費用とは |
| 制度 | 2026年4月の改正で変わったこと／法定養育費／先取特権 |
| 用語 | 債務名義・監護者・基準日 ほか |

**★ 記事の要約も、所要時間も、既読の印も出しません。** 読み進めさせるための仕掛けを置かないことで、「宿題」に見えないようにしています。

### D-2. 記事

- 冒頭に**常時表示の注記**（`surface-2`、`border` 1px、角丸 16px、12px `text-sub-2`）
  「一般的な説明です。個別のご事情への助言ではありません。実際の取り扱いは、ご事情によって変わる可能性があります。」
  **スクロールしても消えません。**
- 本文 15px、行間 2.1
- **文体は断定を避けます。**「〜とされています」「〜の可能性があります」
- **監修枠**（`surface` のカード）：「監修／弁護士 ○○ ○○（第二東京弁護士会）／2026年8月 確認」
  弁護士監修を明示できない期間は、このカードを出しません（空欄で出さない）
- 末尾に相談への導線（`bubble-ai` の地、カピバラ 30px ＋「このことについて相談する」）
  **記事の途中に差し込んで読書を中断させません。**

### ★ 年収の扱い

**入力した精密な年収は、相手には見えません。相手に伝わるのは算定表の「帯」だけです。**

```
入力: 4,380,000円             ← 相手には見えない
   ↓
相手に見える: 「400〜425万円」  ← 算定表のセルが特定できる粒度
```

**この変換を、文だけでなく図で見せてください。** 年収の入力は心理的な抵抗が大きい項目です。文だけでは信じにくい種類の約束なので、実際の値の変換を並べて示します。

**変換カード**（`bubble-ai` の地、`#DCC7A6` の破線枠、角丸 20px）

- カピバラ 28px ＋「この金額そのものは、お相手には見えません。」14.5px
- 内側に `surface` のカード（角丸 16px）：左に「入力した金額／4,380,000円」、中央に「→」、右に「お相手に見えるのは／400〜425万円」（`agree-text`）
- 「算定表のどのマスにあたるか、という幅だけが伝わります。正確に入れていただくほど、目安が実情に近づきます。」12.5px `text-sub-2`

第 1 弾の「ここに書いたことは、お相手には届きません」と同じ役割の表示です。

## F. 設定（退会を含む）

**Layout**: 見出し「設定」→ 呼び方カード → グループ 1 → グループ 2 → 退会カード → タブバー

1. **お相手の呼び方**（最上部・重要機能）
2. **通知に本文を出す**（トグル・**既定 OFF**）／通知の時間帯（9:00–21:00）／制度のこと
3. 相談できる公的な窓口 ／ アカウント
4. **ご利用をやめたいとき**

### ★ 退会

**単純な「退会する」ボタンにはできません。**

- 合意した内容は法的文書の基礎であり、一方の意思だけで消えてよいものではない可能性があります
- 相手が残っている場合の扱いがあります
- **削除範囲は検討中**（弁護士に確認中）。実装時に最新の方針を確認してください

**設計**

- 見出し「ご利用をやめたいとき」14.5px（**「退会」という語を見出しに使いません**）
- 説明「取り決めた内容は、法的な文書のもとになっている場合があります。そのため、お手続きの前に、何がどうなるかをご説明します。」
- 「やめたいと伝える ▸」13.5px `agree-text`

**★ 即時削除のボタンではありません。** 何が起きるかを説明したうえで手続きに進む形です。赤字にも、警告アイコンにも、破壊的操作の色にもしません。設定の最下部に置きますが、隠してもいません。

## E. ログイン

**Layout**: 中央寄せ。カピバラ 76px 角丸タイル → ワードマーク「Aida」24px `letter-spacing: .3em` → メールアドレス → パスワード → 「はじめる」 → 「はじめて使う」「パスワードを忘れた」

**★ 実装ルール**

- 起動画面（第 1 弾）とほぼ同じ見た目にし、そこに入力欄が生えてくる形にします
- **サービス説明も、キャッチコピーも、利用規約の長文も置きません。** 人に覗かれても、何のアプリか分からない状態を保ちます
- 画面下部に 11.5px `text-sub` で「この画面には、用途が分かる説明を出していません。」（これは設計意図の注記なので、実装時は不要です）
- パスワード再設定のメールも、A-2 と同じ規約に従います（件名から用途が推測されないこと）
