## 1. 目的

> **LLMが呼べて、すべての呼び出しがログに記録される状態を作る。**

### 1.1 このスライスは「唯一の入口」を作る作業である

S2 で `ContextBuilder` を作り、**相手の原文へ到達する経路を型レベルで消した。**
しかし LLM SDK を直接叩けば、その努力は迂回できる。

```
❌ 各機能が openai クライアントを直接持つ
     ContextBuilder を通さない経路ができる。
     コストも記録されない。CT-1〜CT-4 が計測できなくなる。

✅ LlmRouter を唯一の入口にする
     C1 の防御とコスト計測が、同じ1点に集まる。
```

### 1.2 ★ S2 と同じ構造の問題である

| S2 | S3 |
| --- | --- |
| `buildRelayContext` に `partyId` を**書けなく**した | LLM SDK を Router 以外から**呼べなく**する |
| シグネチャ検証テスト | **静的検査テスト** |

**「気をつける」ではなく「書けない」状態にする。**同じ手を使う。

## 5. 設計上の要点

### 5.1 ログに何を残し、何を残さないか

| 残す | 残さない |
| --- | --- |
| `purpose` / `tier` / モデルID | **プロンプト本文** |
| `inputTokens` / `outputTokens` | **応答本文** |
| `costJpy` / 所要時間 | **`caseId` 以外の当事者情報** |

> **トークン数は残す。**CT-4 のために必要であり、原文の復元はできない。

### 5.2 単価をハードコードしない

`/api/pricing` はレシオ方式で返す。

```
入力単価 = model_ratio × 2
出力単価 = 入力単価 × completion_ratio
```

**プロバイダの値下げが自動で反映される。**取得失敗時は最後に成功した値を使う。

### 5.3 M-2 を設定の検査で担保する

```
推論モデル（gpt-5 系・o 系）を指定 かつ reasoning_effort 未指定
  → 起動時に落とす
```

**実測で原価20倍を確認している。**コメントで注意を促すだけでは不十分である。
