## ★ 実機で欠陥を検出した

最初に生成された条項：

```
面会交流はMONTHLY_1とし、時間は[object Object]、受け渡し場所は○○駅とする。
```

**コード値がそのまま出て、オブジェクトが文字列化された。**
空欄と同じくらい危険である。**これが公証役場に持ち込まれる。**

### なぜ起きたか

`formatValue` に「定義の無いキーは文字列化する」という逃げ道があった。
**文字列化してよいのは、当事者が自由入力した値だけ**である。

### 直した内容

| # | 対処 |
| --- | --- |
| 1 | **オブジェクト・配列・真偽値は `null`**（条項に埋め込めない） |
| 2 | **表記の定義が無いコード値は `null`**（`^[A-Z][A-Z0-9_]*$` を通さない） |
| 3 | `frequency` / `dayOfWeek` の表記を追加 |
| 4 | **`timeRange` をオブジェクトから文字列に変更**（スキーマ v2） |
| 5 | **G-3b をテストに追加**（enum のすべての値に表記があること） |

### G-3 だけでは足りなかった

G-3 は「プレースホルダ ⊆ スキーマのキー」を検査する。
**しかしキーが揃っていても、値が翻訳できなければ条項は壊れる。**

G-3b として次を追加した。

- 条項に現れる enum の**すべての値**に表記があること
- 条項に現れるキーが**オブジェクト型でない**こと

## ★ 同じ論点に複数の合意があると結果が不定になる

S2 の seed が作った `ai_dev_1` が `VISITATION` と重複しており、
どちらが文書に入るかが Map の構築順に依存していた。

→ **合意時刻の昇順で返し、最新の合意が採用される**ようにした。
（改訂を重ねた場合の挙動としても、これが正しい）

第1条（養育費）
甲は乙に対し、丙の養育費として、30,000円を毎月25日限り、乙の指定する方法により支払う。
前項の支払は、丙が20歳に達する月まで継続する。

第2条（面会交流）
乙は甲に対し、甲が丙と面会交流することを認める。
面会交流は月1回とし、時間は10時00分から17時00分まで、受け渡し場所は○○駅の改札前とする。
面会交流の具体的な日程は、甲乙間で事前に協議して定める。

```
{"ok": false, "reason": "INCOMPLETE", "missing": ["payDay", "until"]}

```
