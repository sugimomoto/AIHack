## 3. 審査基準（Judging Criteria）

**各項目 1〜5点 × 8項目 = 40点満点**

| # | 項目 | 想定される評価の観点 |
| --- | --- | --- |
| 1 | **課題の実在性** | 実在するユーザーの実在する痛みか。誰がいくら困っているか |
| 2 | **ビジネス成立性** | 課金モデル、市場規模、継続利用の見込み |
| 3 | **完成度・デモの説得力** | 動くか。デモで納得させられるか |
| 4 | **AIである必然性** | 「AIを使わないと解けない」か。従来手法で足りるなら減点 |
| 5 | **技術的な作り込み** | 実装の深さ、アーキテクチャ、エンジニアリング品質 |
| 6 | **LLMコスト** | 1リクエストあたりの単価、モデル選択の妥当性、コスト最適化 |
| 7 | **セキュリティ** | 認証・認可、プロンプトインジェクション対策、秘匿情報の扱い |
| 8 | **次世代性・独創性** | 既存プロダクトの焼き直しでないか |

### 審査基準の特徴

- **8項目が均等配点（各5点）**＝「尖った1点突破」より**全項目で穴を作らない**方が有利な設計。
- **LLMコスト・セキュリティが独立項目**として立っているのは一般的なハッカソンでは珍しい。
  → コスト試算表・セキュリティ設計の説明を成果物に明示的に含めるだけで差がつきやすい。
- **AIである必然性**が独立項目 → 「AIをつけた便利ツール」ではなく「AIでしか成立しない体験」を狙う必要がある。

## 4. 審査の流れ

```
┌──────────────────┐        ┌──────────────────┐
│  課題提出        │        │  最終プレゼン    │
│  ブース審査      │  ───▶  │  4分プレゼン     │
│                  │        │  ＋3分 質疑応答  │
│  【全チームが対象】│        │  【上位8チーム】  │
└──────────────────┘        └──────────────────┘
```

1. **課題提出 → ブース審査**（全チーム対象）
2. **最終プレゼン**（上位8チームのみ）
   - プレゼン **4分**
   - 質疑応答 **3分**

> 質疑応答3分は審査員4名によるもの。**LLMコスト・セキュリティ・ビジネスモデルへの突っ込みを想定した準備が必要。**

## 9. OrcaRouter について

Day1スライドには「**How to use OrcaRouter ?**」というセクション見出しページのみが存在し、
具体的な利用方法・API仕様・クレジット等の記載は**スライド本体にはない**（キックオフ動画または Discord で別途案内と推測）。

**確認が必要な事項:**
- OrcaRouter の利用は**必須か推奨か**
- API キーの配布方法、利用可能クレジット/枠
- 利用可能なモデル一覧と価格（→ 審査項目6「LLMコスト」に直結）
- レート制限、SLA

> OrcaRouter は名称から **LLM ルーター（複数モデルへのプロキシ／振り分け）** と推測される。
> 事実であれば「用途に応じたモデル振り分けによるコスト最適化」がそのまま審査項目6のアピール材料になる。
