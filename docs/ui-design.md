## 1. 変わらない前提：ユーザーの心理状態

**これを外すと実装全体が失敗する。**

このアプリを開く人は、人生でもっとも消耗している時期にいる。相手への強い怒り、あるいは恐怖を抱えており、**相手の名前が画面に出るだけで動揺する**。

国の調査では、養育費や面会交流の取り決めをしない理由の**第1位が「相手と関わりたくない」**だった。

> **「相手の存在を感じさせないこと」が、このプロダクトの機能そのものである。**

| | |
| --- | --- |
| ✅ 目指すもの | 静けさ・安全・守られている感じ |
| ❌ 避けるもの | 明るさ・元気・励まし・対立の可視化・急かし |

**判断基準**：*深夜に泣きながら開いても、ふざけて見えないこと。*

## 2. デザイン原則（確定）

| # | 原則 | 実装への現れ |
| --- | --- | --- |
| **U-1** | **相手の存在を最小化する** | 相手のアイコン・実名を出さない。呼称は「**お相手**」 |
| **U-2** | **二人を色で対立させない** | **当事者を指す色が存在しない。**彩度を持つのは AI と合意の2色だけ |
| **U-3** | **AIキャラクターは「愚痴を投げられる相手」** | **カピバラ**。表情差分・リアクションを作らない（→ §4） |
| **U-4** | **「合意」が主役** | 進捗バーと「8つのうち2つが決まりました」。祝わない |
| **U-5** | **急かさない** | 未読バッジ・赤ドット・既読・入力中表示を実装しない |

### 2.1 確定した色の方針

| # | ルール |
| --- | --- |
| 1 | **赤を使わない。**逸脱も入金の未確認も、責める色ではなくくすんだクレイで静かに示す |
| 2 | **純黒・純白を使わない。**最も濃い文字色は `#3A342E`、最も明るい面は `#FFFCF5` |
| 3 | **図版用と文字用の値を分ける。**`#C08F3C` 等を `color:` に使うとコントラスト比を割る。テキストは `-text` 側を使う |

配色・タイポグラフィ・余白・角丸・モーションの**確定値は [design/README-v1.md](../design/README-v1.md) の Design Tokens を参照**。第2弾もこれを踏襲している。

## 3. ★ 3つの設計課題と、その解

デザイン依頼時に提示した3つの課題は、いずれも解けている。

### 課題1｜対話画面の3種別の描き分け

**「相手の生の言葉が届いていない」ことを、説明文なしで理解させる。**

| # | 種類 | 解 |
| --- | --- | --- |
| ① | 自分の発言 | 右寄せの吹き出し（78%幅）。直下に **「ここに書いたことは、お相手には届きません」** |
| ② | AI自身の発言 | カピバラマーク ＋ 左の吹き出し（82%幅） |
| ③ | **AIによる取次ぎ** | **吹き出しではない。画面幅いっぱいの「封書カード」** |

**③が①と別種に見える理由**——5つの属性が同時に反転する。

| | ① 自分の発言 | ③ 取次ぎ |
| --- | --- | --- |
| 寄せ | 右 | 幅いっぱい |
| 形 | 吹き出し | **見出し付きカード** |
| 幅 | 78% | 100% |
| 面 | 塗りのみ | **枠線＋破線の仕切り** |
| 署名 | なし | **「AIが要約しました」** |

> **文字を読む前に別種と分かる。このうち1つでも崩すと課題が解けなくなる。**

封書カードは3つの層を持つ。

```
┌─────────────────────────────────────┐
│ ✉ お相手からのご相談   AIが要約しました │ ← ヘッダ帯
├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤ ← 破線
│ 土曜の日程について、別案のご相談が    │
│ 来ています。                        │
│ 背景として、お相手は現在求職中との    │ ← 伝聞形式
│ ことです。                          │
├─────────────────────────────────────┤
│ お相手が書いた言葉そのものは          │ ← フッタ
│ 含まれていません。                    │
└─────────────────────────────────────┘
```

**①直下の「ここに書いたことは、お相手には届きません」と、③フッタの「お相手が書いた言葉そのものは含まれていません。」は、プロダクトの約束を担う。削らず、コントラストを落とさない。**

### 課題2｜合意ステータス6種を色に頼らず描き分ける

**アイコン ＋ 枠線のスタイル ＋ 色**の3信号で区別する。

| 状態 | アイコン | 枠線 | 色 |
| --- | --- | --- | --- |
| 合意済 | ✓ | 実線 | 合意（緑） |
| 係争中 | △ | 実線 | 注意（クレイ） |
| 未着手 | 点線の円 | **破線** | 無効 |

色を落としても、アイコンと枠線で判別できる。

### 課題3｜「今回だけ？ 今後も？」の重さの違い

**2つの選択肢を、視覚的な重さで差別化している。**

| | 今回だけ変更する | 今後も変更する |
| --- | --- | --- |
| 見た目 | 沈んだ面のみ。軽い | **枠線つきカード ＋ アイコン ＋ 合意色** |
| 補足 | 「9月13日の1回だけ。取り決めは変わりません。」 | 「**取り決めそのものを書き換えます。**お相手の同意が必要です」 |
| 追加情報 | なし | **変更前／変更後の差分を表示** |
| 確認 | 即時 | **確定前に条文をもう一度提示** |

さらに「**あとで決めることもできます**」という逃げ道を用意している。**急かさない**（U-5）の徹底。

## 4. AIキャラクター：カピバラ

### 採用理由

> 争わない。他の動物に背中を貸す。そして**表情筋が動かない**。
> **「無表情である」ことに説明が要らない**のが、この題材で選ぶ最大の利点。

### 実装ルール（重要）

| # | ルール | 理由 |
| --- | --- | --- |
| 1 | **表情差分もポーズ差分も作らない** | ユーザーの感情に反応して表情が変わると「**見抜かれた**」という監視感が生まれる。相手の相談を取り次ぐ場面で中立に見えなくなる |
| 2 | ポーズは2種のみ（伏せ／座り） | 伏せ＝通常の対話、座り＝相談の開始と空の状態 |
| 3 | **動きは3.2秒周期の呼吸だけ。**リアクションを実装しない | — |
| 4 | **温泉・ゆず・「まったり」を使わない** | 癒やしキャラとして消費されると、当事者の切実さと釣り合わない |

素材は `public/character/capybara.png`（伏せ）と `capybara-sit.png`（座り）。

> **1が最も重要。**「AIが感情を読み取って反応する」のは一般には良い体験だが、このプロダクトでは**監視されている感覚**に転ぶ。

## 5.1 第2弾で追加された画面（2026-08-11 納品）

| # | 画面 | 対応機能 | 状態 |
| --- | --- | --- | --- |
| A-1〜A-4 | **招待**（作成・メール文面プレビュー・受け取り側・待機中） | F15 | 確定 |
| B-1・B-2 | **準備モード**（対話・下書き一覧・参加後の遷移） | F16 | 確定 |
| C | 前提情報の登録（**年収の帯変換**） | F17 | 確定 |
| D-1・D-2 | ナレッジ（一覧・記事） | F18 | 確定 |
| F | 設定（**退会を含む**） | F20 | 確定 |
| E | ログイン | F14 | 確定 |
| **G** | **危険検知時の窓口提示** | F19 | ✅ **案2＋案3 で確定**（2026-08-11 → §5.2） |

### 特筆すべき解

**① 年収の変換を「図」で見せる**

> 年収の入力は心理的な抵抗が大きい項目です。**文だけでは信じにくい種類の約束**なので、実際の値の変換を並べて示します。

```
入力した金額        →     お相手に見えるのは
4,380,000円               425〜450万円
```

第1弾の「ここに書いたことは、お相手には届きません」と**同じ役割の表示**として設計されている。

> ⚠️ **納品物の例には帯の誤りがある。**`design/README-v2.md` は 4,380,000円 → 「400〜425万円」としているが、
> 438万円は25万円刻みでは **425〜450万円** の帯に入る。**実装は正しい帯を用いる**（テストで検出済み）。
> 画面に出す例示値も実装側で整合させること。

**② 退会は「退会」と呼ばない**

見出しは**「ご利用をやめたいとき」**。ボタンは「やめたいと伝える」。

> 即時削除のボタンではない。**赤字にも、警告アイコンにも、破壊的操作の色にもしない。**設定の最下部に置くが、隠してもいない。

合意が法的文書の基礎である以上、単純な削除ボタンにはできないという制約を、**UIの語彙で表現**している。

**③ ナレッジはタブを増やさない**

5タブが埋まっているという制約に対し、**タブを増やさない**解を出している。詳細は README-v2 を参照。

### 5.2 ✅ 危険検知時の窓口提示は「案2＋案3の併用」（2026-08-11 決定）

3案が提示され、**併用を採用する。**

| 採用 | 内容 |
| --- | --- |
| **案2** | 入力欄の脇に**常設**。盾アイコン ＋「相談できる公的な窓口」。**検知に一切反応しない** |
| **案3** | 検知したときのみ、**次に開いたときのホーム**に1枚。他のカードと同じ形。**本人に向けたものだと明示しない** |
| ~~案1~~ | 会話の末尾にカードを置く。**採用しない** |

**判断の理由**

| # | 理由 |
| --- | --- |
| 1 | **案1は「読まれている」感覚が最も強く出る。**誤検知したとき、監視されているという体験が残る |
| 2 | **案3は時間差があるため、誤検知の印象が最も小さい。**書いた直後の羞恥や反発も避けられる |
| 3 | 案2で**常に手が届く場所**を確保しておけば、案3が届かなくても経路が残る |
| 4 | **会話の流れに一切触れない**——これが決定的。C1の「何を書いてもいい」を守れる |

**どちらの案でも守る原則（デザイナー提示）**

| # | 原則 |
| --- | --- |
| 1 | **AIは何も判定しない。**「あなたは危険な状態です」と言わない |
| 2 | **説教しない。**「そのような表現は不適切です」は禁止 |
| 3 | **検知したことを本人に告げない。**「〜という記述がありましたので」と書かない |
| 4 | 大きな警告を出さない（モーダル・警告色・感嘆符・振動を使わない） |
| 5 | **無視しても、次に同じものが出てこない。**一度閉じたら繰り返さない |
| 6 | 窓口は公的なものに限る（DV相談ナビ、法テラス、児童相談所など） |

> **3が最も重要。**検知を本人に告げた時点で、それは監視の通告になる。
> 気づいていることを、気づかせずに支える——それがこの画面の要件である。

**残る未決**：**検知の閾値**。誤検知したときの影響は案3で最小化されるが、閾値そのものは S17 で決める。

## 6. 当初仕様との差分と判断

| # | 項目 | 当初 | 納品 | 判断 |
| --- | --- | --- | --- | --- |
| 1 | ダークモード | 必須 | **スコープ外**（単一テーマ） | ✅ **対象外と決定**（→ §6.1） |
| 2 | ボトムタブ | 4つ（対話／合意／予定／設定） | **5つ**（ホーム追加） | ✅ **採用**（→ §6.2） |
| 3 | キャラクター | 方向性のみ指定 | **カピバラに確定** | ✅ 採用 |
| 4 | 3端末デモ | 依頼に含めた | 個別画面のみ | 実装側で組む（S12） |
| 5 | 4画面の精度 | — | 「これから」「逸脱の詳細」「設定」「公正証書の原案」は**ラフ** | 実装時に他画面のスケールへ合わせる |

### 6.1 ✅ ダークモードは対象外（2026-08-11 決定）

当初は「夜間の利用が想定される」「眩しくないこと」を根拠に**必須**としていたが、**対象外とする。**

**判断の理由**

| # | 理由 |
| --- | --- |
| 1 | **当初の懸念には単一テーマで応えられている。**背景 `#FDF8EF` は純白より十分に低輝度であり、夜間に眩しくない |
| 2 | **単純な反転では作れない。**「彩度を持つのは AI と合意の2色だけ」「赤を使わない」「当事者を色分けしない」という色の役割分担を、ダーク側で作り直す必要がある |
| 3 | 得られる価値に対してコストが見合わない |

**反映済み**：product-requirements.md NFR-05 ／ architecture.md §2.2.1 ／ development-guidelines.md §4.1

> **将来対応する場合は、納品パレットからの派生ではなく、役割つきパレットを再設計する。**明度の反転だけでは §2.1 のルールを維持できない。

### 6.2 ホームタブの追加について

当初は4タブ（対話／合意／予定／設定）を想定していたが、**ホームが追加されて5タブになった。**

これは妥当だと判断する。理由：

- **アプリを開いた直後に「今日は何があるか」だけを見て閉じられる。**毎回チャット画面に着地すると、心理的負担が高い
- 「お返事は、急ぎません。」という文言が置かれており、**U-5（急かさない）を最初の画面で体現している**
- 取次ぎの件数を表示するが、**バッジではなくカードとして静かに提示**している

> ホーム画面の存在自体が「開いても何もしなくていい」という許可になっている。
