## 1. 目的

> **合意が公正証書の原案になる。**

### 1.1 ★ ここは LLM を一切使わない

条項は**ひな形のプレースホルダ置換**だけで作る。

```
❌ LLMに条項を書かせる
     弁護士法72条。離婚協議には事件性が認められるため、
     法律事務の取扱いにあたるおそれがある。
     そして、文言が毎回変わる法的文書に意味はない。

✅ ひな形の置換だけで作る
     出力が決定的になる。差分が追える。責任の所在が明確になる。
```

### 1.2 ★ 置換に失敗した文書を世に出さない

置換漏れは `{{monthlyAmount}}` のまま残る。

**空欄のある法的文書は、空欄のない誤りより危険である。**
当事者がそれを公証役場に持ち込む。

## 2. スコープ

### 2.1 実装する

| # | 項目 |
| --- | --- |
| 1 | `DocumentBuilder`（**LLM不使用・純粋な文字列処理**） |
| 2 | **★未置換の検出**（残っていたら文書を返さない） |
| 3 | 値の書式化（金額・支払日・終期の表記） |
| 4 | 条項の選別と並び |
| 5 | 原案画面（**公証人確認の注意書きを常時表示**） |

### 2.2 実装しない

| 除外 | 理由 |
| --- | --- |
| PDF 出力 | 画面表示とコピーまで |
| 公証役場との連携 | 範囲外 |
| 条項の自由編集 | **意図的に作らない。**編集できると、ひな形である意味が消える |

---

## 3. ★ テストを先に書く対象

| 対象 | 理由 |
| --- | --- |
| **未置換が残った文書を返さないこと** | **空欄のある法的文書を世に出さない** |
| **合意していない論点が文書に入らないこと** | `AGREED` 以外を含めると、決まっていないことが条項になる |
| **注意書きが外せないこと** | 「原案である」ことを消せると、確定文書と誤認される |
| G-3（プレースホルダ ⊆ スキーマのキー） | 既存（S1） |

## 5. 設計上の要点

### 5.1 失敗を握り潰さない

置換に失敗したら**例外にする。**
「その条項だけ落とす」も選ばない。**合意した内容が文書から消える**ほうが危険である。

### 5.2 注意書きは組み立て側が持つ

呼び出し側に付けさせない。**算定表の注記と同じ考え方である。**
