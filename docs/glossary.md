## 1. 法律・実務のドメイン用語

出典：[legal-market-research.md](legal-market-research.md)（公的一次資料）／`.meetings/domain-reference-divorce.md`（Git管理対象外）

### 1.1 離婚の手続き

| 用語 | 定義 |
| --- | --- |
| **協議離婚** | 夫婦の合意のみで成立する離婚。裁判所を介さない。**全離婚の約87.5%を占め、本プロダクトの主戦場** |
| **調停離婚** | 家庭裁判所の調停により成立する離婚 |
| **審判離婚** | 家庭裁判所の審判により成立する離婚 |
| **裁判離婚** | 訴訟の判決により成立する離婚 |
| **その他の離婚** | 統計上、調停離婚・審判離婚・裁判離婚の総称 |
| **客観的離婚原因** | 相手方の暴力、浮気等。裁判離婚が認められる可能性を高める事由 |

### 1.2 離婚時に決める事項

| 用語 | 定義 | 本プロダクトでの扱い |
| --- | --- | --- |
| **親権** | 未成年の子に対する権利義務。2026年4月より**共同親権**の選択が可能 | `PARENTAL_AUTHORITY` |
| **単独親権** | 父母の一方のみが親権者となる形態。**DV等のおそれがある場合は制度上こちらになる** | `custodyType: SOLE` |
| **共同親権** | 父母双方が親権者となる形態。**重要事項はそのつど双方の合意が必要**（民法824の2） | `custodyType: JOINT` |
| **監護者** | 実際に子を養育する者。親権者と異なる場合がある | — |
| **養育費** | 子の監護に要する費用。算定表を基準に決める | `CHILD_SUPPORT` |
| **面会交流（親子交流）** | 別居親と子が交流すること。**離婚前の別居時も対象** | `VISITATION` |
| **財産分与** | 婚姻後に形成された共有財産を分けること。請求期間は**2年→5年に伸長**（民法768） | `PROPERTY_DIVISION` |
| **慰謝料** | 精神的損害に対する賠償 | `CONSOLATION_MONEY` |
| **年金分割** | 婚姻期間中の厚生年金の払込保険料を分割する制度。合意により**最大0.5** | `PENSION_SPLIT` |
| **婚姻費用** | 夫婦が分担義務を負う生活費。**別居中（離婚前）も請求可能** | `MARITAL_EXPENSES` |
| **基準日** | 財産分与における財産評価の時点。**別居日**を採る | `Case.separationDate` |

### 1.3 履行確保に関する用語（★制度の用語。アプリが実装しているという意味ではない）

| 用語 | 定義 |
| --- | --- |
| **算定表** | 養育費・婚姻費用の金額算定に用いられる基準表。裁判所が公表 |
| **公正証書** | 公証人が作成する公文書 |
| **強制執行認諾文言** | 「強制執行を受けても異議がない」旨の条項。これを付した公正証書は**債務名義**になる |
| **債務名義** | 強制執行の根拠となる文書（確定判決、調停調書、強制執行認諾文言付き公正証書など） |
| **法定養育費** | 取決めがなくても請求できる養育費。**月額2万円 × 子の数**（民法766の3、2026年4月施行） |
| **先取特権** | 特定の債権に与えられる優先権。**養育費債権には月額8万円 × 子の数を上限に付与され、債務名義がなくても差押えが可能**（民法308の2、2026年4月施行）。<br>★アプリの画面では扱わない。**制度の説明としてナレッジ記事に残る** |
| **公証人** | 公正証書を作成する公務員。**本プロダクトは原案を作るのみで、公正証書は公証人が作成する** |
| **非弁行為** | 弁護士以外の者が報酬を得て法律事務を扱うこと（弁護士法72条）。**本プロダクトの設計制約の根拠** |
| **事件性** | 弁護士法72条の要件の一つ。**離婚協議には事件性が認められる** |

## 2. プロダクト固有の用語

### 2.1 中核コンセプト

| 用語 | 定義 |
| --- | --- |
| **転送しない（C1）** | 一方の入力した原文が、他方に届かないこと。本プロダクトを定義する最重要の性質 |
| **吸収** | 感情的な入力を**ブロックせず受け止め、相手に転送しない**こと。先行サービスの「ブロック」と対比される |
| **ブロック** | 感情的な入力の送信を拒否すること。**本プロダクトが採らない方式** |
| **取次ぎ** | AIが一方の提案を、中立な表現に書き直して他方に提示すること |
| **越境** | データが一方の当事者から他方へ渡ること。**越境できるものは限定される**（INV-3） |

### 2.2 やりとりの3層

| 用語 | 定義 | エンティティ |
| --- | --- | --- |
| **L1：合意** | 離婚時に一度決める取り決め。8論点。**公正証書の対象** | `AgreementItem` |
| **L2：調整** | 運用中に繰り返し発生する、合意が必要なやりとり | `Adjustment` |
| **L3：連絡** | 合意を要さない一方向の伝達 | `Notification` |

### 2.3 合意に関する用語

| 用語 | 定義 | エンティティ |
| --- | --- | --- |
| **論点** | 合意すべき項目。8つ存在し、**コードで固定される** | `AgreementTopic` |
| **合意項目** | 論点ごとの合意の状態と内容 | `AgreementItem` |
| **提案** | 合意に至る前の、一方からの申し出 | `Proposal` |
| **仮案** | 一方が作り、まだ相手に渡していない案。★**下書きのあいだ、相手には見えない** | `Proposal`（`sharedAt` が null） |
| **お渡し** | 仮案を相手に見えるようにすること。★**「見ていない状態」には戻せない** | `Proposal.sharedAt` |
| **取り下げ** | 渡した仮案を引っ込めること。★**取り下げたことは相手に見える** | `Proposal.withdrawnAt` |
| **了承** | 相手の仮案を受け入れること。**内容はサーバが複製する**ので必ず一致する | `Consent = ACCEPTED` |
| ~~**調停案**~~ | 🚫 **やめた。**AI が双方の差を説明していたが、**AI が金額に触れる経路を残さない**（P3） | — |
| **改訂** | 合意内容の**恒久的な**変更。履歴として追記される | `AgreementRevision` |
| **一時的例外** | 合意を変えずに、特定の回だけ内容を変えること | `Adjustment.effect = ONE_TIME` |
| **恒久的変更** | 合意そのものを変えること。改訂を伴う | `Adjustment.effect = PERMANENT` |
| **約束** | 相談で了承された、日付のある個別の取り決め。**公正証書には載らない** | `Arrangement` |
| **控え** | 個別の相談（ADJUSTMENT）の帰結。「決まったこと」に並ぶ | `Adjustment` |
| **おふたりで決めたこと** | 臨時費用の分け方など、**ずっと続くルール。**<br>★**公正証書には入らない。**当事者が自分で決め、自分で直す。<br>片方だけでは決まらない | `Rule` |

### 🚫 やめた用語（履行の記録）

| 用語 | 扱い |
| --- | --- |
| ~~**義務**~~ `Obligation` | 🚫 生成しない |
| ~~**履行**~~ `Fulfillment` | 🚫 記録しない |
| ~~**逸脱**~~ `Deviation` | 🚫 検知しない |

> **手間で押されない。**押されないと「確認できていません」と出て、
> **実際は払っているのに疑いが立つ。**
>
> **記録率が低い台帳は、正しい信号より誤った信号を多く出す。**

★ コードは残してある。呼ばないだけである（Issue #7 で作り直す土台）。
★ かつての規律「**『逸脱』を『違反』と呼ばない**」は、語彙の方針としては生きている
（→ development-guidelines.md §4.5）。

### 2.4 相談・マスタに関する用語

| 用語 | 定義 | エンティティ |
| --- | --- | --- |
| **相談** | 対話の単位。シナリオを選んで開始し、帰結が3層のいずれかになる | `Consultation` |
| **分類** | 相談トピックの大分類（「お金のこと」「子どもと会うこと」等） | `TopicCategory` |
| **シナリオ** | 相談の具体的な型（「今回の日程を変更したい」等）。**マスタとして追加できる** | `Scenario` |
| **種別** | シナリオが FORMAL / ADJUSTMENT / NOTIFICATION のいずれかであること | `Scenario.kind` |
| **payload** | 合意・提案・調整の構造化された内容。**条項ひな形のプレースホルダと1対1で対応する** | — |
| **payloadスキーマ** | payload の形を定義する JSON Schema。**DBで版管理される** | `PayloadSchema` |
| **条項ひな形** | 公正証書の条項の雛形。プレースホルダを持つ | `ClauseTemplate` |
| **事情** | AIが原文から抽出・再構成した背景事実。**原文ではない** | `Proposal.context` |

### 2.5 ★ 画面の名前

| 画面 | 意味 | ★注意 |
| --- | --- | --- |
| **相談** | AI が仲介する対話。**取り決めは動かさない** | 「チャット」と呼ばない |
| **取り決め** | **公正証書に入れる内容。**ここでだけ合意が成立する | 「合意」は成立を前提とした語なので、係争中の項目には使わない |
| **決まったこと** | 相談で決まったことの控え | ★旧「これから」。**中身が「これから起きること」から<br>「決まったことの記録」に変わったため改名。**<br>「これから」のままだと**予定表だと思われる** |

> ★ **「取り決め」と「決まったこと」はタブが隣り合う。**
> 公正証書に入るのは**取り決め**のほうであることを、画面にも書く。

### 2.6 技術用語

| 用語 | 定義 |
| --- | --- |
| **コンテキストビルダー** | LLMに渡す情報を許可リスト方式で組み立てる関数群。**C1の実装本体** |
| **階層（Tier）** | LLMモデルの区分。SMALL / MEDIUM / LARGE |
| **不変条件（INV）** | 破られてはならない性質。自動テストで検証する |
| **ホワイトリスト** | 事情の抽出において、抽出してよいカテゴリの限定列挙 |
| **伝聞形式** | 「〜とのことです」という表現。**AIが事実認定しないための規約** |

## 3. ユーザー・ロールの用語

| 用語 | 定義 | コード上 |
| --- | --- | --- |
| **監護親** | 子と同居し養育している親 | `CUSTODIAL` |

## 4. 使ってはいけない語

| 使わない語 | 代わりに使う語 | 理由 |
| --- | --- | --- |
| 違反 | **逸脱** | 責める語彙を避ける（★逸脱の検知自体はやめた。語彙の方針としては生きている） |
| 未払い | — | ★**そもそも書かない。**入金を観測できないため、確認できていないという表示ごとやめた |
| これから（画面名） | **決まったこと** | 予定表だと思われる。**予定は管理しない** |
| 問題行動 / トラブル | **できごと** | ★いちばん言い出しにくい話題である。<br>入口にその語があれば、**書く前に責められた気持ちになる** |
| 元夫 / 元妻 | **お相手** | 関係性を想起させない |
| 父 / 母（コード上） | **監護親 / 非監護親** | 役割と性別は一致しない |
| 相手のメッセージ | **取次ぎ** | 相手の言葉ではないため |
| チャット | **対話** / **相談** | 相手と直接話している印象を避ける |
| テンプレート / 定型文 | **選択肢** | 本プロダクトは定型文を採用しない |
| ユーザー登録 | **招待** | 双方の参加が前提であるため |
