## 何をするものか

離婚した父母が、**別々に暮らしながら、子どもを一緒に育てていく**ための道具です。

父はAIと話し、母もAIと話します。
AIが、**責める言い回しや感情の部分を取り除いて、決めるために要る事実だけを相手に伝えます。**

```
入力（父が書いたもの）
  月3万が限界。こっちだって仕事切られて必死なんだよ。そっちだって働いてるだろ、少しは考えろ

母の画面に届くもの
  養育費について、月額3万円までを希望されているそうです。
  背景として、現在は職を失っているとのことです。
  ── お相手が書いた言葉そのものは含まれていません。
```

大事なのは、「必死なんだよ」が**届かなかったこと**ではありません。

> **月3万円という希望と、仕事を失ったという事情が、相手に届いたこと**です。

このままの言葉では送れません。送れば話し合いはそこで止まります。だから多くの人は送らない。そして何も決まらない。
**Aida がやるのは、送れなかったものを、送れる形にして届けること**です。
「直接転送しない」は、そのための手段にすぎません。

### なぜ要るのか

国の調査で、養育費の取り決めをしない理由の第1位は**「相手と関わりたくない」**です。
そして裁判所や代理人が入れば、取り決め率は **43.6% → 81.2%** に上がります。

**あいだに誰かが入れば決まる。**
けれど離婚の **87.5% は協議離婚**で、そこには誰も入ってきません（弁護士を双方が立てれば60〜100万円）。

> **人がやると成立しない条件——非同期・24時間・低単価——で、同じ役割を果たせるか。**

### 離婚しても、連絡は終わりません

実際のやり取りを見せていただく機会がありました。**9か月あまりで約1,000件。**
送迎、学校の提出書類、臨時の費用、体調、進路。**体感で8割以上が事務連絡でした。**

感情的な対立は数十件です。ただ**その数十件が、残りの1,000件を止めます。**
一度そうなると「送迎お願いできますか」の一行に身構えるようになる。

**決裂しているのではありません。事務連絡が、続かなくなるのです。**

## 設計の要点

### 1. LLM に文章を書かせない。枠を埋めさせる

いちばん効いた設計です。**型は2種類あり、埋める人が違います。**

| | 誰が埋めるか | 型の性格 |
| --- | --- | --- |
| **相談からの抽出** | **LLM** | **全部 `string`。**「原文にある表記をそのまま」 |
| **取り決めの入力** | **人**（画面のフォーム） | `integer` と `enum` で厳密 |

LLM に渡している型に、**数値型がありません。**「6万円」は `60000` ではなく **`"6万円"` のまま**受け取ります。
単位の換算も年の補完も、`parseYen()` のような**決定的なコード**の仕事です。

そして**相手に届く文章は、こちらが定型の枠に流し込んで組み立てます。**
自由に文章を書かせる経路が無いので、そこから原文が滲みません。

厳密な型を人に、曖昧なままの型を LLM に渡す——**逆にすると、モデルが「たぶん月額だろう」と判断して埋めます。**

### 2. 「気をつける」ではなく「書けない」

```ts
// partyId を引数に取らない ＝ Message へ到達する経路が型レベルで存在しない
buildRelayContext(snap: CaseSnapshot, proposalId: ProposalId): RelayContext
```

引数の数そのものをテストしています（増やすと CI が落ちます）。
同じ手を LLM にも使い、`LlmRouter` を唯一の入口にして、
**Router の外から SDK・エンドポイント・APIキーを参照していないことを静的検査**しています。

### 3. 検査は、テストであると同時に実行時の門

LLM の出力は毎回変わります。**テストで確かめるだけでは足りません。**

```
生成 → 検査（逐語一致・ホワイトリスト・伝聞形）→ 通れば越える
            ↓ 落ちた
        1回だけ作り直す
            ↓ また落ちた
        事情を落として、提案だけを越えさせる
```

**事情が伝わらないことより、原文が越えることのほうが重い**という判断です。

### 4. 対になる、2つの検査

| 越えるもの | 検査 |
| --- | --- |
| `content`（相手が読む文章） | **原文と逐語一致してはならない** |
| `payload`（金額・日付などの値） | **原文に逐語で書かれていなければならない** |

同じ道具を、片方では禁止に、もう片方では必須に使っています。

> **言葉は渡さない。事実は、原文のまま。**

実データに通して分かりました。**取次ぎの検査は全部すり抜けたのに、値の取り出しは落ちていた。**
書かれていない日付をモデルが作るのは、**言い換えではないので逐語一致で止まりません。**

### 5. 数字と条項は、人が書く

前提として、**取り決めの中身を入力するのは人**です。AIはその欄に触れません。
相手が了承すると**サーバが値を複製する**ので、記録の一致は構造的に保証されます。

そのうえで、AIが数字や条項に近づきうる2か所も、LLM には作らせていません。

- 養育費の目安は、裁判所公表の**令和元年改定標準算定表**から決定的に引きます
  （帯グラフのPDFから抽出し3つの方法で検証。9表中8表が通過。**通らなかった表は含めていません**）
- 条項は**ひな形の置換のみ**。未置換が残れば**文書を返しません**

> 空欄のある法的文書は、空欄のない誤りより危険です。

### 6. 持てないものを、持たない

| | |
| --- | --- |
| 既読 | **持ちません。**「ご覧になったかは、こちらでは分かりません」 |
| 履行の記録 | **やめました。**払った側は押さないので、記録率の低い台帳は<br>正しい信号より誤った信号を多く出します |
| 催促・リマインド | **しません。**急かすと話し合いが止まります |

### 7. AIは説教しない

危険な表現を検知しても、**その場では何も変わりません。**
「そのような表現は不適切です」と返した瞬間、**「何を書いてもいい」という約束が壊れます。**

受け止めたうえで、届けない。それだけです。通告の判断は**人が行います**
（[国自身が、児相の一時保護判断AIを導入見送りにしています](docs/legal-child-risk-research.md)）。

## コスト

| | |
| --- | --- |
| 階層 | SMALL `gpt-4.1-nano` ／ MEDIUM `gpt-4.1-mini` |
| **CT-4** | ルーティングなしとの比較を [`/metrics`](https://aida-4n47tjpp2a-an.a.run.app/metrics) に**実測値**で表示 |

単価はハードコードせず、**OrcaRouter の `/api/pricing` から取得**しています。
プロバイダの値下げが自動的に反映され、**呼び出しごとの原価をそのときの単価で記録**できます。

> **数字は測る範囲で変わります。**`/metrics` は集計期間を画面に出します。
> 期間を示さない削減率は意味を持ちません。

### 推論モデルの罠（実測）

| モデル | 出力トークン | 円/回 |
| --- | --- | --- |
| `gpt-5-nano`（入力 $0.05） | **1,358** | **0.0822** |
| `gpt-4.1-nano`（入力 $0.10・非推論） | 29 | **0.0032** |

**入力単価が半分のモデルが、25倍高くつきました。**思考トークンが出力に計上されるためです。
分類タスクの答えは29トークンで足ります。**階層を変えたら実測する**という規約にしました。

### LARGE を使わなくなりました

当初 LARGE（`gpt-5.1`）は調停案の説明文を書かせるために用意していましたが、**やめました。**
**LLM に文章を書かせない**方針を徹底した結果、**長文を書かせる用途そのものが無くなった**からです。

いま LLM を呼んでいるのは4か所だけで、**相手に届く文章を書いている呼び出しは1つもありません。**

## セキュリティ

| | |
| --- | --- |
| 分離 | `INV-1〜4a` を**実装より先に**テスト化。CI でブロッキング |
| インジェクション | 検知は**記録であって拒否ではない**。止めなくても、**コンテキストに無いものは出ません** |

### E2E

**メールを送らずに、メールリンク認証まで通して確認できます。**

```bash
pnpm e2e                                   # localhost に対して
BASE_URL=https://… pnpm e2e                # 本番に対して
```

`generateSignInWithEmailLink` はリンクを**返すだけ**で送信しません。
そこから `oobCode` を取り出して ID トークンに交換するため、**人手を介さずに確認できます。**

ケース作成 → 招待 → 受諾 → 対話 → **C1の検証** → メール登録 → 別端末からの復帰 → 合意 → 原価まで。

### 開発の進め方

**不変条件・状態遷移・安全に関わるものは、実装より先にテストを書いています**
（`docs/development-guidelines.md` §5.0）。コミット履歴で確認できます
（`test(SN): …` が落ちる状態でコミットされ、次に `feat(SN): …` が通す）。

このやり方は機能しましたが、**机上では出ないものもありました。**2人で触って初めて出たものです。

- 算定表の帯の誤記（デザイン納品物と設計書の両方）
- 一時的な融通が、合意そのものを書き換えうる状態だった
- 相手が参加していなくても「ご返事をお待ちしています」と出ていた
- 承諾が、承諾として伝わっていなかった（抽出に「お返事」の置き場が無かった）
- **届いた取次ぎのカードが、高さ 2px に潰れていた**（flex の子は `overflow` が
  `visible` でないと最小高さが 0 になる。API も描画も正しく、**主題そのものが画面から消えていた**）

> **説明を組み立てる前に、数字を1つ取る。**最後の1件は、`getBoundingClientRect()` を1回見て終わりました。
