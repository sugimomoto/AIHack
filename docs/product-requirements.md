## 1. プロダクトビジョンと目的

### 1.1 ビジョン

> **離婚しても、子どもが健やかに育つための基盤になる。**

### 1.2 目的の構造

**親同士のコミュニケーションを楽にすることは、目的ではなく手段である。**

```
【目的】離婚しても、子どもが健やかに育つための基盤になる
   │
   ├─【経済面】養育費の不払いによる困窮から、子どもの成長と健康を守る
   │
   └─【関係面】連絡の負担を理由に、子どもが親に会えなくなる状況を防ぐ
                              ↑
                     どちらも、親同士のコミュニケーションが
                     機能しないことによって損なわれている
   │
【手段】親同士が直接やりとりせずに合意できるようにする
```

| | |
| --- | --- |
| 直接的な受益者 | 父母（連絡の負担が減る） |
| **本来の受益者** | **子ども（生活基盤が守られ、親に会える）** |

### 1.3 改正民法の理念との一致

この目的設定は本プロダクト独自の主張ではなく、**改正民法が掲げる理念そのもの**である。

| 条文 | 内容 |
| --- | --- |
| 民法817の12 | 婚姻関係の有無にかかわらず父母が子に対して負う責務を明確化。**「子の心身の健全な発達を図るため」**子の人格を尊重すること |
| 民法818等 | **親権が「子の利益」のために行使されなければならない**ことを明確化 |

> **法が父母に課した責務を、実行可能にするのが本プロダクトである。**
> 法は「協力せよ」と定めたが、協力の手段は用意していない。

### 1.4 中核コンセプト

本プロダクトを定義する構造的特徴は次の3点。**この3つが揃って初めて成立する。**

#### C1. メッセージを転送しない（ハブ&スポーク型調停）

既存サービスはすべて **P2Pメッセージング + フィルタ** 構造であり、相手の言葉が形を変えて届く。本プロダクトは構造を変える。

```
【既存】父 ──[メッセージ]──▶ AIフィルタ ──[緩和済]──▶ 母
        相手の意図・感情が透ける

【Aida】父 ◀──個別対話──▶ AI ◀──個別対話──▶ 母
                           │
                           ▼
                     合意事項のみ確定
        相手の言葉は原理的に一度も届かない
```

父の「また勝手に土曜に決めやがって」は**転送されない**。母に届くのは、AIからの「土曜の日程について別案の相談が来ています」という提示のみ。

**これが「AIである必然性」の根拠**：定型文は送信者の文言をそのまま届ける仕組みであり、この動作は原理的に実現できない。人力による仲介では可能だが、非同期・24時間・低単価では成立しない。

**C1の帰結：定型文を採用しない**

| | 定型文（raeru / Copak） | Aida |
| --- | --- | --- |
| 仕組み | 送信者が文言リストから選ぶ → **そのまま相手へ転送** | ユーザーは自由に入力 → **転送されない** |
| 思想 | 転送する内容を制限する | 転送しない |

両者は思想として真逆であり、併存させると製品の定義が崩れる。ただし入力負担の軽減は代替手段で確保する。

```
【定型文】  ユーザーが文言リストから選ぶ → そのまま相手へ転送
【Aida】    AIが「次のどれに近いですか？」と選択肢を提示
            → ユーザーが選ぶ → AIへの入力になる → AIが相手と個別に交渉
```

#### C2. 入口を協議離婚に置く

**根拠1：双方の関与が制度上の前提である**

協議離婚と公正証書作成は制度上、双方の関与が前提である。したがって入口を前段に置くことで、離婚後アプリが抱える「相手を招待できない」という獲得上の障壁が構造的に解消される。

**根拠2：協議離婚は、統計上もっとも取り決めがされていない場所である**

| 離婚方法 | 養育費の取り決め率 | 面会交流の取り決め率 |
| --- | --- | --- |
| **協議離婚（母子世帯 758,312）** | **43.6%** | **27.9%** |
| その他の離婚（同 192,146） | 81.2% | 56.5% |

第三者（裁判所・代理人）が介在すれば取り決め率は約2倍になる。**協議離婚は件数が最も多く、かつ第三者が最も介在しない領域**であり、AIという第三者を投入する対象として統計的に最適である。

#### C3. 合意が、その後のAIの判断基準になる

入口で作成した合意内容（養育費額・支払日・面会頻度等）を構造化データとして保持し、**離婚後のAI調停はこの合意を根拠に動作する**。

> 「合意では面会交流は月1回・第2土曜です。今回のご提案はこれと異なりますが、変更として記録しますか？」

汎用AIの「原則論」ではなく、**当事者本人が署名した約束**を根拠にできる点が、調停の説得力を決定的に変える。

## 2. ターゲットユーザーと課題・ニーズ

### 2.1 制度環境

**民法等の一部を改正する法律（令和6年法律第33号）が、2026年（令和8年）4月1日に施行された。**

| # | 改正点 | 内容 |
| --- | --- | --- |
| ① | **法定養育費制度**（民法766の3） | 取決めがなくても請求できる。ただし**月額2万円 × 子の数**（「子の最低限度の生活の維持」に要する額） |
| ② | **養育費債権への先取特権**（民法308の2） | **月額8万円 × 子の数**を上限に、債務名義なしで差押えが可能 |
| ③ | **共同親権の選択**（民法819等・824の2） | 日常の行為と急迫の事情を除き、**双方の合意が必要**。意見対立を調整する裁判手続を新設 |

> ⚠️ **共同親権に関する統計データは存在しない。**施行から日が浅く、選択率も運用実態も未知である。**共同親権を課題の根拠として用いてはならない。**

### 2.2 実在する課題

出典：令和3年度全国ひとり親世帯等調査（こども家庭庁／旧厚生労働省）。**本節の数値はすべて単独親権世帯のものである。**

```
① 離婚の87.5%は協議離婚。裁判所も代理人も介在しない
        ↓
② 協議離婚の養育費取り決め率は 43.6%。裁判所を経れば 81.2%
   第三者が入るかどうかで倍の差がある
        ↓
③ 取り決めをしない理由の第1位は「相手と関わりたくない」
        ↓
④ 養育費を現在も受けている母子世帯は 28.1%
   受けたことがない世帯が 56.9%
        ↓
⑤ 取り決めがなければ月2万円（子1人）のみ
   取り決めをしている世帯の平均月額は 50,485円
```

#### 核心となる事実

**（1）取り決めをしない最大の理由は「相手と関わりたくない」**

調査本文に、養育費・面会交流の**両方で第1位**として明記されている。

> 養育費の取り決めをしていない最も大きな理由については、母子世帯の母では「**相手と関わりたくない**」が最も多く、次いで「相手に支払う意思がないと思った」

**本プロダクトが解決しようとしている課題が、国の公式調査によって課題の第1位として特定されている。**

**（2）連絡の負担が、面会の回数を決めている**

離婚案件専門の弁護士による実務観察。

```
別居親が子との面会交流を申し立てる
        ↓
同居親が「精神的苦痛」を主張する
        ↓
裁判所が面会制限を認める（「2ヶ月に1回が限界」など）
        ↓
実際の理由の多くは「相手と連絡を取り合いたくない」という感情的なもの
```

> 「できるだけ連絡を取りたくないから、面会は月1回だけ」という結論になってしまっている（離婚案件を専門とする弁護士）

#### 主要指標

| 指標 | 値 |
| --- | --- |
| 協議離婚が全離婚に占める割合 | 87.5% ※二次情報・要再確認 |
| 養育費の取り決め率（母子世帯） | 46.7% |
| 養育費の受給率（現在も受けている・母子世帯） | **28.1%** |
| 養育費を受けたことがない（母子世帯） | 56.9% |
| 養育費の平均月額（額が決まっている世帯） | 50,485円 |
| 面会交流の取り決め率（母子世帯） | 30.3% |
| 養育費について誰にも相談していない（母子世帯） | **45.5%** |
| 弁護士に相談した（母子世帯全体に対する概算） | **約11%** |

> **「弁護士に頼めない大多数」がターゲットである。**

### 2.3 当事者・実務家からの一次情報

統計は「取り決めがされていない」という事実を示すが、**現場の質感は当事者と実務家からしか得られない**。

**（1）当事者の実感**（共同養育の当事者・raeru 利用者）

| 発言 | 含意 |
| --- | --- |
| raeru は「あんまり使い勝手が良くない」「足りない」 | 先行サービス利用者による直接評価 |
| **「結局は本人同士の直接メッセージになる」** | **C1の必要性を裏づける** |
| 定型文はあるが「実際のやり取りははるかに細かい」<br/>例：「この塾に入れようと思う」「明日お迎えに行ってほしい」 | **定型文では被覆できない** |
| 直接やり取りすると **「いちいち腹が立つことがある」** | **これが本質的な痛み** |

**（2）実務家の観察**（離婚案件専門の弁護士）

| 発言 | 含意 |
| --- | --- |
| 離婚後3〜5年経てば落ち着くが、**最初あるいは離婚調停中はコミュニケーションそのものが衝突要因**になる | ターゲットのタイミング |
| 面会日程の調整を**弁護士同士が代理で行っている**。依頼者から「**これは弁護士の仕事ではないだろう**」という声 | 専門家側の課題 |
| 子のいる家庭の離婚で「スムーズにやり取りできる人は圧倒的に少ないはず」 | 市場規模の実務感覚 |

**（3）既存手法の限界が数値で判明**

| サービス形態 | 制限 |
| --- | --- |
| 人が間に入って伝達するサービス | **月3回まで5,000円** |
| raeru の緊急メッセージ（ブロック型AIフィルター） | **月3回**・プレミアム限定 |

**人力型とブロック型の双方が「月3回」という同じ限界値に収束している。**「非同期・無制限・低単価」が既存手法では実現不可能であることの傍証である。

### 2.4 ペルソナ

| # | ペルソナ | 状況 | 主要ニーズ |
| --- | --- | --- | --- |
| **P1** | 監護親（子と同居） | 協議離婚を進行中／離婚後。相手と直接話すと感情的になる | 養育費を確実に受け取りたい。相手と直接やりとりしたくない |
| **P2** | 非監護親（別居親） | 同上。子に会いたいが連絡が取りづらい | 面会交流を安定して実現したい。一方的に決められたくない |
| **P3** | 専門家 | 行政書士・弁護士・調停人 | 代理人業務の負担軽減。顧客の合意形成の効率化 |

### 2.5 親権の形態は問わない

**本プロダクトは共同親権専用ではない。単独親権のケースも等しく対象とする。**

養育費・面会交流は、**いずれも親権の形態と無関係に発生する**。

| | **単独親権** | **共同親権** |
| --- | --- | --- |
| 養育費 | 必要 | 必要 |
| 面会交流 | 必要 | 必要 |
| 重要事項の共同決定 | 不要 | **必要**（民法824の2） |
| **利用の強度** | 中（月次の支払・面会） | **高**（重要事項が生じるたび） |
| **DVケース** | **ここに含まれる** | **制度上、除外される** |
| 母数 | **既存の約118万世帯＋年約9.4万件** | 今後増加（**統計データなし**） |
| 位置づけ | **ベース市場** | **高LTVセグメント** |

**DVケースは単独親権にしかならない。**改正法は「子の利益を害する場合には単独親権としなければならない」とし、DVのおそれを例示している。**「相手と直接やりとりしたくない」ニーズが最も強いのは単独親権の層であり、ここを外してはならない。**

## 3. 主要な機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| F1 | **個別対話** | 父・母それぞれがAIと1対1で対話する。相手の入力内容は一切共有されない |
| F2 | **感情の受け止め** | 感情表出を受け止める。この応答は相手に共有されない |
| F3 | **論点抽出と調停** | 対話から合意すべき論点を抽出し、算定表等の客観的根拠に基づく調停案を生成する |
| F4 | **合意状態の管理** | 8論点それぞれの状態と内容を構造化データとして保持する。変更は履歴として追記する |
| F5 | **公正証書原案の生成** | 合意内容から、公証役場に持参可能な原案を生成する |
| F6 | **予定管理とリマインダー** | 支払日・面会日を予定として登録し、期日前に通知する |
| F7 | **履行トラッキングと逸脱検知** | 履行状況を記録し、合意との差分を検知する |
| F8 | **法的状態の提示** | 逸脱時に、先取特権の範囲内かどうか等の客観的情報を提示する |
| F9 | **協議決裂時の出口提示** | 調停不能と判断した論点について、調停・専門家への導線を提示する |
| F10 | **非開示情報の保護** | 住所・連絡先等を構造的に分離し、相手側から参照不可能にする |
| **F11** | **運用中の調整** | 日程変更・特別費用・進路等について、合意を基準に調整する。一時的な例外と恒久的な変更を区別する |
| **F12** | **日常の連絡** | 体調・写真・学校からの連絡等を、合意を要さずに伝達する |
| **F13** | **相談トピックの選択** | 分類とシナリオから相談内容を選んで対話を開始する。**選択せずに書き始めることもできる** |

### 3.1 やりとりの3層構造

父母間のやりとりは性質の異なる3層からなる。**利用時間の大半は L2・L3 に費やされる。**

| 層 | 内容 | 例 | 合意 | 公正証書 |
| --- | --- | --- | --- | --- |
| **L1** | 離婚時の取り決め | 養育費の額、面会のルール | 必要 | **なる** |
| **L2** | 運用中の調整 | 今月の日程変更、塾の費用、進学の相談 | 必要 | ならない |
| **L3** | 日常の連絡 | 体調の報告、写真の共有 | 不要 | ならない |

**L1があるからこそL2が機能する。**「取り決めでは月1回・第2土曜です。今回は例外にしますか、それとも今後も変更しますか？」という問いかけができることが C3 の実体である。

### 3.2 相談トピックのマスタ化

やりとりのバリエーションは無限にあるため、**分類とシナリオをマスタとして持ち、コード変更なしに追加できる構造とする。**

| 項目 | 方針 |
| --- | --- |
| **編集主体** | **運営**（専門家へのヒアリングをもとに整備） |
| 編集手段 | DBを直接操作。**マスタ管理画面は設けない** |
| 専門家の位置づけ | **情報源であり、編集者ではない** |
| エンドユーザー | 編集しない。「その他（自由に書く）」の実績をもとに運営が昇格させる |

**ただしカスタマイズ可能な範囲は限定する。**

| kind | 対応する層 | カスタマイズ | 理由 |
| --- | --- | --- | --- |
| **FORMAL** | L1 | **不可（システム定義）** | 公正証書の条項ひな形と payload スキーマが1対1で対応するため。可変にすると LLM に条項を書かせることになり NFR-03 L-1 に抵触する |
| **ADJUSTMENT** | L2 | 可能 | 法的文書にならない |
| **NOTIFICATION** | L3 | 可能 | 同上 |

### 3.3 対象とする合意論点（L1・FORMAL）

離婚時に決めるべき論点は**8項目**存在する。**この8項目は固定である。**

| # | 論点 | 誰のためのものか | 優先度 |
| --- | --- | --- | --- |
| 1 | 離婚への同意 | 親 | 低 |
| 2 | 親権者の決定 | 子（制度上の帰属） | 中 |
| **3** | **養育費** | **子（経済面）** | **最高** |
| **4** | **面会交流** | **子（関係面）** | **最高** |
| 5 | 財産分与 | 親 | 低 |
| 6 | 慰謝料 | 親 | 低 |
| 7 | 年金分割 | 親 | 低 |
| 8 | 婚姻費用 | 主に配偶者（子の生活費を含む） | 中 |

**養育費と面会交流を最優先とするのは、§1.2 で定義した目的の2本の柱そのものだからである。**残り6論点は親同士の清算に関するものであり、重要ではあるが目的の中心ではない。

### 3.4 履行確保と証拠能力に対する考え方

日本の民事訴訟は自由心証主義を採り、米国のように裁判所が特定サービスの利用を指定する運用がない。したがって**OurFamilyWizard型（自社ログの証拠能力を訴求する）は日本では再現困難**である。

**本プロダクトは証拠能力を自ら作らない。**既存の法制度に乗る。

| 層 | 内容 | 担保者 |
| --- | --- | --- |
| L1. 合意 | 強制執行認諾文言付き公正証書、先取特権の対象となる養育費債権 | **法制度** |
| L2. 履行記録 | 入金の有無、面会の実施記録 | 客観的事実の記録 |
| L3. 対話ログ | AIとの会話、交渉経緯 | 参考資料に留める |

役割は「**すでに執行力のある合意からの逸脱を検知・記録すること**」に限定する。

**訴求の方針**

先取特権により「公正証書がないと差押えできない」は成立しない。採る訴求は**取り決めの有無による受給額の差**である。

| ケース | 請求できる額 |
| --- | --- |
| **取り決めなし** | **月2万円 × 子の数**（法定養育費のみ） |
| 取り決めあり | 合意額（月8万円/子までは債務名義不要、超過分は債務名義が必要） |

公正証書が依然として必要な領域は、①月8万円/子を超える養育費 ②養育費以外のすべて ③金額の確定そのもの ④施行日前に離婚した層、である。

## 5. ビジネス要件

### 5.1 競合とポジショニング

| サービス | カバー範囲 | 限界 |
| --- | --- | --- |
| **raeru** | 離婚後の面会交流調整。定型文＋月3回のブロック型AIフィルター | 合意形成を支援しない。自由文を原則禁止する設計 |
| **Copak** | 共同養育計画書の作成支援 | 私文書。作成時点で完結し、その後の運用に接続しない |
| **りむすび等（人力仲介）** | 人による文面仲介 | 非同期・24時間対応・低価格化が構造的に不可能 |

**ギャップ**：「合意を作る段階」と「合意を運用する段階」が分断されており、両者を1つのシステムで貫くプレイヤーが存在しない。

**ポジショニング**

> **Copakは計画書を「作る」。Aidaは、作った合意を「動かし続ける」。**
>
> **raeruは危ない言葉を「ブロックする」。Aidaは危ない言葉を「受け止めて、相手に届けない」。**

**ブロックと吸収の差**

| | ブロック型（raeru） | 吸収型（Aida） |
| --- | --- | --- |
| 感情的な入力への応答 | 送信を拒否する | 受け止める（相手には転送しない） |
| 送信者の体験 | **拒絶された。言い直しを強いられる** | **聞いてもらえた** |
| 回数制限 | **月3回**（誤判定リスクを回数で抑制） | **不要**（転送しない設計のため） |

### 5.6 チーム構成による差別化

先行サービスが不十分である理由についての、実務家の仮説。

> raeru がいまいちなのは、**弁護士が開発しているから**。弁護士は共同養育や離婚の当事者ではないため、「**実際こういう文面が来るとむかつく**」という視点が抜けている。

| 役割 | この視点がないと欠落するもの |
| --- | --- |
| **法律の専門家** | 非弁の線引き、実務の手続き、裁判所の運用実態 |
| **ITの専門家** | アーキテクチャ、セキュリティ、LLMコスト設計 |
| **共同養育の当事者** | **どの文面が実際に人を傷つけるか** |

**3つ目が最も希少で、かつ先行サービスに欠けている。**「メッセージを転送しない」というコンセプト自体、当事者の「いちいち腹が立つ」という実感から出たものである。

> **これは機能ではなく、体制による差別化である。**同じ機能を後から実装することはできても、この3者の視点を後から獲得することは難しい。

### 5.7 認知の獲得が価値の前提になる

§1.2 の目的（面会制限の言い訳を封じる）は、**プロダクトが普及して初めて成立する**。現状は既存サービス名を挙げても実務で通用していない。**認知の獲得そのものが事業計画の中心に位置づけられる。**

## 6. ユーザーストーリー

### US-01｜対立点をAIに預ける
> **監護親（P1）として、**元配偶者と直接交渉せずに養育費の金額を決めたい。**なぜなら**直接話すと必ず感情的な口論になり、話が前に進まないから。

### US-02｜感情を吐き出しても、相手を傷つけない
> **非監護親（P2）として、**不満をそのままAIに伝えたい。**なぜなら**言葉を選ぶ負担が大きく、かといって感情を抑え込むのも苦しいから。**ただし**その言葉が相手に直接届かないことが保証されている必要がある。

### US-03｜根拠のある着地点がほしい
> **双方（P1・P2）として、**AIから客観的な根拠（養育費算定表など）に基づく妥協案を提示してほしい。**なぜなら**相手の主張が妥当なのか判断できず、譲るべきかどうかが分からないから。

### US-04｜合意を法的に有効な形にしたい
> **監護親（P1）として、**合意内容を公正証書の原案として出力したい。**なぜなら**口約束では養育費が支払われなくなったときに何もできないから。

### US-05｜事情が変わったときに再交渉したい
> **非監護親（P2）として、**収入減などの事情変更を相手に伝え、支払条件を再交渉したい。**なぜなら**一方的に滞納すると関係が決定的に壊れるから。

### US-06｜約束が守られているか把握したい
> **監護親（P1）として、**養育費の入金や面会の実施状況が自動で記録されてほしい。**なぜなら**不履行が続いたときに、公正証書に基づく手続きへ進む判断材料が必要だから。

### US-07｜相手に個人情報を知られたくない
> **監護親（P1）として、**現住所や連絡先を相手に知られたくない。**なぜなら**関係性によっては身の安全に関わるから。**また**相手がAIを誘導して情報を引き出せないことが保証されている必要がある。

### US-08｜まとまらないときは、次の手段を知りたい
> **双方（P1・P2）として、**話し合いがまとまらない論点について、次に取るべき手続きを知りたい。**なぜなら**アプリ内で堂々巡りを続けても解決せず、調停という制度があること自体を知らないことも多いから。

### US-09｜相手の名前を見たくない
> **監護親（P1）として、**相手の表示名を自分で変更したい。**なぜなら**元配偶者の氏名が画面に表示されるだけで動揺してしまうから。

### US-10｜細かい連絡もこのアプリで済ませたい
> **双方（P1・P2）として、**「この塾に入れようと思う」「明日お迎えに行ってほしい」といった日常の細かい連絡もAI経由で行いたい。**なぜなら**定型文では表現できず、かといって直接連絡は取りたくないから。

## 7. 受け入れ条件

プロダクトが成立したと言えるための条件。

### AC-P1｜メッセージが跨がらない
- [ ] 一方が入力した原文が、他方の画面に**いかなる経路でも表示されない**
- [ ] 一方のセッションから他方のセッション内容を取得できない
- [ ] この性質が**自動テストで検証されている**

### AC-P2｜感情を受け止める
- [ ] 感情的な入力が**ブロックされず**、AIに受け止められる
- [ ] 受け止めの応答は相手に共有されない
- [ ] **回数制限がない**

### AC-P3｜根拠のある調停
- [ ] 調停案には**算定表に基づく根拠が明示される**
- [ ] 金額は決定的な参照によって算出され、AIが生成した値ではない
- [ ] 個別の法的助言は行わない

### AC-P4｜合意が構造化され、文書になる
- [ ] 合意内容が構造化データとして保持される
- [ ] 変更時は履歴が保持される（上書きしない）
- [ ] 合意内容から公正証書の原案が生成される
- [ ] 原案に「公証人による確認が必要」である旨が明示される

### AC-P5｜約束が守られているかを追跡する
- [ ] 合意から支払・面会の予定が生成される
- [ ] 履行状況が記録される
- [ ] 逸脱が検知され、双方に通知される
- [ ] 逸脱時に法的状態（先取特権の範囲内か等）が提示される

### AC-P6｜非開示情報が守られる
- [ ] プロンプトインジェクションによって相手の非開示情報が出力されない
- [ ] 非開示情報が**そもそもAIのコンテキストに存在しない**
- [ ] AIへのシステム指示をユーザー入力で上書きできない

### AC-P7｜解決できないときは手を引く
- [ ] 合意に至らない論点について、調停・専門家への導線が提示される

## 8. 機能要件

### FR-01｜個別対話インターフェース
父・母それぞれに独立したセッションを提供する。相手の入力内容・入力中状態・既読状態は一切共有しない。

**定型文は提供しない。**入力負担の軽減は、AIが対話中に提示する**選択肢**によって行う。選択肢は相手への送信内容ではなく、AIへの入力として扱う。

### FR-02｜意図分類と危険検知
入力メッセージごとに意図（要求／同意／拒否／感情表出／情報照会／変更申請）を分類する。同時に、暴力的表現・脅迫・個人情報の照会要求を検知する。

**1メッセージが複数の意図を持つことを許容する。**感情は受け止めて捨て、要求だけを構造化して相手側へ渡す。

### FR-03｜感情の受け止め
相手に転送されない領域として、感情表出を受け止める応答を行う。この応答は他方に共有されない。**回数制限を設けない。**

### FR-04｜論点抽出と調停案生成
双方の対話から合意すべき論点を抽出し、調停案を生成する。

### FR-04a｜算定表による根拠提示
養育費および婚姻費用は、実務上いずれも**算定表を基準に計算される**。調停案の提示にあたっては、**算定表に基づく根拠を必ず併記する**。

> **提示は客観的情報に留める。**「算定表では一般にこの範囲とされています」という情報提示は行うが、「あなたはこの額にすべきです」という**個別の法的助言は行わない**。

### FR-05｜合意状態の管理
8項目の論点マスタを保持し、各論点について状態を管理する。

```
未着手 → 係争中 → 合意済 → （変更申請中 → 合意済）
           ↓         ↓
      調停へ      逸脱検知
```

- 合意済の論点は、内容・合意日時・双方の承諾記録を保持する
- 変更時は**履歴を上書きせず追記**する

### FR-06｜公正証書原案の生成
合意済の論点から、公証役場に持参可能な形式の原案を生成する。

> **LLMに条項文を自由生成させてはならない。**あらかじめ用意した条項ひな形を選別し、合意された構造化データを流し込む方式に限定する。

生成物には**公証人による確認が必要である旨を画面上に明示**する。

### FR-07｜支払い予定の登録とリマインダー
合意された養育費の金額・支払日を予定として登録し、期日前に双方へ通知する。面会交流についても同様に予定を登録する。

### FR-07a｜履行トラッキング
登録された支払日・面会予定日に対し、履行状況を記録する。

### FR-08｜逸脱検知と通知
履行記録と合意内容を突合し、逸脱を検知して双方に通知する。

### FR-08a｜法的状態の提示
逸脱検知時に、そのケースが**先取特権の範囲内かどうか**を判定して提示する。

| 判定 | 提示内容 |
| --- | --- |
| 範囲内 | 「合意額は先取特権の範囲内（子1人あたり月8万円）です」 |
| 超過あり | 「月◯円分は範囲を超えるため、公正証書等の債務名義が必要になります」 |

> この区別を当事者が理解するのは困難であり、AIが説明できること自体が価値になる。ただし客観的情報の提示に留める。

### FR-09｜非開示情報の分離
住所・連絡先・勤務先等の非開示情報は、AIのコンテキストから構造的に分離し、他方の対話セッションで参照不可能とする。

### FR-10｜原文の保全と開示
送信者本人は自身の入力原文をいつでも確認できる。第三者（裁判所等）への開示手続きの存在を明示する。

### FR-11｜協議決裂時の出口提示
一定回数の調停試行を経ても合意に至らない論点について、AIが**調停不能と判断し、家庭裁判所の調停または専門家への相談を提示する**。

> **AIが「解決できない」と認める導線を持つことは、プロダクトの誠実性を担保する。**

### FR-12｜相手の表示名変更
相手の表示名をユーザーが任意に変更できる。

### NFR-01｜セキュリティ

### NFR-02｜LLMコスト

| 用途 | 頻度 | モデル階層 |
| --- | --- | --- |
| 意図分類・危険検知 | 全メッセージ（高） | 小型 |
| 感情の受け止め・傾聴 | 中 | 中型 |
| 調停案生成 | 低 | 大型 |
| **条項の生成** | — | **なし（ひな形置換）** |
| **金額の算定** | — | **なし（算定表参照）** |

| # | 目標 |
| --- | --- |
| CT-1 | 1メッセージあたりの単価を計測・表示できること |
| CT-2 | 1世帯あたりの月額原価を試算できること |
| CT-3 | **市場アンカーである月額500円**を前提としても、継続課金層で粗利が成立する原価に収めること |
| CT-4 | ルーティングなし（全処理を大型モデルで実行）との**原価比較を提示**できること |

### NFR-03｜法規制対応（弁護士法72条）

**前提：離婚協議には「事件性」が認められる。**

法務省ガイドラインは、弁護士法72条違反の成立には3要件（①報酬を得る目的 ②法律事件＝事件性 ③鑑定その他の法律事務）すべての該当が必要としたうえで、次の例を挙げている。

> 取引当事者間で**紛争が生じた後に、当該紛争当事者間において、裁判外で紛争を解決して和解契約等を締結する場合**には……「事件性」が認められる

離婚協議はこれに該当する。**残る防御線は要件③（法律事務）である。**

| # | 制約 |
| --- | --- |
| **L-1** | **公正証書原案の生成において、LLMに条項文を自由生成させない。**ひな形を選別し、構造化データを流し込むにとどめる |

### NFR-04｜倫理・透明性

- AIが仲介していることを両当事者に明示する
- AIは意思を代弁するのではなく、**伝達のタイミングと形式を制御する**に留まる
- 本人は自身の原文をいつでも確認できる（FR-10）

### NFR-05｜フォームファクタ

**スマートフォンを前提とする。**最終的に iOS / Android ネイティブアプリとしてリリースすることを想定する。
