実体験者へのヒアリングを受けた方針整理。
**議事の原本は `.meetings/`（Git 対象外・実名を含む）。ここには匿名化した内容だけを置く。**

## 1. フィードバックの要点

### 1.1 ★ 入口とコアを分ける

| | 内容 |
| --- | --- |
| **入口機能** | 公正証書・基本取り決めの**定型入力（ウィザード形式）**。AI 相談に全面依存しない |
| **コア機能** | **離婚後の日常的コミュニケーションの仲介**（合意形成と情報共有） |

ドラフト作成を専門家に頼むと5万〜10万円かかる。そこを定型入力で効率化しつつ、
**その後に都度発生する連絡こそが本体**、という整理。

### 1.2 ★ 「合意」と「共有」の二軸

離婚後の連絡は大きく2種類。

1. **合意を要する相談** … 費用分担、ルール調整
2. **単純な情報共有** … 運動会の案内、学校からの連絡、成績、写真

実体験では**共有連絡のほうが実務的に多い。**
直接連絡したくない相手とやり取りするうえで、共有にも仲介の価値が高い。

> AI の挙動を、目的に応じて分けること。
> **共有目的の連絡に、合意前提の進行を混ぜない。**

### 1.3 ★ 臨時費用が頻繁に発生する

養育費とは**別枠**で、入塾費用・メガネ代・医療費といった臨時費用の分担相談が繰り返し起きる。
ケースバイケースであり、ドラフト作成のような定型処理とは性質が違う。

### 1.4 品質：要約ではなく、基準に基づく取捨選択

デモで**領収書提出依頼の文面抽出に齟齬**が出た。
AI に「要約」させるのではなく、**目的項目の定義を前提にした取捨選択**を徹底する。

### 1.5 実体験の具体

- 公正証書は当事者間で協議し、ドラフトは行政書士へ依頼、公証役場で手続き
- 養育費は一般基準を参照しつつ、**私立・インター進学など家族事情を加味**して協議で決定
- 離婚後は役割分担がある（一方が学校・部活、他方が塾・食事など）
- **突発的に攻撃的なメッセージが混じる。**緩衝と整流の必要性が高い

### 1.6 ハッカソン提出の到達点

「日常利用できる完全版」ではなく、**コンセプトと体験価値が伝わるデモと説明資料**。

## 2. ★ 実装との差分

### 2.1 すでに満たしているもの

| フィードバック | 実装 |
| --- | --- |
| 合意と共有で挙動を分ける | `kind`（FORMAL / ADJUSTMENT / NOTIFICATION）で帰結を分岐（S32）。分類に `INFO_SHARING` を追加 |
| 共有目的に合意前提を混ぜない | 取り決めを動かせるのは FORMAL だけ。書き込み直前でも検査（`assertNegotiable`） |
| 要約ではなく取捨選択 | 抽出を「言い回しだけ言い換え、**事実は変えない**」に修正。品目が化けていた（スマホ代→コピー代） |
| 領収書依頼の文面の齟齬 | 同上で修正。画像は扱えないので、**できないと答える**ようにした（→ Issue #6） |
| 攻撃的表現の緩衝 | 受け止めは感情を否定しない。取次ぎだけが検査を通る（逐語一致・ホワイトリスト・伝聞形） |
| DV への配慮と窓口 | `SafetyEvent` で記録し、**本人には告げない**。窓口は常設（検知に反応しない） |

### 2.2 ★ 満たしていないもの

| # | フィードバック | いまの実装 | 差分 |
| --- | --- | --- | --- |
| **A** | 入口は**公正証書の定型入力（ウィザード）** | 取り決めは**AI 対話でしか作れない**。定型入力は「離婚済み・取り決めあり」を選んだ人の養育費だけ | **面会のルール・財産分与・年金分割を定型入力できない。**「これから決める」人は対話しか道が無い |
| **B** | 臨時費用が別枠で頻発 | 調整（Adjustment）として記録はされるが、**精算の完了状態が無い** | → Issue #7 |
| **C** | 証跡（領収書） | 扱えない | → Issue #6 |
| **D** | デモ動画・説明資料 | 未着手 | 提出物として必須 |

> **★ A が最も大きい。**
> フィードバックは「**AI 相談に全面依存しない**」と明確に言っている。
> 現状は依存しており、**取り決めを作る唯一の道が対話**になっている。

## 3. 対応方針（締切まで約2日）

### 3.1 いま入れる

- [ ] **A：基本取り決めのウィザード**
      面会のルール（回数・曜日・時間・受け渡し場所）を定型入力できるようにする。
      養育費は既にある。**対話を経ずに取り決めへ到達する道**を作ることが要点
- [ ] **D：デモと説明資料**
      提出の到達点そのもの

### 3.2 Issue に積む（ハッカソン後）

- [Issue #6] 領収書などの画像
- [Issue #7] 証跡と精算の完了まで（受給率に効かせる）
- [Issue #5] 面会交流と養育費の非対称
- 臨時費用を独立した単位にする（Issue #7 の1番目）

### 3.3 やらないと決めたこと

- **口座連携による入金確認。**
  「アプリは入金を観測できない」という不変条件を捨てることになる。
  観測できないことを断定しない規律のほうが、この製品では重い
