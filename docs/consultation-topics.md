## 3. ★ `kind`（種別）が実際に効くところ

| 種別 | 取次ぎ | 取り決め（公正証書） | 「決まったこと」への控え | スレッド |
| --- | --- | --- | --- | --- |
| `FORMAL`（取り決めを決める相談） | する | ~~作る~~ **→ 作らない**（2026-08-13 の方針転換） | 作らない | ~~続き~~ **→ 都度別** |
| `ADJUSTMENT`（個別の相談） | する | 作らない | 作る | 都度別 |
| `NOTIFICATION`（お知らせ） | する | 作らない | 作らない | 都度別 |

### 3.1 いまの実装との差

- **`FORMAL` から取り決めは作られない。**対話から取り決めへ行く経路を断った（T1）
  - → **`FORMAL` であることの意味は、ほぼ失われている**
- ✅ **`NOTIFICATION` の控えは直した。**`isAdjustment(kind)` で分岐している

### 3.2 ★ スレッドの例外を無くした（2026-08-14）

以前は `FORMAL` だけが**続き**だった（`th_{scenarioId}` 固定）。
そのため「養育費を決める」を新しく相談しようとしても、**前のスレッドが開いた。**

> ★ **先月の事情が残ったまま、今月の話が始まる。**
> `ADJUSTMENT` で避けていたことが、`FORMAL` でだけ起きていた。

**続きにする根拠は、もう無い。**取り決めは取り決めの画面で書くので、
相談は**合意形成の本体ではない**。だとすれば、都度の相談である。

→ `isContinuing` を削除し、**`token` を必須**にした。
   以前は省略でき、省略すると `th_{scenarioId}`（＝続きのID）になった。
   **渡し忘れが、黙って前の会話につながる**形だったので、型で塞いだ。

★ **過去のスレッドは、そのまま開ける。**一覧は保存済みの `threadId` を辿る。

### 3.2 `kind` がまだ効いている箇所

| `consultations` API | `FORMAL` かつ `linkedTopic` があるときだけ論点を結びつける |

## 5. シナリオ一覧（27件）

**内訳：`ADJUSTMENT`（個別の相談）19 ／ `NOTIFICATION`（お知らせ）8**

> ★`FORMAL`（取り決めを決める相談）を、この一覧には置かない方針である。
> 対話から取り決めを作らないと決めた以上、**題が「決める」なのに決まらない。**
> 相談の入口には「取り決めを決める・変える」の1行を置き、取り決め画面へ送る。

### ★ 「決める」の2件を、「相談する」に直した（2026-08-14）

```
sc_001  養育費を決める        → 養育費のことを相談する      FORMAL → ADJUSTMENT
sc_006  面会のルールを決める   → 面会のルールを相談する      FORMAL → ADJUSTMENT
```

★ **本番マスタは 29 件（ADJUSTMENT 21 / NOTIFICATION 8）。`FORMAL` は 0 になった。**

**題が、果たせない約束になっていた。**対話から取り決めへ行く経路は断ってある（T1）ので、
話しても決まらない。`opening` はさらに踏み込んで、**最初の一行でこう言っていた。**

> 金額・お支払いの日・いつまで続けるか、この3つが決まると**書面にできます。**

`promptHint` の「金額は算定表を参照して**範囲を示してください**」も外した。
**数字を LLM に作らせない**（P3）に反していた。

★ **消さなかった。行き先として要るからである。**
取り決めの画面の「このことを相談する」は `?topic=CHILD_SUPPORT` へ送り、
`linkedTopic` が一致するシナリオを出す。消すと、
**養育費そのものを相談する先が無くなる**（残るのは塾・進学・医療など個別の件だけ）。

★ **`kind` も一緒に変えた。題だけでは片手落ちになる。**
`FORMAL` のままだと `isAdjustment` が false で、**相談しても控えが残らない。**
いちばん残ってほしい題で、何も残らないことになる。

| ADJUSTMENT にして揃ったこと | |
| --- | --- |
| 控えが残る | ✅ |
| 「このご相談では、いまの取り決めは変わりません」が画面に出る | ✅ ★題が「相談する」なら、この注記こそ要る |
| 合意済みでも「済んだ」に沈まない | ✅ 別件として何度でも相談できる |

### ★ 一覧から「外した」つもりが、外れていなかった

`NewConsult.tsx` には「ここから外した」と書いてあったが、
**手書きの行を消しただけ**で、一覧は**マスタから引いている。**
`/api/scenarios` は `kind` で絞らないため、**並んだままだった。**

> ★ **コードのコメントが、実装の証明にはならない。**
> 「外した」と書いた場所と、実際に一覧を作る場所が違っていた。

## 6. ★ 作り直しで直したこと

この一覧を機械的に書き出したことで、**設計と実装のずれが3つ**見えた。いずれも直した。

### 6.1 「決める」と題したシナリオが、決められなかった

`sc_001 養育費を決める` / `sc_006 面会のルールを決める` は `FORMAL` だった。
**対話から取り決めを作る経路を断った**ので、選んでも決まらなかった。

> 題が「決める」なのに、決まらない。**果たせない約束だった。**

**→ 外した。ただし外すだけにしない。**

| | |
| --- | --- |
| 相談の入口 | 「**取り決めを決める・変える**」の1行を置いた |
| 個別の相談を開いたとき | `NOT_NEGOTIABLE_NOTE` を表示し、同じ場所に「取り決めの画面へ」 |

★ 文言は**書かれていたのに、一度も表示されていなかった。**
★ 行き先を同じ場所に置かないと、**入口が消えるだけで行き止まりになる。**

### 6.2 `NOTIFICATION`（お知らせ）が、控えを残していた

設計では「お知らせは取次ぎのみ」だが、実装は種別を問わず控えを作っていた。

実測：運動会の写真を共有すると `{"subject":"入学金"}` が控えとして残った。

**→ `isAdjustment()` で分岐を戻した。**合意を求めない連絡に、控えは要らない。

### 6.3 `linkedTopic`（対応する論点）の持たせ方

新しく足したシナリオは、**`linkedTopic` を持たない。**

`canNegotiateAgreement` の注記にあるとおり、これが
**「進学費用の相談が養育費の枠で決められる」**の発生源だった。
いまは経路そのものが無いが、**分類の材料としても持たせない。**

## 7. スコープ外にしたもの

### 緊急・安全確認

実データには、**警察に捜索願を出す直前**まで発展した家出がある。
だが**このアプリでは扱わない。**

アプリは「お急ぎいただくご連絡はしません。期限もありません」と明記している。
**平時の設計としては正しい。**緊急を扱うには、この前提を崩すことになる。
そして**中途半端に扱うと、届かなかったときの責任が重い。**

**シナリオを作らない。**行き先は、既にある常設の窓口にある。

| | |
| --- | --- |
| 児童相談所虐待対応ダイヤル `189` | 子どもの安全に関わるとき |
| 子ども医療電話相談 `#8000` | 急な体調のとき（★受付時間は都道府県ごとに違う） |

★ 窓口は**相談画面（＝書く場所）に常設**され、**検知に一切反応しない。**
緊急のときにも、**同じ場所に、同じように在る。**

★ 緊急の入口が増えないことは、テストで固定してある
（`tests/invariants/scenarioRedesign.test.ts`）。
