# Handoff: Aida（あいだ）— スマートフォンアプリ UI

## Overview

Aida は、離婚・共同養育の当事者が使うスマートフォンアプリです。父母のあいだに AI が立ち、**二人を直接やりとりさせずに合意をつくり、それを守り続ける**ことを目的としています。

決定的な特徴は、**メッセージを転送しないこと**です。父は AI と話し、母も AI と話す。AI が両者のあいだで着地点を探り、合意した内容だけが共有されます。相手が書いた言葉そのものは、一度も相手に届きません。

このハンドオフに含まれるのは、以下の設計です。

- 起動画面／ホーム／相談（対話）／相談の開始（トピック選択）／今回だけ・今後もの確認／取り決め一覧／公正証書の原案／これから（予定・記録）／逸脱の詳細／設定
- AI キャラクター（カピバラ）とその使い分け
- 役割つき配色パレット、タイポグラフィ、余白、角丸、モーション
- 合意ステータス 6 種の、色に依存しない表現パターン

## About the Design Files

このバンドルに含まれる HTML ファイルは、**HTML で作られたデザインリファレンス**です。意図した見た目と振る舞いを示すプロトタイプであり、そのまま本番コードとして流用するものではありません。

実装のタスクは、これらの HTML デザインを**対象コードベースの既存環境（React / Vue / SwiftUI / ネイティブ等）で、その環境の確立されたパターンとライブラリを使って再現すること**です。まだ環境が存在しない場合は、プロジェクトに最も適したフレームワークを選定したうえで実装してください。

想定している実装環境は Next.js（App Router）＋ TypeScript ＋ Tailwind CSS です。成果物は Tailwind のクラスで再現できる範囲に収めており、凝った独自コンポーネントは避けています。将来的な iOS / Android ネイティブ化も想定しているため、各 OS の標準的な作法から大きく外れないようにしてください。

## Fidelity

**High-fidelity（hifi）** です。色・タイポグラフィ・余白・角丸はすべて確定値で、そのまま実装してください。ただし以下は例外です。

- 「これから」「逸脱の詳細」「設定」「公正証書の原案」の 4 画面は **ラフ**（300×600 で作成）です。構造と文言は確定していますが、余白の詰めは実装時に他画面のスケールへ合わせてください。
- カピバラのイラストは提供素材（PNG）です。実装時はベクター化または高解像度版への差し替えを推奨します。

## ★ 最重要の前提：ユーザーの心理状態

**これを外すと実装全体が失敗します。**

このアプリを開く人は、人生でもっとも消耗している時期にいます。相手への強い怒り、あるいは恐怖を抱えており、相手の名前が画面に出るだけで動揺します。国の調査では、養育費や面会交流の取り決めをしない理由の第 1 位が「相手と関わりたくない」でした。

> **「相手の存在を感じさせないこと」が、このプロダクトの機能そのものです。**

DV・つきまといの文脈が現実にあります。ロック画面に「元夫から連絡が来ています」と出るような実装は危険です。

### 実装時に守ること

| | |
| --- | --- |
| ✅ 目指すもの | 静けさ・安全・守られている感じ |
| ❌ 避けるもの | 明るさ・元気・励まし・対立の可視化・急かし |

**絶対に実装してはいけないもの**（仕様で明示的に禁止）：

- 未読バッジ、赤い通知ドット、「入力中…」、既読表示
- LINE 風の左右振り分け吹き出し
- 相手のアイコン・実名・顔写真
- 紙吹雪・バッジ・レベル・連続日数などのゲーミフィケーション
- ダークパターン（同意を促す強調ボタン等）。**法的合意を扱うため厳禁**
- 赤／青の対立的な色分け

## 文言規約

**画面に出る言葉は、デザインの一部です。実装時に言い換えないでください。**

### 使ってはいけない語

| 使わない | 代わりに使う | 理由 |
| --- | --- | --- |
| 違反 | **逸脱** | 責める語彙を避ける |
| 未払い・滞納 | **入金が確認できていません** | 断定を避ける（反映遅れがありうる） |
| 元夫 / 元妻 | **お相手** | 関係性を想起させない |
| 相手のメッセージ | **お相手からのご相談** | 相手の言葉ではないため |
| チャット | **対話** / **相談** | 相手と直接話す印象を避ける |
| テンプレート / 定型文 | **選択肢** | 定型文は採用していない |
| ユーザー登録 | **招待** | 双方の参加が前提 |

### 表現の規約

| 項目 | 規約 |
| --- | --- |
| 法的な事柄 | 断定しない。「〜とされています」「〜の可能性があります」 |
| 相手の申告 | 伝聞形式。「〜とのことです」 |
| 逸脱の表現 | 責めない。事実として静かに示す |
| エラー | 技術的な内容を出さない。**「うまくいきませんでした。もう一度お試しください」** |

## AI キャラクター（カピバラ）

### 採用理由

争わない。他の動物に背中を貸す。そして**表情筋が動かない**。「無表情である」ことに説明が要らないのが、この題材を選ぶ最大の利点です。

### 素材

| ファイル | ポーズ | 使用箇所 |
| --- | --- | --- |
| `assets/capybara.png` | 伏せ（横向き） | 対話の AI 発言マーク、ホームの入力の入口、起動画面、アプリアイコン |
| `assets/capybara-sit.png` | 座り | 相談の開始（トピック選択）、ホームのヘッダー |

500×501px / 500×499px、PNG、背景は不透明のクリーム。円形にクリップして使っています（`border-radius: 50%` + `object-fit: cover`）。

### 実装ルール

1. **表情差分もポーズ差分も作りません。** ユーザーの感情に反応して表情が変わると「見抜かれた」という監視感が生まれ、相手の相談を取り次ぐ場面で中立に見えなくなります。
2. **ポーズは上記 2 種のみ。** 伏せ＝通常の対話、座り＝相談の開始と空の状態。
3. **動きは 3.2 秒周期の呼吸だけ。** リアクションは実装しないでください。
4. 温泉・ゆず・「まったり」といった、カピバラに付随しがちな記号は使いません。癒やしキャラとして消費されると、当事者の切実さと釣り合わなくなります。

### マークのサイズ

| 文脈 | サイズ |
| --- | --- |
| 対話の AI 発言 | 28px（円形、`margin-top: 3px`） |
| ホームのヘッダー | 44px（円形） |
| 相談の開始 | 38px（円形） |
| 起動画面 | 96px（角丸 26px のタイル内） |

### 3. ★ 相談（対話）— 最重要画面

**Purpose**: AI と 1 対 1 で話す。このアプリの中心。

**必ず「AI と 1 対 1 で話している」画面に見えること。相手とチャットしている印象を与えたら失敗です。**

**Layout**: ステータスバー 44px → シナリオ見出し → 会話領域（`flex: 1`、`padding: 20px 20px 8px`、`gap: 14px`）→ 選択肢 → 入力欄 → タブバー。

**シナリオ見出し**: 「今回の日程を変更したい ⌄」14.5px `text-sub-2`、右端に 44×44 の `⋯`。下辺に `border-subtle`。

#### 登場する要素は 3 種類だけ。この描き分けが最も重要な実装課題です。

| # | 種類 | 求められる印象 |
| --- | --- | --- |
| ① | 自分の発言 | ここには何を書いてもいい。誰にも届かない |
| ② | AI 自身の発言 | 落ち着いた第三者 |
| ③ | AI が相手の相談を取り次いだもの | **相手の言葉ではなく、AI の言葉**であることが伝わる |

**① 自分の発言**

```
align-self: flex-end / max-width: 78% / background: bubble-self (#F2E8D9)
border-radius: 20px / padding: 13px 15px / font-size: 15.5px / line-height: 1.9
枠線なし・尻尾なし・時刻表示なし・既読表示なし
```

直下に 11px `text-sub` で「ここに書いたことは、お相手には届きません」。
**この一行はプロダクトの約束を担っています。削らず、コントラストを落とさないでください。**

**② AI 自身の発言**

```
横 flex / gap: 9px / カピバラ（伏せ）28px 円形、margin-top: 3px
吹き出し: max-width: 82% / background: bubble-ai (#FBF0DA)
border-radius: 20px / padding: 13px 15px / font-size: 15.5px / line-height: 1.95
```

マークは会話の連続する塊の先頭にだけ出し、繰り返しません。

**③ AI による取次ぎ ← 最重要**

**吹き出しではありません。画面幅いっぱいの封書カード**として、会話の流れから物理的に切り離します。

```
flex: none / width: 100% / background: surface / border: 1px solid border
border-radius: 20px / overflow: hidden

├ ヘッダ帯: background: envelope-head / border-bottom: 1px DASHED border-dashed
│           padding: 11px 14px / 封筒アイコン + 「お相手からのご相談」11.5px agree-text
│           右端に「AIが要約しました」10.5px text-sub
├ 本文: padding: 16px 14px 14px / 15.5px / line-height: 1.95
│      伝聞の補足は 13.5px text-sub（「〜とのことです」）
└ フッタ: border-top: 1px solid border-subtle / padding: 9px 14px 12px
         「お相手が書いた言葉そのものは含まれていません。」11px text-sub
```

**① と ③ が別種に見える理由（実装時のチェックリスト）:**

| | ① | ③ |
| --- | --- | --- |
| 寄せ | 右 | 幅いっぱい |
| 形 | 吹き出し | 見出し付きカード |
| 幅 | 78% | 100% |
| 面 | 塗りのみ | 枠線＋破線の仕切り |
| 署名 | なし | 「AIが要約しました」 |

5 つの属性が同時に反転するため、文字を読む前に別種と分かります。**このうち 1 つでも崩すと課題が解けなくなります。**

**選択肢領域**（入力欄の上）

```
横 flex / flex-wrap / gap: 8px / padding: 0 20px 10px
チップ: border: 1px solid #E4DACA / border-radius: 999px / padding: 10px 15px
        font-size: 13.5px / color: agree-text / background: surface
```

これは**定型文ではありません**。選んだものは相手に送られるのではなく、**AI への入力**になります。文言は AI が文脈に応じて生成します。

**入力欄**

```
padding: 8px 16px 12px / border-top: 1px solid border-subtle
入力欄: flex: 1 / min-height: 44px / surface / border 1px / 角丸 16px
        padding: 12px 14px / 15px / プレースホルダ「思っていることを書く」text-sub
送信: 44×44 / 角丸 20px / background: ai (#C08F3C) / 中に白い紙飛行機 17px
```

**入力欄は常に開いています。** トピックを選ばなくても書き始められることが必須要件です。

### 4. 相談の開始（トピック選択）

**Purpose**: 相談をシナリオから始める。ただし**選択を必須にしてはいけません。**

**Layout**: ヘッダー（カピバラ座り 38px ＋「何について、お話ししますか」18px、`margin-bottom: 28px`）→ 4 つの分類 → 区切り → 自由入力への導線 → 入力欄 → タブバー。

**分類カード**: `surface`、`border` 1px、角丸 20px、`padding: 17px 18px`、16px、`gap: 10px`

- お金のこと
- 子どもと会うこと
- 子どもの進路・生活
- 日常の連絡

**自由入力への導線**（`margin-top: 22px`、`padding-top: 20px`、上辺に `border-subtle`）

- 「選ばずに、そのまま書く ▸」15px `agree-text`
- 「選ばなくてかまいません。書きはじめてから、あとで整理します。」12px `text-sub`

> **⚠️ トピック選択を強制してはいけません。**
> 「まず愚痴りたい」人に選択を強いると、このアプリの核心である感情の受け止めが選択画面の後ろに隠れます。入力欄は常に開いておき、自由入力から始まった場合は AI が後からシナリオへ紐付けます。

分類をタップすると配下のシナリオ一覧（各 5〜8 個）が出ます。**各分類の末尾に必ず「その他（自由に書く）」を置きます。**

参考シナリオ：

| 分類 | シナリオ |
| --- | --- |
| お金のこと | 養育費を決める／塾・習い事の費用／進学費用の分担／今月の支払いを待ってほしい |
| 子どもと会うこと | 面会のルールを決める／今回の日程を変更したい／学校行事に参加したい／長期休暇の過ごし方 |
| 子どもの進路・生活 | 進学について／医療について／転居・転校について |
| 日常の連絡 | 送迎をお願いしたい／子どもの体調を伝える／写真・成長を共有する |

### 5. ★「今回だけ？ 今後も？」の確認

**Purpose**: 日程変更などの申し出があったとき、AI が**合意（取り決め）を参照して**選択肢を出す。このアプリで最も特徴的なインタラクションです。

**Layout**: 背後の会話は `opacity: .35` で沈め、下からボトムシート（`surface`、上辺 `border` 1px、角丸 `26px 26px 0 0`、`padding: 24px 20px 28px`、`gap: 18px`）。上部に 36×4 のハンドル。

**AI の問いかけ**: カピバラ 28px ＋「取り決めでは「月1回・第2土曜」となっています。」15.5px ／ 続けて `text-sub` で「今回だけの変更でしょうか。それとも、今後もでしょうか。」

**2 つの選択肢**

| | 今回だけ | 今後も |
| --- | --- | --- |
| 意味 | その回だけの例外 | **法的な取り決めそのものを変える** |
| 重さ | 軽い | **重い** |

```
[今回だけ変更する]
background: surface-2 / border: 1px solid border / 角丸 20px / padding: 16px 18px
タイトル 16px / 補足 12.5px text-sub「9月13日の1回だけ。取り決めは変わりません。」

[今後も変更する]
background: agree-bg / border: 1.5px solid agree / 角丸 20px / padding: 18px
box-shadow: 0 0 0 4px rgba(91,138,99,0.14)
文書アイコン 13px + タイトル 16px agree-text
補足 12.5px text-sub「取り決めそのものを書き換えます。お相手の同意が必要です。
                    確定の前に、変更後の条文をもう一度お見せします。」
区切り線の下に 11.5px text-sub「変更前：月1回・第2土曜 ／ 変更後：月1回・第3土曜」
```

重さの差は、**面積・枠線の太さ・合意色の有無・情報量**の 4 点で表現しています。
**どちらも強調ボタンにはしません。** 法的合意を扱うため、片方を押させるデザインは厳禁です。

最下部に「あとで決めることもできます」12px `text-sub` を中央寄せ。**逃げ道を必ず残してください。**

「今後も」は取り決めの改訂にあたるため、確定前にもう一段の確認（変更後の条文プレビュー）を挟みます。ただし脅かさないこと。

### 6. 取り決め（合意一覧）

**Purpose**: 離婚時に決めるべき 8 項目の一覧と状態。

**Layout**: ヘッダー（`padding: 4px 20px 14px`）→ 項目リスト（`flex: 1`、`gap: 10px`）→ 公正証書への導線 → タブバー。

**ヘッダー**: 「取り決めの状況」24px / 500 ／ 「8つのうち、2つが決まりました」13px `text-sub` ／ 8 分割の進捗バー（高さ 3px、`gap: 3px`）

**項目カード**: `surface`、`border` 1px、角丸 20px、`padding: 16px`

- 項目名 16px ／ 右端にステータスチップ ／ 下に内容 13px `text-sub`

**「今後対応する項目」**: 見出し 11.5px `text-sub` ／ `surface-2` の地に 5 行（各 `padding: 10px 0`、14.5px `text-sub`、行間に `border-subtle`）

**公正証書への導線**: 合意が揃うまでは無効状態（`surface-2` の地、`#D4C6B1` の枠、`text-sub` の文字）。「公正証書の原案を見る／すべての項目が決まると開けます」

項目をタップすると詳細（合意内容・合意日時・**変更履歴**）へ遷移します。

#### ★ 合意ステータス 6 種 — 色だけに頼らない表現

**色覚特性への配慮も兼ねて、線種・地の明度・記号の形・文字列の 4 点で判別できるようにしています。グレースケールに変換しても区別できることを必ず確認してください。**

| 状態 | 枠線 | 地 | 記号 | 文字色 | 意味 |
| --- | --- | --- | --- | --- | --- |
| 未着手 | **破線** `#C4B8A7` | なし | 破線の円 | `text-sub` | まだ話し合っていない |
| 係争中 | 実線 `#DCC0AB` | `attention-bg` | **三角**（唯一の傾いた形） | `attention-text` | 意見が分かれている |
| 合意済 | 実線 `agree` | `agree-bg` | チェック | `agree-text` | 決まった |
| 変更申請中 | 実線 `#C6D3C1` | `#F1F5EE` | 回転矢印 | `agree-text` | 事情が変わって再交渉中 |
| 逸脱 | 実線 `#DCC0AB` | `surface` | 予定線から外れた実線 | `attention-text` | 約束が守られていない |
| 調停へ | 実線 `muted` | `muted-bg` | 天秤 | `text-sub-2` | AI では解決できず、専門家・裁判所へ |

チップの共通スタイル：`display: inline-flex`、`gap: 6px`、角丸 11px、`padding: 4px 9px`、ラベル 11.5px、アイコン 11px。

**とくに「逸脱」を責める表現にしないでください。** 強い赤は避け、感嘆符も使わず、一覧の中で他と同じ大きさに置きます。事実として静かに示すだけです。
「合意済」だけが実線の枠と合意色を持ちます。**最も彩度が高い状態はここだけ**で、これがこのアプリで唯一のポジティブな進捗表現です。ただし祝いません。

### 7. 公正証書の原案（ラフ）

**Purpose**: 合意した内容を、公証役場に持っていける文書の形で表示する。

- **注意書きを常時表示**（法的に必須）：`attention-bg` の地、`#DCC0AB` の枠、角丸 12px、11.5px `#7A5A44`
  「これは原案です。公正証書は公証人が作成します。」
  目立つが威圧的でない置き方にしてください。スクロールしても消えないこと。
- タイトル「離婚給付等契約公正証書」16px、**Shippori Mincho**、`letter-spacing: .1em`、中央寄せ
- **条項ごとに畳めます。** 折りたたみヘッダ 13.5px（明朝）＋ `⌄` / `⌃`、本文 12px 行間 2.1（明朝）
- 未確定の条項は **破線の枠**で「第4条（　　　）未確定」と空欄のまま残します

スマートフォンで長い法的文書を読ませる難所です。条項の折りたたみは必須です。

### 8. これから（予定・記録／ラフ）

**Purpose**: これからの予定と、過去の記録。

**予定カード**: 日付 11.5px `text-sub` ／ 内容 14.5px

**一時的例外の表示**（必須）: 破線の区切りの下に 11.5px `attention-text` で
「今回だけ第3土曜に変更（本来は第2土曜）」
**「本来は第2土曜だが、今回だけ第3土曜」という状態が、それとわかる表示が要ります。**

**記録リスト**: 日付 ／ 種別 ／ 状態。逸脱は `attention-text` で「入金が確認できていません」、続けて「詳しく見る ▸」`agree-text`。
**「未払い」「滞納」とは書きません。** 反映遅れがありうるため断定を避けます。

### 9. 逸脱の詳細と法的状態（ラフ）

**Purpose**: 入金が確認できない場合に、その状態を客観的に説明する。

- 見出し「7月分の養育費について」17px
- 定義リスト：期日 ／ 金額 ／ 状態（`attention-text`）
- **法律上の状態カード**（`surface`、`border` 1px、角丸 16px）
  見出し 12px `agree-text`「法律上の状態」
  本文 13px 行間 2.05「合意された金額は、先取特権の範囲内（子1人あたり月8万円）とされています。」
- 「制度の説明です。何かをするようお勧めするものではありません。」11.5px `text-sub`
- 最下部に「このことについて相談する」

**制度の説明であり、行動を促すものではありません。「差押えをしましょう」とは言いません。** 静かで、事務的で、しかし冷たくないトーンを保ってください。

**Purpose**: 表示名・通知・表示の設定。

## Interactions & Behavior

### ナビゲーション

- タブ切替：フェード 240ms。**横スライドは使いません。**
- 画面遷移も同様にフェード。戻る操作は OS 標準に従う。

### 対話

1. ユーザーが入力欄に文字を入れて送信 → ① の吹き出しが fade + 4px 上昇（320ms）で追加
2. AI の応答待ち：カピバラのマークが 3.2 秒周期で呼吸。**「入力中…」やドットの明滅は使いません。**
3. ② の吹き出しが同じアニメーションで追加
4. AI が選択肢を提示する場合、入力欄の上のチップ列が更新される
5. 相手から相談が届いた場合、③ の封書カードが会話の流れに挿入される

**リアルタイム性を持たない設計です。** 相手を待たせている感覚を与えないこと。ポーリングやプッシュでの即時反映は不要です。

### 確定操作

感情が高ぶった状態で使われます。**誤タップで取り返しがつかないことが起きないよう、確定操作は一段深くしてください。**

- 「今後も変更する」→ 変更後の条文プレビュー → 確定
- 取り決めの改訂は、相手の同意が揃うまで `変更申請中` として保持

### エラー

技術的な内容を出しません。文言は「うまくいきませんでした。もう一度お試しください」に統一します。

### 通知

- 既定では本文を出さない。ロック画面には「お知らせがあります」のみ
- **「元夫から連絡が来ています」のような文面は絶対に生成しないでください**
- 通知の時間帯を尊重する（既定 9:00–21:00）

## State Management

### 主要な状態

| 状態 | 内容 |
| --- | --- |
| `agreements` | 8 項目。各項目に `status`（6 種）、`content`、`agreedAt`、`history[]` |
| `conversations` | シナリオ単位。`messages[]` は `{ kind: 'self' \| 'ai' \| 'relay', body, meta }` |
| `pendingRelay` | 相手から届き、まだ開かれていない相談。**件数は持つが、バッジには出さない** |
| `schedule` | 定期の予定と、`exception`（今回だけの変更）を持つ回 |
| `records` | 支払い・面会の記録。`deviation` フラグ |
| `settings` | `partnerDisplayName`、`notifyWithBody`（既定 false）、`notifyWindow` |

### 状態遷移

```
未着手 → 係争中 → 合意済
              ↘ 調停へ
合意済 → 変更申請中 → 合意済（改訂）
合意済 → 逸脱（期日超過かつ入金未確認）→ 合意済（入金確認後）
```

- `逸脱` は自動判定ですが、**責める通知を送りません。** 記録に静かに追加するだけです
- `変更申請中` は相手の同意待ち。同意が揃った時点で `合意済` に戻り、`history` に追記されます

### データ取得

- リアルタイム同期は不要。画面表示時とプルダウンで取得すれば十分です
- **既読状態は保持しません。** 相手に既読を伝える経路を作らないでください
